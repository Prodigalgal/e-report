# 全系统安全审计初步报告

审计基线：`2.5.3`，Git `6561a0fbfdd1`，生产命名空间 `e-report`。本次仅执行源码、配置、依赖链和生产运行态的只读检查，没有修改生产代码、配置或数据，也没有执行口令猜测、越权写入、漏洞利用或工单/通知写入。

## 结论

当前租户隔离、组织数据范围、资源关系和委派上限能够有效阻止普通用户或区县管理员直接取得超出自身的权限，superAdmin 的系统级能力也与租户管理员分开。但系统尚未达到“单个弱密码失陷后不能横向扩散”的目标：同级管理员接管、高危动作单因子执行、敏感配置读取、API Token 驻留和运行平台扁平化仍可形成完整攻击链。

建议将专案拆为身份保证、特权操作、应用秘密、运行隔离和制品可信五条并行防线。不能只继续增加 RBAC 权限码；RBAC 约束“能做什么”，MFA/step-up、职责分离和运行隔离负责约束“凭什么做、一次失陷能影响多远”。

## 关键攻击路径

### 普通账号密码失陷

1. 登录成功后可直接创建最长十年或长期有效的 API Token，无需 API Token 管理权限。
2. 用户修改密码和管理员重置密码只撤销登录会话，不撤销 API Token；攻击者可保持原权限驻留。
3. Token 权限会与账号当前有效权限动态求交，账号停用或权限回收后失效，这是现有的重要限制。
4. 普通账号不能跨租户、跨组织或取得未拥有的原子权限，但可反复创建大文件上传会话，占用临时存储和 I/O。

### 区县管理员密码失陷

1. 默认岗位同时包含用户创建、状态管理、密码重置、授权管理、导入导出、系统配置、通知配置和运行诊断。
2. 攻击者可在本区县创建新账号并授予与自己相同的权限，或重置、锁定权限面可完整覆盖的同级管理员账号。
3. 系统配置查询返回敏感配置原值，可取得邮件密码、Webhook 和 API Key 等秘密。
4. Webhook 与 SMTP 目标缺少出站目标校验，可用于区县数据外发或盲 SSRF。
5. 组织范围和委派上限会阻止其扩散到其他区县、市公司或系统级安装包能力。

### 市公司管理员密码失陷

攻击路径与区县管理员相同，但数据面扩大到全租户，可创建全市管理员、接管同级账号、导出全市用户和工单数据并修改租户级配置。系统级安装包和平台租户能力仍受 system-scoped 权限与 superAdmin 边界保护。

### superAdmin 密码失陷

当前没有 MFA、passkey、双人复核或高危操作 step-up。superAdmin 密码本身即可取得平台和租户最高能力，属于单点完全失陷。普通租户管理员不能重置、停用或删除该系统身份，这是现有防线，但不能防止其自身密码被盗。

### 应用工作负载失陷

生产 Backend 以容器内 root 运行、自动挂载 ServiceAccount Token、挂载宿主机目录，并同时持有 MySQL root、Redis、认证密钥、默认管理员、superAdmin、R2 和外部集成 Secret。集群没有 NetworkPolicy；测试同步任务还持有生产 MySQL root 凭据。任一 Backend RCE 或测试同步容器失陷都可能从单应用问题扩大为数据库、缓存、对象存储或跨命名空间事件。

## 发现与分级

### P0 / 严重

1. **特权操作仍是单因子认证。** 用户密码重置、账号启停/删除、授权计划应用、岗位模板发布、批量导入导出、通知目标和发件方修改均不要求近期重新认证、MFA 或审批。弱密码一旦成功登录，所有授权内高危动作立即可用。
2. **同级管理员可横向接管。** 目标保护采用“当前管理员是否完整覆盖目标授权”判断；完整覆盖意味着可修改，因此同级区县管理员或市公司管理员之间可以重置密码、锁定账号并改授权。应改为严格高于目标，或对凭据/授权操作引入独立安全管理员与双人复核。
3. **敏感配置通过 API 返回原值。** 审计基线中 `ScopedAppConfigDTO` 同时包含 `configValue` 和遮掩后的 `displayValue`，Controller 对敏感项仍填入真实值。`2.5.5` 候选已改为服务端 write-only：响应原值恒为 `null`、移除敏感值搜索和客户端显示入口。
4. **生产运维入口允许 root 密码登录。** `sshd -T` 显示 `PermitRootLogin yes`、`PasswordAuthentication yes`；主机 `INPUT` 默认 ACCEPT，UFW 未启用。运维口令失陷即为宿主机和集群完全失陷。
5. **生产仍提供明文 HTTP 入口。** `http://36.212.129.231:60080/` 与 `/api/auth/csrf` 返回 200，且该 Origin 被加入 CORS。Secure Cookie 可能导致明文入口登录后会话不可用，但用户名和密码仍会先经明文网络传输。

### P1 / 高

1. **API Token 默认开放且不随密码事件撤销。** 审计基线中 `/api-tokens/**` 只要求登录；Token 可长期有效，密码修改/重置只撤销 Session。`2.5.4` 候选已完成查看、创建、撤销三项显式权限门槛；`2.5.5` 候选进一步在密码修改和管理员重置时撤销全部未撤销 Token 与既有设备信任。
2. **默认管理员职责过度集中。** 同一个默认岗位同时具有账号生命周期、密码重置和授权分发三类互相制约的能力，凭据失陷后可自行创建持久化管理员。应拆为业务管理员、账号管理员和授权安全管理员，默认岗位不同时包含“创建/重置/授权”。
3. **工作负载与数据层缺少最小权限。** Backend 使用 MySQL root；MySQL `require_secure_transport=OFF`，Redis `protected-mode=no`、TLS 关闭；生产与测试命名空间没有 NetworkPolicy。应建立应用专用数据库账号、迁移专用账号、备份只读账号、Redis ACL、TLS 和默认拒绝网络策略。
4. **容器边界过宽。** Backend 没有 `runAsNonRoot`、只读根文件系统、能力删除、seccomp 和 `allowPrivilegeEscalation=false`，并挂载 hostPath；不需要 Kubernetes API 的 Pod 仍自动挂载 ServiceAccount Token。
5. **生产 Secret 集中注入单个 Backend。** 一次进程内信息泄露可同时取得数据库、缓存、认证、管理员和 R2 凭据。默认管理员配置口令在首次创建后仍长期注入运行容器，也扩大了不必要暴露面。
6. **测试同步拥有生产 root 凭据。** `e-report-test-data-sync` 通过 Secret 注入生产 MySQL root 密码并可直接访问生产数据库；测试命名空间或同步镜像失陷会越过环境边界。
7. **通知出口可成为数据外发和 SSRF 通道。** 企业微信/钉钉直接对配置 URI 发起 POST，SMTP 主机也可任意设置；没有 HTTPS 强制、官方域名/租户域名白名单、DNS 重绑定与私网地址阻断。
8. **Android 设备信任不是第二因素。** 新设备在密码验证成功后自动登记为 TRUSTED；root、模拟器、Hook、签名不匹配和 `PLAY_INTEGRITY_UNAVAILABLE` 仅记录信号，不影响登录或高危操作。请求签名能防篡改和重放，但不能阻止持有密码的攻击者登记自己的设备密钥。

### P2 / 中

1. **公共观测入口可被污染。** 匿名 `/observability/events/batch` 会把事件写入默认租户，虽有 512 KiB、批次数和 IP 限流，但没有客户端证明；攻击者可制造错误噪声和存储压力。`getRemoteAddr` 还会使运营商 NAT 用户共享限额。
2. **上传缺少用户级容量预算。** 普通已登录用户可建立多个 100 MiB 工单附件上传会话，只有单文件/单会话大小与六小时过期，没有并发数、日累计量和磁盘水位门禁。
3. **用户导入初始密码明文文件保留七天。** 导入文件仅所有者可访问且行预览不保存原密码，但原始 XLSX 在文件存储中按任务保留期保存。应执行完成后立即销毁密码列或采用一次性初始凭据流程。
4. **Kubernetes Secret 未配置静态加密。** kube-apiserver 未发现 `encryption-provider-config`；Secret 仅依赖 etcd/磁盘和节点权限保护。
5. **本地容器制品缺少签名准入。** 依赖锁定、SBOM、SCA、Gitleaks 和镜像扫描已建立，但生产使用 `localhost/*` 与 `imagePullPolicy: Never`，没有 cosign/SLSA provenance 或准入验证，本地同名 tag 可被宿主机管理员替换。
6. **备份为宿主机明文 SQL。** 备份使用 `umask 077` 且仅保留十四天，但未看到应用层加密、离机不可变副本和恢复演练证明。

## 已验证的有效控制

- 用户名全局唯一，认证响应不区分账号不存在与密码错误；登录具有 PoW、交互验证码、账号/设备风险计数和指数延迟。
- 密码最少十五字符，常见口令、长连续序列和用户上下文均被拒绝；新密码使用 Argon2id，历史 BCrypt 登录后升级。
- WEB 使用 Secure、HttpOnly、SameSite Cookie，存在 CSRF 与 Origin/Referer 校验；Android 使用硬件密钥请求签名、短时窗口和 Redis Nonce 防重放。
- Refresh Token 轮换并检测旧 Token 重用；权限版本变化、密码修改和管理员重置会撤销会话。
- API Token 仅存受保护哈希、明文只展示一次、不能管理会话或其他 Token、不能携带 system-scoped 权限，并与账号当前权限动态求交。
- 工单和用户查询采用租户、组织、资源关系和授权有效期共同判定；授权分发不得超过授予者的权限、范围、关系和期限。
- 文件上传校验所有者、租户、用途、大小、分片范围、文件名与 SHA-256；用户导入导出有幂等、预览令牌、并发槽位和所有者隔离。
- 供应链门禁通过：release runtime OSV 发现为 0；Git 历史和工作树 Gitleaks 未发现密钥；七类镜像扫描和 SBOM 生成通过。APP 的已知构建期告警有显式基线和控制条件。
- 生产 Swagger/API Docs 默认关闭，Actuator/Swagger/H2 公网探针均未匿名开放；HTTPS 响应已配置 CSP、HSTS、DENY frame、nosniff 和 no-referrer。

## 整改顺序

### 第一批：立即阻断横向扩散

1. API Token 管理权限化；密码泄露处置统一撤销 Session、API Token 和受信设备。
2. 敏感配置改为服务端 write-only；移除 DTO 原始值，单独建立受 step-up 保护的秘密轮换动作。
3. 管理员 MFA/passkey 与高危动作 step-up；密码重置、授权、批量导入、配置秘密和通知目标至少要求五分钟内二次认证。
4. 禁止同级管理员凭据与授权互改；建立 Security Administrator 或双人审批。
5. 下架 60080 明文业务路由；SSH 改为密钥/证书、非 root、来源白名单和跳板审计。

### 第二批：收缩运行爆炸半径

1. Backend、Liquibase、备份分别使用最小权限数据库账号；启用数据库和 Redis TLS/ACL。
2. 为生产、测试和平台命名空间部署默认拒绝 NetworkPolicy，只开放明确调用边。
3. 容器以非 root、只读根文件系统、drop ALL capabilities、seccomp RuntimeDefault 运行；关闭无用 ServiceAccount Token 自动挂载。
4. 测试同步改为生产只读快照导出服务或离线脱敏制品，禁止测试命名空间持有生产 root Secret。
5. 将管理员/bootstrap/R2 等 Secret 按用途拆分，改为短期凭据和可审计轮换；配置 ENV 仅负责首次引导后应退出运行容器。

### 第三批：可信客户端与持续治理

1. Android 引入 Play Integrity/硬件证明并按风险分级；高危操作拒绝签名不匹配、root、Hook 和不可信安装来源。
2. WebAuthn/passkey 优先，TOTP 作为兼容方案；建立新设备、异常网络和高风险操作通知。
3. 出站网络采用域名与协议策略、私网/链路本地地址阻断、DNS 重解析校验和 egress NetworkPolicy。
4. 匿名观测使用限时安装证明或一次性上报票据；上传增加用户/组织容量预算和磁盘熔断。
5. 容器和 APK 建立 provenance、签名、SBOM 绑定与部署准入，定期执行恢复演练和凭据失陷演练。

## 本轮实现决定

API Token 管理拆为三个原子权限：查看、创建、撤销；新增“API Token 管理员”岗位模板，并纳入区县管理员和市公司管理员标准岗位。未授权用户不展示 Token 面板，后端直接访问返回 403。Token 自身仍被禁止访问 `/api-tokens/**`，也不会因为拥有这些权限而创建 Token 链。

## `2.5.4` 候选验证结果

- 后端全量测试：84 个测试类、267 项测试，失败/错误/跳过均为 0；包含 Liquibase H2 全量迁移、权限目录漂移、内置岗位和 API Token 接口 403 验证。
- WEB：52 项测试、ESLint 和生产构建通过；无 lint 错误或警告。未授权账号不挂载 API Token 面板，查看、创建、撤销按钮分别按权限显示。
- APP：52 项测试、TypeScript、Expo Doctor 19/19、构建资产安全检查和版本契约通过；查询缓存按账号隔离。
- 版本契约：Backend、WEB、APP 统一为 `2.5.4`，Android `versionCode=1005004`、`runtimeVersion=android-2.5.4-native1005004`。
- 本候选未构建 APK、未登记发布中心、未修改测试或生产运行态。

## `2.5.5` 候选整改范围

- 敏感配置响应不再携带原值；`configured` 仅表达是否已配置，固定掩码不泄露长度、前后缀，敏感配置值不参与管理端搜索。
- WEB/APP 编辑敏感配置时不预填原值；留空显式提交 `retainSensitiveValue=true`，输入新值才执行覆盖，避免客户端把掩码误写回数据库。
- 新增 `CredentialRevocationService` 统一编排本人修改密码和管理员重置密码后的 Session、API Token、受信设备处置。
- 受信设备进入 `REAUTHENTICATION_REQUIRED`，旧会话立即失效；只有同一安装实例、同一公钥在新密码认证成功后才恢复为 `TRUSTED`。人工永久撤销的 `REVOKED` 设备不会自动恢复。
- Liquibase `052` 扩展受信设备状态字段并增加撤销原因，记录密码事件产生的设备信任撤销。
- 后端 89 个测试类、277 项测试，WEB 52 项测试/ESLint/生产构建，APP 52 项测试/TypeScript/Expo Doctor 19/19/版本与资产门禁均通过。
- Expo/Metro 构建链仍有 `image-size` 的 8 项 high 传递告警；资产魔数门禁已拒绝受影响格式，当前自动修复路径会降级 Expo 主版本，保持为已知受控构建期风险并等待同 SDK 上游修复。
- 本候选未构建 APK、未登记发布中心、未修改测试或生产运行态。
