# ADR：使用现有 MySQL 构建轻量化客户端可观测性

- 日期：2026-08-09
- 状态：已实施并投产

## 决策

客户端通过统一 Telemetry SDK 将有界批次写入 Spring Boot，后端先将脱敏事件写入 Redis 有界缓冲，再由单消费者合并批次写入 `client_observation_events`，并在现有管理后台提供受组织权限约束的检索能力。Android 使用 SQLite 离线队列，Web 使用有界本地队列；服务端关键写请求另行生成权威操作事件。

## 关键取舍

- 单表事件模型替代日志、链路、告警、问题单等多套模型，当前规模下可依靠组合索引和保留期控制满足检索成本。
- 不做问题聚合状态机、告警规则和市县对比，观测中心只负责提供排障事实，不复制工单系统能力。
- `installationId` 是可重置的应用安装标识，只用于事件重试和同次安装关联；不采集任何系统或硬件唯一标识。
- 认证身份、租户和组织由服务端写入，客户端仅提供环境与操作上下文；匿名事件只进入默认租户且仅租户全域管理员可见。
- 客户端与服务端均执行脱敏，服务端脱敏是最终安全边界。
- Redis 使用 ready/processing/dead-letter 队列和 AOF，提供至少一次投递；MySQL `client_event_id` 唯一约束消解客户端重试、消费者恢复和确认失败产生的重复事件。
- 不引入新的 Kubernetes 组件，降低单节点 VPS 的内存、存储和升级负担；当事件量或查询时延超过 MySQL 设计容量时，再通过稳定 API 契约替换存储实现。

## 容量边界

- 默认 30 天保留、每批 20 条、最大 50 条；警告和错误完整采集，操作事件仅记录关键写请求。
- 本地队列有界，错误和诊断优先于操作事件；数据库按租户、组织、接收时间、严重度和分类建立索引。

## 结果

该方案能够在现有部署资源内提供错误编号关联、客户端环境、操作上下文、离线补传和权限隔离，同时保留未来迁移到专用观测存储的边界。
