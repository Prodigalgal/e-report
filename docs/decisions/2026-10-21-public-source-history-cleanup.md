# 源码仓库公开与敏感历史清理

## 目标与边界

将 `Prodigalgal/e-report` 源码公开以使用公共仓库的标准 GitHub Actions runner。`e-report-config` 保持私有，运行凭据继续通过私有配置仓库和 GitHub Secrets 提供。

用户已授权重写包含敏感资料的历史，并接受相关 commit/tag 变化及 GitHub 缓存、制品引用清理。仅在源码、可见历史、附属内容和服务端敏感引用处理完成后切换公开；本轮仍只自动部署测试环境。

2026-10-22 用户追加决定：接受放弃仓库身份和历史记录，删除后重建同名源码仓库。现已采用独立 public 仓库（ID `1429111686`），main 以完成脱敏和回归的 `6.8.4` 源码树建立快照；四个 Android 基础包 tag 分别保留脱敏源码快照，不导入原提交祖先或 PR refs。原仓库（ID `1325651935`）已删除，Support 工单 `4889540` 继续处理其服务端残留，并明确排除同名新仓库。以下历史改写记录保留已执行的脱敏与数据库兼容依据。

新仓库已恢复 11 个 Secret、现有镜像的 Actions Write 权限和四份 Release 的八个原始资源。APK/manifest 的原始字节、摘要和签名保持一致，GitHub Release/asset ID 随新仓库重新生成；私有配置仓库记录完整映射。匿名检查新 main 可访问、原敏感 SHA 和原 PR 不可访问、配置仓库返回 404。

## 范围与实施

1. 在独立副本检查全部远端分支、tag、PR 引用、发布资料及 Actions 附属内容；对通用密钥规则和已知私有凭据分别扫描，并人工区分真实个人信息与测试数据。
2. 对确认的敏感值执行精确替换，保留业务规则、测试含义和既有功能。已执行的 Liquibase changeset 使用精确的旧校验和兼容，禁止跳过所有校验或直接清空数据库校验和。
3. 使用 `git-filter-repo --sensitive-data-removal` 重写完整历史，验证脱敏后再更新原仓库分支/tag；保留私有的映射与审计结果，防止旧 clone 再次推入清理前历史。
4. 已发布 APK、镜像、OTA 和签名内容保持原始字节及摘要。发布 tag 指向清理后的对应提交；基础包清单保留其原始构建溯源，业务候选继续通过现有封装引用不可变基础包。
5. GitHub 的只读 PR 引用及旧提交缓存按官方流程申请清理；不能用本地扫描或强制推送代替服务端清理结果。

## 非目标

不修改生产账号密码、不重签或覆盖已发布制品、不提升生产、不修改用户主工作树中的其他开发内容。

## 数据库兼容

当前生产和测试使用 PostgreSQL changelog，不加载包含人员定向修复的 MySQL/H2 changeset。该历史修复中的人员身份改为六个 `countyAdministratorUsernameA/B/C`、`countyAdministratorNameA/B/C` 参数；公共默认值不选择任何账号。已执行数据库接受原有版本 8、9 的精确校验和，其他不匹配仍报错，已执行步骤不重新运行。

尚未执行该步骤的 MySQL 存量库，必须在私有迁移配置中完整设置 `COUNTY_ADMINISTRATOR_USERNAME_A/B/C`、`COUNTY_ADMINISTRATOR_NAME_A/B/C` 后运行数据库迁移工具，并持续保留这些配置。原部署映射仅存于服务器管理的私有运维目录。新安装不存在该部署的定向人员修复需求。

包含真实人员资料的三张 WEB 设计截图从全部历史移除，文档改为链接到脱敏 HTML；APP 流程图保留。运行 API、权限和当前 PostgreSQL 业务迁移不变。

同一私有密码对应的历史预生成 BCrypt 哈希也已替换为独立测试基线。该步骤保留当前部署租户对应的版本 8、9 精确 SQL 校验和，已有账号不重置密码。组织隔离测试显式准备当前岗位授权，并在事务回滚后清除测试快照；原始迁移资源下独立运行也能复现的权限夹具依赖已消除。

## 本地验证与公开门禁（2026-10-22）

- Backend 139 个测试类、518 项测试及 bootJar 通过；涵盖脱敏迁移、旧校验和、重复升级不重跑、未配置身份不误选、配置完整性和 SQL 字面量边界。
- WEB 92 项、lint/build；APP 79 项、typecheck；发布工具 26 项、供应链策略 19 项及版本/供应链契约通过。业务候选为 `6.8.4`，原生 `6.8.2`、Lite `6.8.1` 的基础包身份和指纹不变。
- 全历史通用密钥扫描覆盖全部远端 refs；另外比对私有运行凭据、个人资料及已确认的凭据哈希。具体替换值和提交映射仅保存在私有运维目录。
- 203 份 Actions 制品、854 份日志完成检查，无未处理的凭据发现；79 处公开漏洞公告示例与 50 处公开 Expo 资源标识已分别核实。GitHub PR/发布说明等附属正文未发现需要脱敏的值。
- 已清除 45 份 Actions 构建缓存，PR 已关闭，源码和配置仓库暂时仍为 private。待历史更新、服务端 PR 引用/缓存清理并核验后再切换源码仓库可见性；GitHub Support 的处理结果不能由本地检查替代。
- 本轮不修改任何生产工作负载或账号；现有 APK/镜像/OTA 使用原制品，后续测试候选继续走既有自动化链路。

## 验收与验证

- 全部拟公开 refs 的通用密钥及已知凭据扫描无未处理发现；确认的个人信息在文本、提交说明及公开附属内容中清除。
- 旧 Liquibase 校验和可通过验证，已执行 changeset 不重跑；脱敏后的新库迁移语义保持有效。
- 版本契约、相关 Backend 测试、WEB/APP 及发布工具验证通过，原生指纹不变。
- 私有配置仓库可见性不变，自动化仍只由本仓库 main 的可信审计结果触发；公开后由 GitHub Actions 和 Argo CD 执行测试发布。
- 记录清理后的 main、影响 refs、不可变制品摘要、GitHub 服务端处理状态及剩余验收边界。

## 回滚约束

业务故障使用既有不可变镜像回滚；禁止把含敏感资料的旧 Git 历史推回公开仓库。历史映射仅保存在私有运维目录，旧工作副本须迁移后再恢复推送。

## 原生基础包复用门禁（6.8.5）

重建后的 `6.8.4` 原生任务在复用基础包前执行 Expo Doctor，被在线推荐的 Expo、location、router 三个补丁版本阻断；APP 测试、静态类型和资产检查此前均通过，原生基础包指纹未改变。

Doctor 调整到构建新基础包的分支。每个候选仍执行 npm 锁文件安装、原生模块契约、APP 测试、typecheck、资产、版本和原生指纹检查；复用时还必须验证 APK 包名、版本、runtime、指纹、签名、大小和 SHA-256。指纹或包身份不符时直接失败，不能借复用跳过原生变更。需要新建基础包时完整 Doctor 检查继续阻断不匹配的 SDK 依赖。原生 `6.8.2`、Lite `6.8.1` 的基础包身份和签名不变，业务候选递增为 `6.8.5`。
