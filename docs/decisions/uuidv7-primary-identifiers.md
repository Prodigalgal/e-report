# UUIDv7 技术主键

## 状态

已采纳，适用于本版本后的全部持久化实体。

## 决策

- 所有应用实体使用 `java.util.UUID` 技术主键，统一继承 `UuidV7Entity`。
- Hibernate 使用 `@UuidGenerator(style = VERSION_7)` 生成新主键，不在业务代码中手工生成实体 ID。
- MySQL 主键和外键使用 `BINARY(16)`；H2 测试库使用原生 `UUID`。
- REST/JSON 使用 Jackson 标准 UUID 字符串，即小写、带连字符的 36 字符格式。
- 业务编码继续保留，例如 `work_order_no`、租户编码、组织编码和用户名；它们是唯一业务键，不再承担技术主键职责。
- 不提供数值 ID 与 UUID 双轨字段、数值路由兼容或 `CHAR(36)` 旁路。

## 理由

UUIDv7 的高位包含时间顺序，较 UUIDv4 更适合 B-Tree 聚簇索引的持续写入；同时避免多租户、多区县和离线客户端扩展时依赖中心自增序列。`BINARY(16)` 比 `CHAR(36)` 更节省索引空间，接口仍保持人和客户端都能稳定处理的标准字符串。

Jackson 负责 UUID 的 JSON 序列化与反序列化，不负责生成 UUID。生成策略唯一归属 Hibernate 映射，避免 Controller、Service、初始化器和迁移脚本各自形成一套生成规则。

## 迁移

- Liquibase 011 使用影子 UUID 列保存映射：先为历史主记录分配迁移 UUID，再按旧关系回填所有外键，验证无漏映射后重建主键、唯一约束、索引和外键。
- 已经是 UUID 文本的上传会话 ID 保持原值；其他历史主键会变化，迁移前后通过影子列完成一次性映射。
- 生产早期 Hibernate 哈希外键先规范化为显式约束名；已经退出运行时代码但仍存在于生产库的企业微信/API 资源表保留数据并同步转换，不静默删表。
- 历史行的迁移 UUID 不承诺版本为 7；迁移后由 Hibernate 创建的全部新实体必须是 UUIDv7。
- 旧 JWT 中的数字成员/租户 ID 不再兼容，发布后用户需要重新登录；Web 与 Android 路由、请求体和本地会话均只接受 UUID 字符串。

## 回滚

主键切换是破坏性、不可逆的结构迁移，不提供反向 changeset。生产执行前必须停止写入并生成全库备份；若 Liquibase 切换或上线 smoke 失败，回滚应用和数据库都以该备份为唯一恢复点，不能只回滚镜像。

## 验证

- 持久化集成测试断言新实体 `UUID.version() == 7`。
- Jackson 集成测试断言 UUID 输出标准字符串。
- H2 从空库执行完整 Liquibase 链并运行全部后端测试。
- MySQL 使用生产快照的隔离 rehearsal 库执行 011，核对行数、空外键、约束、索引和 Hibernate 启动。
