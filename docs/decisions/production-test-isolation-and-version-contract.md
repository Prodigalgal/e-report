# ADR：生产只读验证与隔离环境写入测试

- 日期：2026-08-10
- 状态：已接受，已实施

## 决策

写入型 E2E 使用三层防护：客户端阻断已知生产地址、服务端仅在隔离配置下暴露能力端点、能力端点验证全部通知渠道和 Outbox 入队均关闭。三层任一不满足时，E2E 在创建账号或工单前终止。

生产发布后仅运行独立的只读 smoke。它可以执行认证，但业务接口只使用 `GET` 和 `HEAD`；写入型生命周期测试不再以“执行后清理”作为生产隔离方案。

历史测试数据通过 Liquibase 的一次性、可前置校验的数据迁移删除，附件物理文件由受限运维工具在完整备份后回收。数据库迁移不直接操作宿主机文件，运维工具也不绕过 Liquibase直接删除数据库行。

Android 从 code39 开始以 `1.0.<versionCode>` 作为版本规则，`runtimeVersion` 固定为 `android-1.0.<code>-native<code>`。源码、APK 和发布登记使用同一校验器验证。

## 原因

- “测试后清理”仍会触发真实邮件、定时任务和观测告警，且异常中断会留下生产数据。
- 仅检查 URL 可以被反向代理或错误转发绕过；仅依赖服务端配置又可能误把生产配置为测试，因此需要双向确认。
- 客户端可控的跳过通知标记会成为业务用户压制通知的能力，不可接受。
- Liquibase 适合可审计的数据迁移，文件系统清理则需要路径边界和备份校验，两者职责不能混合。
- `versionName` 与 `versionCode` 错位会增加发布、升级和现场排障成本，必须在上传前自动阻断。

## 兼容与失败行为

- 生产默认不启用隔离能力端点，现有业务 API 不变。
- Outbox 入队默认开启；只有显式隔离配置可以关闭。
- 019 在没有历史测试数据的新环境中安全空跑；发现活动测试账号、非终态测试工单或测试账号参与业务工单时直接 HALT。
- 上传文件清单只允许受控文件名，最终解析路径必须位于 `/data/e-report/uploads`，否则拒绝删除。
- 清理或发布任一步失败时停止后续动作，保留备份和当前运行版本，不做部分成功声明。
