# ADR：以有效能力替代空身份角色

- 日期：2026-08-11
- 状态：已接受，待 1.0.43 实施

## 决策

角色是可授予权限与数据范围的集合，不再同时承担无权限“身份标签”。删除 `ROLE_ADMIN`、`ROLE_COUNTY_ADMIN`、`ROLE_PLATFORM_ADMIN`，管理员岗位由现有窄职责角色组合表达。客户端管理入口继续依据 `management:access`，用户称谓依据真实权限和职责展示。

角色目录不是租户内无条件公开字典。服务端仅返回权限集合为当前操作者有效权限子集的角色；岗位模板只有在其全部角色均可授予时才可见。权限目录同样裁剪，创建或修改自定义角色、岗位模板以及用户授权时再次执行服务端校验。

通知路由需要稳定的业务归属，因此新增具有明确业务权限的“市公司通知收件人”和“区县通知收件人”窄角色。它们分别进入市公司、区县管理员岗位模板，邮件解析不再查询空身份角色。

## 原因

- 无权限身份角色与真实授权并列显示，会让管理员误以为勾选一个名称就获得完整能力。
- 仅在前端隐藏高权限角色无法防止直接调用 API 越权，也会在用户详情和岗位模板接口泄露高权限目录。
- 以岗位模板组合职责、以角色承载权限、以 Grant 承载数据范围，三层职责清楚，支持区县与市公司差异化授权。

## 迁移与回滚

- Liquibase 先根据旧身份角色为现有管理员补齐通知收件角色和 Grant，再删除旧角色的模板关系、Grant、用户关系和角色实体，并递增授权版本。
- 默认区县密码重置、手机号/邮箱全局唯一约束和身份角色删除均属于数据契约变更；生产执行前必须备份并检查重复手机号和重复邮箱。
- 不支持单独回滚应用或数据库。失败时恢复迁移前数据库快照、Redis 授权缓存和 1.0.42 镜像。
