# 版本号与发布线治理

- 状态：已批准并自 2026-08-16 起执行
- 当前生产基线：`2.5.3` / Android `versionCode=1005003`
- 下一开发版本：根据实际兼容性影响从 `2.5.4`、`2.6.0` 或 `3.0.0` 选择，禁止预先占用或复用历史候选版本。

## 决策

项目从授权体系 V2 候选开始按 SemVer 管理版本。已发布版本保持不可变，不对 APK、R2 对象、发布中心记录、历史镜像或日志做追溯改名；尚未进入生产的候选可以在正式发布前按真实影响级别重定版本。

Android `versionCode` 按下式从 `x.y.z` 唯一计算：

```text
versionCode = (x - 1) * 1,000,000 + y * 1,000 + z
```

该公式兼容当前生产的 `1.0.47/code47`，并让后续 minor、major 版本仍保持全局递增。`y`、`z` 各保留三位，取值范围为 `0..999`。

## 历史审计

测试库由生产数据隔离同步，其 `app_releases` 表记录了实际发布事实：

| 发布阶段 | 实际记录 | 处理结论 |
| --- | --- | --- |
| 早期发布 | code2 至 code26 对应 `1.0.1` 至 `1.0.25`，存在一位偏移 | 保留原记录，不追溯改名 |
| 中期发布 | code28 至 code38 对应 `1.0.27` 至 `1.0.37`；code27、32 等存在未发布空档 | 空档永久保留，不复用 |
| 对齐发布 | code39 至 code42、code45 至 code47 与 `1.0.<code>` 对齐 | 保留并作为旧规则收口线 |
| 未单独发布 | code43、code44 没有 APK 发布记录，功能随 code45 统一上线 | 不补发、不复用 |
| 授权 V2 测试候选 | `1.0.48/code48` 只部署测试环境，从未进入生产发布中心 | 停止使用，正式候选重定为 `2.0.0/code1000000` |

历史上 code 与 versionName 不完全一致，因此排障和审计必须同时记录二者，不能只凭其中一个推断旧版本。

## 2.0.0 判定依据

授权体系 V2 删除旧 Role/RoleBundle 运行时与兼容层，迁移授权事实表，调整原子权限、委派边界、用户授权 API、WEB/APP 管理流程和导入导出契约。这些变化对数据、API 和权限语义均不向后兼容，符合 major 版本条件，不能作为 `1.0.48` patch 发布。

## 发布约束

- Backend、WEB、APP、Liquibase tag、镜像、SBOM 和发布说明统一使用同一个正式 `x.y.z`。
- 测试镜像使用 `x.y.z-<purpose>-test-N`；历史测试 tag 不重命名。
- 正式 APK 的 `versionName` 使用 `x.y.z`，验收变体仅通过 `-acceptance` 后缀和独立包名区分。
- 已发布 APK 和 R2 对象不可覆盖；客户端回滚必须发布更高版本。
- 每次版本变更都必须由 `verify-version-contract.mjs` 同时校验源码、Gradle、runtime 和 APK 元数据。
- 每个可部署的开发/测试候选都必须占用新的 `x.y.z`；候选部署后只要修改 deployable 代码、配置或数据库迁移，就必须继续递增版本。
- 测试通过后提升同一不可变镜像与 APK 到生产，禁止为生产重新构建同版本制品。

## 2.1.3 发布线

`2.0.0` 完成授权体系 V2 与用户批量治理的破坏性迁移；`2.0.1` 完成读模型、缓存与入口性能优化；`2.1.0` 引入 API Token 与 AI Guide。由于候选门禁连续发现原生依赖锁和入口迁移脚本问题，`2.1.0`、`2.1.1`、`2.1.2` 均只作为拒绝提升的测试候选保留，最终生产版本为 `2.1.3/code1001003`。

`2.1.3` 于 2026-08-17 发布，Backend、WEB、APP、Liquibase、SBOM、R2 对象和发布中心记录使用同一版本身份。后续不得覆盖 `android/stable/1001003/app-release.apk`，也不得复用 code `1001000..1001003`。

## 2.2.0 发布线

`2.2.0` 新增 WEB 可选持久登录、修复 APP 冷启动 refresh 恢复，并补齐长交互 loading 与登录计算性能优化，属于向后兼容的用户可感知能力，因此递增 minor 而不是 patch。

`2.2.0/code1002000` 于 2026-08-17 发布，Backend、WEB、APP、Liquibase、R2 对象和发布中心记录使用同一版本身份。测试通过后将同一不可变镜像提升至生产，后续不得覆盖 `android/stable/1002000/app-release.apk`，也不得复用 code `1002000`。

## 2.5.3 发布线

`2.5.0` 完成附件数量与容量提升以及显式分页契约；`2.5.1`、`2.5.2` 在权限目录和默认管理员迁移验收中分别发现历史空授权、冗余标准 Grant，均作为拒绝提升的测试候选保留；最终生产版本为 `2.5.3/code1005003`。

`2.5.3` 于 2026-08-20 发布，Backend、WEB、APP、Liquibase、SBOM、R2 对象和发布中心记录使用同一版本身份。后续不得覆盖 `android/stable/1005003/app-release.apk`，也不得复用 code `1005001..1005003`。
