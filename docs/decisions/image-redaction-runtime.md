# 图片品牌脱敏运行时决策

## 决策

图片脱敏采用“本地训练、独立 CPU Worker 推理、Backend 持久化编排”的结构。Backend 与 Worker 只通过 PostgreSQL 任务表和共享隔离存储协作，不增加公开服务、外部视觉 API 或新的消息中间件。

## 取舍

- 单个轻量目标检测模型同时覆盖图形标识、中文品牌字样、英文品牌字样和组合标识，降低 VPS 常驻内存；通用 OCR 仅作为后续召回不足时的可插拔二次检测器。
- PostgreSQL 是任务状态事实源，Redis 只能用于后续的非可靠唤醒优化；这保证 Redis 重启不会丢任务。
- Worker 以数据库租约领取任务，并发固定为 1；模型或解码进程异常不能传播到 Backend。
- 原图与安全文件使用不同目录。下载代码只解析安全目录中的文件名，禁止用状态字段之外的兼容回退访问原图。
- 模型随不可变 Worker 镜像发布，启动时校验 SHA-256；模型升级不覆盖旧文件，任务记录实际使用版本。

## 安全边界

- 只信任服务端探测的媒体类型、尺寸和解码结果，不信任文件名或客户端 `Content-Type`。
- 限制压缩文件大小、解码后像素总量、单边尺寸和处理超时，防止图片炸弹与资源耗尽。
- 日志仅记录任务 ID、租户、模型/策略版本、数量、耗时和规范化错误码，不记录原图路径、识别文字或像素内容。
- 处理失败保持关闭，不提供“下载原文件”兜底。

## 回滚

Backend/WEB 回滚到上一不可变镜像；Worker 可缩容至 0。数据库新增结构保留，不删除已完成安全文件。未完成的新附件保持不可见，避免回滚期间泄露原图；恢复服务后继续处理或由运维精确清理。
