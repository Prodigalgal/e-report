# ADR：同一 APK 运行时选择测试或生产环境

- 状态：已采纳
- 日期：2026-10-01

## 决策

同一签名 APK 内置测试和生产 API 地址，默认生产。用户只在未登录状态下切换环境；当前环境名称持续显示。选择保存在设备安全存储。环境切换清除登录凭据和 React Query 缓存，重新从新环境加载验证码和数据。API 请求、附件上传、下载入口及遥测均读取同一当前环境配置；SQLite 遥测队列按环境分库，保留原生产队列并防止测试事件跨环境发送。

测试环境的 Backend 通过仅测试配置的邮件收件人 ID allowlist 限制邮件目标；生产不配置该值，继续按现有系统授权解析。该过滤覆盖新工单和调单接收通知，不移除系统基线授权，也不改变非邮件通知行为。

## 原因

构建时固定 API 地址会产生不同 APK，无法把同一不可变候选从测试验收提升到生产。测试端只部署测试域名的 APK 会让验收制品与生产制品不同。设备端运行时选择保持制品 hash 不变，同时通过会话清理和显式环境标识降低数据串环境风险。

## 备选方案

- 分别构建测试/生产 APK：与同一候选晋级规则冲突，且容易出现签名、versionCode、内容差异。
- 继续构建时注入 API 地址：只能生成不同二进制，无法验证将进入生产的同一个 APK。
- 测试时全局开启邮件并保留原授权收件人：可能把测试工单发给其他管理员，拒绝采用。

## 约束

测试收件过滤通过测试 GitOps 配置启用，默认空值保持现有生产行为。切换环境必须在未登录状态完成；不能在已认证会话中更改 API 目标。
