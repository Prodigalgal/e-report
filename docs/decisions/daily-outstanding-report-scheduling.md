# 每日工单汇总按配置时间触发

## 目标和范围

- 每个启用日报的区县按 `Asia/Shanghai` 的 `HH:mm` 预约执行，取消固定间隔扫描。
- 日报继续同时受通知中心、邮件渠道、日报开关和环境投递总闸控制；邮件渠道也控制即时工单邮件。
- 配置、组织目录修改提交后重排任务；启动、Redis 订阅恢复和每日零点重新加载预约。
- 保留租户与区县隔离、180 分钟补发窗口、60 分钟执行权超时回收，以及每日唯一执行台账。
- 不改变收件权限、收件地址、SMTP 发送方式和失败邮件重发策略，不新增数据库表或外部调度组件。

## 实现取舍

- 使用现有 Spring `TaskScheduler` 预约具体执行时刻，每次完成后预约下一天；邮件生成和 SMTP 使用独立线程池，避免阻塞其他定时任务。
- 缓存失效在事务提交后发出本地事件，相关事件通过现有 Redis 通知其他副本重排。订阅恢复时全量读取配置，每日零点再做一次配置校准。
- 调度及实际发送都读取数据库配置；多副本通过执行台账的唯一键及条件更新竞争执行权，不依赖扫描锁。
- 未完成的 `PROCESSING` 记录按租约到期时刻单独预约恢复，不进行周期扫描。SMTP 部分失败仍记入当天台账，不给已经成功的收件人整批重发。
- 补发窗口按原定发送时刻计算，可跨北京时间零点；持久化时间继续使用 UTC，台账日期使用原定发送的北京时间日期。

## 影响与验收

- 主要影响：`reporting/`、缓存提交后事件、调度配置、相关测试及日报运行配置。
- 验收：到点触发、配置变更重排、关闭后取消、启动窗口内补发、窗口外不补发、跨零点日期正确、执行权超时恢复、重复触发不重复投递、任务异常不阻断其他区县。
- 验证：后端相关单元/集成测试、`bootJar`、版本契约及 diff 检查；真实邮件送达单独验收，不以调度注册或 SMTP 接受代替收件确认。

## 回滚与边界

- API 和数据库结构不变；应用可回滚至上一不可变镜像。撤销生产邮件恢复可通过同一管理 API 关闭南靖县邮件渠道。
- Redis 通知不作为持久任务队列；副本启动、订阅恢复、每日校准及执行前校验以数据库为准。数据库提交后、广播前进程异常的极窄窗口，其他副本可能要等下一次校准才能获得新预约。
- SMTP 接受后、台账完成前进程崩溃无法保证外部邮件严格一次送达；沿用现有执行权回收策略，保留可追踪台账。
