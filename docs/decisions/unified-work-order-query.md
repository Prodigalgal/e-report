# 统一工单查询与权限范围

## 决策

- 故障、未关箱和破损换箱共享一个工单领域模型，以 `reportType` 区分类型。
- Web 与 App 只保留一个“工单查询”业务入口；报单、详情和回单是独立动作，不再建立“我的工单”“待我处理”“工单管理”等平行列表。
- 查询入口同时承载关键词、类型、状态和高级条件筛选，并在有回单权限且状态可处理时显示处理动作。
- 后端只提供 `GET /work-orders/search` 和 `GET /work-orders/statistics` 两个读取端点；旧的 `/work-orders/my`、`/work-orders/admin` 和 `/work-orders/admin/statistics` 不再提供。
- 可见范围在数据库查询阶段统一计算：本人上报工单，或当前角色对对应工单类型具有查看/回单权限的工单。业务筛选条件在可见范围之上继续使用 AND 组合。
- 统计端点继续按角色可查看的工单类型聚合，不承担工单列表查询。

## 取舍

- 权限端点保持固化，角色只组合已有权限；不引入运行时动态端点。
- Web 旧路径仅执行无界面跳转，便于已打开页面回到统一入口；后端旧接口直接返回 404，不保留双实现。
- App 旧文件路由仅执行统一入口跳转，业务列表实现已删除，避免两套状态与缓存继续演进。

## 验收

- 普通用户只能查询本人上报工单；具有工单类型权限的角色可同时查询本人和职责范围工单。
- Web 桌面与移动端、Android 首页和侧边栏均只展示一个工单查询入口。
- 旧后端列表端点返回 404，统一查询、详情、统计和回单端点正常。
