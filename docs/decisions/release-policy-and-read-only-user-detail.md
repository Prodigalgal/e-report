# ADR：发布策略独立授权与只读用户详情

- 日期：2026-08-10
- 状态：已接受并实施

## 决策

用户详情采用稳定的只读 Query 页面，所有 Command 通过按职责拆分的弹窗发起。现有 `PUT /admin/users/{userId}/detail` 继续接受局部请求，但每个弹窗只传递自己拥有的字段，服务端字段级权限和单事务规则保持不变。

发布记录的文件身份与更新策略分离。文件身份发布后不可变；强制更新、最低支持构建号和更新说明由独立策略接口维护。新增 `app-update:policy-update` 权限和 `ROLE_RELEASE_POLICY_MANAGER`，不把策略修改并入发布、删除或对象存储权限。

## 原因

- 只读页面能明确区分“查看事实”和“发起变更”，避免长表单误触或保存时夹带无关字段。
- 分弹窗提交缩小失败面，权限提示、校验错误和成功反馈都能落到具体职责。
- 发布完成后通过 SQL 改 `force_update` 不可审计、不可复用，也无法由产品界面验证最终结果。
- 版本身份可变会破坏 R2 不可变对象路径、APK 哈希和客户端升级判断，因此只开放策略元数据。

## 兼容与失败行为

- 1.0.39 及更早客户端继续消费原有更新检查响应，无需兼容分支。
- 发布策略修改立即影响下一次更新检查；R2 对象和固定下载入口不变化。
- `forceUpdate=false` 不会覆盖最低支持构建号产生的强制升级：客户端版本低于 `minSupportedVersionCode` 时仍必须升级。
- 弹窗失败时保留草稿，主详情继续显示最后一次服务端确认值。
