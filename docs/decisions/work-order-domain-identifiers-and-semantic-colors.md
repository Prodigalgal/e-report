# ADR：工单领域标识深度迁移与正交颜色语义

- 日期：2026-08-10
- 状态：已接受并实施（2026-08-10）

## 决策

将工单类型、优先级、角色、权限和客户端路由视为同一领域契约，在 1.0.41 中一次性迁移为新标识，不保留运行时别名、旧请求兼容或双读双写。历史 Liquibase 文件不可修改，生产数据通过新的 022 changeSet 原位转换。

Web 与 Android 共同读取 `shared/work-order-presentation.json`。该文件只负责展示语义；后端枚举和 DTO 负责业务语义。工单卡片以优先级决定左侧轨道，类型、SLA 风险和状态分别使用独立徽标，任何维度不得覆盖另一维度。

SLA 风险由后端 `WorkOrderSlaService` 统一计算。临期定义为剩余时限不超过当前环节配置预算的 20%；客户端只使用 `slaRiskLevel` 展示，不根据本地时钟或硬编码时长重新分类。

## 原因

- “普通故障”会被理解为严重程度，但它实际表达的是网络故障类型；`NORMAL` 同时承担类型文案和优先级含义也容易混淆。
- 表层改名会让旧枚举、权限、路由和角色长期并存，增加授权错误、缓存污染和后续维护成本。
- 红色同时表示紧急、超时、工单类型或状态时，用户无法快速判断真正风险；颜色维度必须正交。
- 客户端独立计算 SLA 会受策略调整、暂停时间和设备时间影响，服务端统一计算才能保持 Web、Android、通知和报表一致。

## 取舍

- 这是不可滚动兼容的契约切换，需要数据库停写窗口和整版部署；换取迁移后没有兼容层和长期歧义。
- 角色与权限保留 UUID 原位改名，既保持所有 Grant 与岗位模板关联，又避免同时维护两套编码。
- `shared` JSON 是构建期契约，不引入运行时配置服务；保持部署简单，并由单元测试验证枚举与 JSON 完整对应。

## 失败与回滚

- 任一旧值未清零、角色/权限重名、工单或授权关联数量异常时，Liquibase 或发布验收必须停止。
- 应用切换后清理 Redis 授权缓存；若发生不可接受问题，停止写入并整体恢复迁移前数据库快照与 1.0.40 镜像。
- 已登记的 Android code41 不降级、不复用；修复版本使用更高且与 versionName 尾号一致的 code。
