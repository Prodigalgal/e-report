# Redis 系统级接入决策

## 决策状态

- 日期：2026-08-09
- 状态：已实施并投产
- 适用范围：Spring Boot 后端、单节点 Kubernetes Redis、Web/App 客户端观测缓冲

## 目标

Redis 作为系统的共享并发基础设施，承担高频只读数据缓存、短期原子状态、跨实例协调和有界异步缓冲，减少每个 Bearer 请求重复加载用户、角色、权限、组织树、SLA 策略和仪表盘聚合造成的数据库 I/O。

MySQL 继续作为用户、权限、组织、工单、SLA、幂等记录、通知 Outbox 和客户端观测事件的唯一事实源。Redis 丢失后允许重建缓存和短期状态，不允许依靠 Redis 恢复任何业务事实。

## 接入分层

| 类别 | Redis 数据 | 一致性与故障语义 |
| --- | --- | --- |
| 读缓存 | 鉴权快照、组织目录、SLA 策略、系统配置、工单统计 | cache-aside；写事务提交后失效；读取失败回源 MySQL；短 TTL 限制失效失败的窗口 |
| 原子状态 | 登录挑战、接口限流、地图密钥游标、R2 同步租约 | 使用 `SET NX`、Lua、原子计数和 TTL；安全/并发控制不可用时拒绝相关请求，非关键游标允许本实例降级 |
| 幂等加速 | 已完成命令的响应快照 | MySQL 幂等表仍为最终依据；Redis 只在重复请求时减少数据库读取，缺失时回源 |
| 分布式协调 | SLA 扫描、日报扫描、Outbox 拉取、观测落库和数据清理租约 | Redis 锁减少多实例重复扫描；数据库唯一约束、行状态或业务台账仍承担最终幂等 |
| 可靠缓冲 | 客户端观测 ready/processing/dead-letter 队列 | Redis AOF `everysec`、有界队列、至少一次投递；MySQL 唯一键消重；Redis 不可用时客户端保留本地事件并重试 |

## 缓存契约

- 所有 key 使用带显式版本的 `e-report:<domain>:vN:` 前缀，租户数据必须在 key 中包含 `tenantId`，用户数据必须同时包含 `membershipId`；缓存序列化格式变更必须提升版本，禁止混读旧值。
- 鉴权快照不保存密码、手机号、邮箱、Token 或设备标识，只保存鉴权所需的账号状态、授权版本、角色、权限和数据范围。
- 鉴权快照 TTL 为 60 秒；用户状态、组织、角色、权限或授权范围变更时，在数据库事务提交后失效。失效失败时最多保留一个 TTL 窗口，下一次回源会重新校验租户和账号状态。
- 组织目录和 SLA 策略只缓存不可变 DTO 快照，不缓存 JPA 托管实体。
- 工单统计 key 必须包含租户、用户、授权版本、组织筛选和工单类型；所有影响统计的工单状态写入提交后清理统计缓存。
- 不缓存任意组合的工单分页查询、附件内容、用户密码、验证码明文或敏感配置明文副本。

## 可靠性与容量

- Redis 使用单实例有状态部署、AOF `everysec` 与周期 RDB 快照，生产卷为 `/data/e-report/redis`。
- `maxmemory-policy=noeviction`，队列和安全状态不能被静默淘汰；所有缓存均设置 TTL，观测队列和死信队列均设置硬上限。
- 观测缓冲限制单批序列化结果不超过 512KB，`ready + processing` 合计不超过 64MB，死信只保留最近 32 批，给验证码、限流、锁和核心缓存保留内存余量。
- 观测入队与缓冲字节计数、处理确认与计数扣减、移入死信均由 Lua 原子完成，避免 Redis 断连形成列表和容量计数的半状态。
- Redis 达到容量上限时，缓存读取回源数据库；登录挑战、限流和观测接收返回可重试错误，不静默绕过安全控制或丢事件。
- Redis 设置访问密码，仅通过 Kubernetes Secret 注入 Redis 和后端；Service 不暴露 NodePort/公网入口。
- 部署前必须备份现有 AOF/RDB 和 Kubernetes 工作负载，先验证 Redis 恢复与认证，再滚动后端。

## 非目标

- 不用 Redis 替代 MySQL 事务、工单状态机、通知 Outbox、持久幂等记录或审计事件表。
- 不引入 Redis Cluster、Sentinel、Prometheus、Grafana 或新的消息中间件；当前单节点规模优先保持轻量和可运维。
- 不采集 IMEI、MAC、设备序列号、Android ID 或其他硬件唯一标识。

## 验收标准

- 同一有效 Bearer Token 的连续请求命中鉴权快照，数据库鉴权查询显著减少；账号停用、角色或数据范围变更后缓存按事务提交失效。
- 组织目录、SLA 策略和工单统计命中缓存；相关写入后下一次读取返回最新数据。
- 限流、锁、一次性挑战和队列 Lua 操作具备并发测试；锁内业务异常不得被当作 Redis 故障吞掉。
- Redis 重启后 AOF 数据可恢复，密码校验、健康探针、内存策略、队列边界和后端连接均通过验证。
- Redis 不可用时，纯缓存能力可回源；安全控制和可靠缓冲按契约明确失败，不产生静默绕过或直接写库洪峰。
