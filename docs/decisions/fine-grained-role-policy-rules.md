# ADR：角色权限关联携带固定范围策略

- 日期：2026-08-09
- 状态：已接受并投产
- 扩展：`rbac-capability-role-bundles.md`

## 决策

系统继续使用固定原子权限、窄角色和成员角色授权，但将 `role_permissions` 从无属性的多对多关联升级为 `RolePermissionRule`。每条规则同时指定权限和平台固定的 `scope_profile`，使一个岗位中的报单、查看、处理和历史读取可以使用不同范围。

工单角色按“工单类型 × 职责”物化为明确角色，不使用“通用职责角色 + 类型角色”的并集组合。跨类型岗位通过租户级岗位模板展开为多个窄角色；模板可自定义，但展开后仍是明确角色与 Grant。

## 原因

- 单一 `DataScope.SELF` 同时表达提单人和处理人，无法区分历史关系。
- 角色级统一范围不能表达“组织内接单，但只处理本人当前工单；调离后仍可查看参与历史”。
- 无有效 Grant 回退为全租户会把过期授权放大为更高权限。
- 类型角色与职责角色分别授权采用并集语义，无法安全表达二者必须同时满足。

## 授权顺序

```text
认证成员
  -> 有效角色授权
  -> 匹配 RolePermissionRule
  -> 租户硬边界
  -> scope_profile 关系或组织范围
  -> 领域状态机
  -> 字段投影与 allowedViews / allowedActions
```

列表 SQL 和详情对象校验必须由同一组范围策略生成，禁止 Controller、客户端或独立查询再次推导可见范围。

## 兼容与回滚

- `role_permissions` 原表原位增加字段，不建立长期双表或运行时旧角色别名。
- Liquibase 先创建权限和窄角色、复制授权并校验，再删除旧宽角色。
- 应用发布失败时恢复迁移前数据库快照和上一版本镜像；不允许只回滚应用而保留新角色契约。
