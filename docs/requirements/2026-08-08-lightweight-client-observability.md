# 轻量化客户端可观测性一期需求

## 目标

- 在不部署 Prometheus、Grafana、Loki、Tempo、Sentry、Kafka 或 ClickHouse 的前提下，统一采集 Web、Android 和后端关键操作、警告、错误及诊断上下文。
- 让后台人员能够通过错误编号、时间、平台、功能分类和环境信息定位用户现场问题，重点覆盖 Android 定位、网络、附件和应用升级链路。
- 复用现有 Spring Boot、Redis、MySQL、配置中心、租户与组织权限体系，保持单节点 Kubernetes 的资源占用和运维复杂度可控。

## 范围

- 后端：批量采集 API、Redis 有界缓冲、服务端关键写操作审计、双重脱敏、幂等、限流、MySQL 批量落库、分页查询、详情查询和定时清理。
- Web：全局异常、未处理 Promise、React 渲染错误、API 失败、关键写操作和最近操作面包屑。
- Android：JS 异常、API 失败、关键写操作、离线 SQLite 队列、网络恢复补传、定位链路诊断、原生崩溃标记和用户主动上传诊断。
- 管理端：按权限范围查询事件和查看脱敏详情，不提供告警、区域对比或问题状态流转。
- 配置：采集开关、警告/操作开关、批量大小、发送间隔和保留天数继续使用现有配置中心的租户/组织继承模型。

## 非目标

- 不新增独立观测基础设施、消息队列或搜索引擎。
- 不采集 IMEI、MAC、设备序列号、Android ID、广告 ID 或其他硬件唯一标识。
- 不建设错误告警规则、错误激增检测、同型号聚集告警、市县数据对比或问题处置状态机。
- 不采集表单正文、附件内容、密码、令牌、验证码、Cookie、手机号、邮箱、详细地址和精确经纬度。

## 数据与 API 契约

- `client_observation_events` 使用 UUIDv7 主键；`client_event_id` 为客户端重试幂等键。
- 事件类型限定为 `ERROR`、`WARNING`、`OPERATION`、`DIAGNOSTIC`，平台限定为 `WEB`、`ANDROID`、`SERVER`。
- `POST /observability/events/batch` 支持认证与未认证客户端；认证事件的租户、组织、用户归属仅由服务端身份上下文确定，客户端值不可信任。
- `GET /observability/policy` 返回当前组织解析后的客户端采集策略。
- `GET /admin/observability/events` 和 `GET /admin/observability/events/{id}` 需要 `observability:view`，并按现有 `DataScope` 收敛到所在租户及组织树。
- 匿名事件归属默认市公司租户且不归属组织，只允许具有租户全域数据范围的管理员查看。

## 可靠性与安全

- 客户端先落本地有界队列再批量发送；服务端幂等接收，网络恢复后重试，队列达到上限时优先保留错误和诊断事件。
- 单批最多 20 条，服务端硬上限 50 条；客户端上下文、面包屑、消息和堆栈均有长度、层级和数量上限。
- Redis 使用 ready/processing/dead-letter 三段队列、AOF 持久化和 `noeviction`；写库消费者先合并多个客户端批次，再执行一次幂等查询和批量插入。
- Redis 不可用或有界队列已满时返回可重试错误，客户端保留本地事件；不直接回退为请求线程写 MySQL。
- 未认证入口按来源地址执行分钟窗口限流；服务端再次递归清理敏感键和敏感值，避免绕过客户端脱敏。
- 默认保留 30 天，由定时任务分页清理；不在事务内执行网络或文件 I/O。

## 验收标准

- Web 和 Android 的错误、警告、关键写操作能够携带同一请求的 `X-Request-Id` 上报并在管理端查询。
- Android 无网时事件保留，恢复网络后幂等补传；定位失败包含权限、服务开关、Provider、缓存年龄/精度、厂商、型号和 Android 版本，不包含坐标或唯一硬件标识。
- 普通区县管理员只能读取其授权组织树内事件；市公司租户全域管理员可读取本租户事件；跨租户不可见。
- 密码、Authorization、Cookie、验证码、手机号、邮箱、地址、坐标和硬件标识不会写入数据库或管理页面。
- Liquibase 在空库、存量结构和二次执行场景通过；后端、Web、App 测试与构建通过；浏览器和 Android 模拟器完成真实上报、查询、离线补传和定位失败回归。

## 回滚

- 客户端可通过 `observability.client.enabled=false` 停止新增上报。
- 应用版本可先回滚，新增表和权限保留不会影响旧版本；确认无需保留观测数据后再单独执行 Liquibase 回滚删除表和固定权限。
