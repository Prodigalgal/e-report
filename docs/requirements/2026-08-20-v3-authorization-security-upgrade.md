# 权限体系 V3 与横向越权安全升级

- 最终交付版本：`4.2.0`（`4.0.0`、`4.0.1`、`4.1.0`、`4.1.1`、`4.1.2`、`4.1.3`、`4.1.4`、`4.1.5` 已由先前测试制品占用）
- 功能架构版本：权限系统 V3
- 状态：开发中，仅允许部署 `e-report-test`
- 变更级别：破坏性权限、数据库、数据与 API 契约升级

## 目标

将业务访问权、转授权权、账号管理权和高风险审批权彻底分离，解决同级管理员互相改权或接管账号、业务权限自动推导转授权权、组织范围与账号管理范围混用、默认管理员账号保护不完整等问题。

本任务同时将运行数据库从 MySQL 迁移到 PostgreSQL。权限系统 V3 是功能架构名称，`4.2.0` 是当前遵循 SemVer 的最终制品版本；二者作为同一测试闭环和同一生产切换窗口交付。

## 范围

- 保留原子业务权限、逐权限数据范围、资源关系和有效期。
- 新增管理域、账号保护级别、管理主体任命、显式委托授权和高风险动作策略。
- 用户详情与授权编辑改为按动作返回可执行能力和精确拒绝原因。
- 用户导入、岗位模板、直接授权、API Token 统一复用服务端 V3 策略。
- 密码、账号状态、会话、转授权权、默认管理员等高风险动作接入二次校验和审批策略。
- 使用 Liquibase 完成一次性深迁移；不保留 V2 运行时兼容判定。
- 建立 PostgreSQL 原生 `uuid`、统一时间语义、租户 RLS 防线、部分索引和表达式唯一约束。
- 提供可审计、幂等、失败可重跑的 MySQL 到 PostgreSQL 数据转换与逐表校验工具。
- Backend、WEB、APP、镜像、SBOM 和发布记录统一为 `4.2.0`；数据库沿用已验证的 PostgreSQL `4.0.0` baseline，并继续追加后续 changeset。
- 完成 Backend、WEB、APP、数据库、缓存、会话与 API 安全回归。

## 非目标

- 不引入 OPA、OpenFGA 或独立权限微服务。
- 不改变工单业务状态机和现有逐权限数据范围语义。
- 不在用户终验前部署生产环境。
- 不自动把现有业务权限转换为可转授权权限。
- 不保留 MySQL/PostgreSQL 双写或长期双数据库运行分支。
- 不把完整原子权限、组织关系和资源关系判定下沉到 PostgreSQL RLS。

## 影响模块

- Backend：权限目录、授权管理、用户管理、API Token、认证快照、缓存失效、审计。
- 数据库：PostgreSQL 4.0.0 baseline、管理域、账号保护、管理主体、委托授权、高风险请求与审批、租户 RLS、数据转换与校验。
- WEB/APP：用户详情、调整授权、结构化 Diff、精确权限提示。
- 用户导入导出：访问授权与委托授权分表、服务端预检和分片处理。
- 部署：`e-report-test` 迁移期间保留只读源 MySQL，并新增独立 PostgreSQL/Redis；目标应用只连接 PostgreSQL，通知与数据同步保持关闭。

## 核心验收标准

1. 拥有业务权限不再隐含转授权权。
2. 同一管理域、同保护级别的管理员不能互相改权、重置密码、停用或撤销会话。
3. 区县管理员不能管理其他区县或市公司保护账号；市公司上级可管理区县账号。
4. 区县默认管理员只能由市公司管理域调整；市公司默认管理员只能由 superAdmin 调整。
5. 所有授权范围、关系和有效期不得超过显式委托上限；下发转授权权还必须具有 `may_subdelegate`。
6. 任何用户不能自我提权、自我审批或降低自身保护级别。
7. WEB、APP、导入和直接 API 对同一动作得到一致判定。
8. API Token 只能携带业务访问权限，不能进入账号管理或委托控制面。
9. 管理写操作在 Redis/安全快照不可用时 fail closed。
10. `e-report-test` 完成 BOLA/BFLA、并发、缓存失效、会话撤销、浏览器和 Android 模拟器闭环后等待用户终验。
11. MySQL 全表数据转换后，行数、外键、UUID、时间、关键摘要以及工单附件关联全部一致。
12. PostgreSQL 应用角色不能绕过租户 RLS；组织和权限数据面仍由统一授权服务判定且结果不退化。
13. 切换前 MySQL 保持只读回滚点；目标应用开放写入前完成全部迁移门禁。

## 测试方式

- Backend 单元、集成、PostgreSQL Liquibase baseline、权限属性与并发测试；数据库契约测试使用真实 PostgreSQL，不再以 H2 MySQL 模式代替。
- 双会话角色矩阵：superAdmin、市公司默认管理员、市公司受托管理员、两个区县默认管理员、区县受托管理员、跨区县高权限用户、普通用户、API Token。
- WEB unit/lint/build 与真实浏览器授权流程。
- APP unit/typecheck/Doctor/release 与 Android 模拟器流程。
- 测试命名空间数据库约束、Redis 失效、HTTP/API、日志和 Pod 运行态验证。
- 至少两次由同一源备份执行的全量迁移演练，验证幂等、失败恢复、校验报告和切换耗时。
