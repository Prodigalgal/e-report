# WEB 与 APP 全页面视觉对齐及品牌标识

## 目标

- 覆盖 WEB、APP 全部页面及共用弹窗，统一页面边距、标题层级、卡片内容边界、表单控件、操作区及状态信息的对齐。
- 替换网络运维管理 LOGO，统一 WEB 导航、登录、加载、下载页、PWA，以及 APP、Android 启动和安装图标。
- 视觉对齐随 `6.4.0` 测试候选提交；用户选定 C 版 LOGO，并新增发件池组织策略后，统一以 `6.5.0` 生成新的不可变候选，由既有 GitHub Actions / Argo CD 流程构建与部署。

## 标识含义

- 用户选定 C 版：两段相互衔接的折叠路径组成 `N`，表达 Network 和跨组织网络运维协同；中间留白表示工单与责任沿确定路径流转。
- 保留现有品牌蓝，使用实心轮廓与小圆角。WEB 导航、登录和 APP 页面使用透明底蓝色标志，桌面图标使用蓝底白色标志。
- `shared/brand-mark.json` 保存唯一几何源，资源生成脚本同时产出 SVG、PNG 和 Android WebP，避免不同终端分别维护轮廓；自适应与 maskable 图标保留圆形遮罩安全区。

## 范围和约束

- 使用现有蓝色品牌、React/MUI、React Native/Expo 和共享契约目录；沿用现有字体家族与业务状态色。
- 通过共享尺寸契约和现有基础组件收敛视觉规则，再修正页面局部覆盖；页面布局负责外边距，内容组件负责内部间距。
- 保留全部业务入口、字段、交互、权限和加载/错误/空状态。视口适配检查长标题、操作按钮折行、表格滚动、弹窗高度和 Android 文本基线。
- LOGO 以可维护的矢量几何生成 WEB 与 Android 各尺寸资源；保留安装包名称、包名、签名和版本契约。
- 不改变 API、数据库或权限模型。生产仅恢复已授权的邮件渠道，新代码先部署测试环境。

## 验收与验证

- 共享组件和页面局部样式按同一尺寸体系工作，表单输入与按钮同排对齐，窄屏无页面整体横向溢出，长内容不挤出操作区。
- WEB 检查桌面和窄屏；APP 检查手机和宽屏布局。构建、静态检查与真实目视检查分别记录，不能相互替代。
- 运行 WEB 测试/lint/build、APP 测试/typecheck/资源校验/Android 构建、版本契约；补充测试环境 API、Pod、发布制品与定时任务运行态证据。
- 安全门禁的依赖告警单独处理；不能使用降级、全局忽略或禁用审计来完成发布。

## 回滚

- 应用使用前一不可变镜像回滚；Android 问题通过更高版本修复。视觉变更不涉及数据迁移。
