# 5.4.0 工单图片品牌脱敏

## 目标

对新上传的工单图片执行服务端自动脱敏，只模糊中国移动图形标识和品牌文字附近的小范围；原图在脱敏完成前不得通过工单附件接口访问。训练在本地 GPU 完成，资源受限的 VPS 只运行单并发轻量推理。

## 范围

- 报单材料和回单材料中的 JPEG、PNG、WebP、HEIC/HEIF 图片。
- 分片上传完成后的真实媒体类型、像素上限和解码安全校验。
- 持久化脱敏任务、状态、模型版本、检测数量、耗时、失败原因和重试信息。
- 独立 `media-image-worker`，数据库作为任务事实源；Backend 不在 HTTP 请求线程内推理。
- WEB/APP 上传完成后立即提交工单；附件以后台任务关联，安全处理不阻塞报单/回单。
- 本地合成训练数据、来源清单、训练/评估/ONNX 导出和模型完整性校验。

## 非目标

- 本版本不处理视频、GIF 动图、PDF 或 Office 文档内嵌图片。
- 不在生产环境训练，不在 APP/WEB 客户端执行可信脱敏。
- 不批量改写历史附件；历史治理另行使用限速迁移任务。
- 不把原图、识别区域或图片内容写入日志和埋点。

## 核心契约

1. 上传文件先落入隔离目录；工单可以立即绑定附件任务，但只有 `READY` 的脱敏派生文件可以预览或下载。
2. 图片状态为 `QUEUED -> PROCESSING -> READY`，失败进入 `RETRY_PENDING` 或 `FAILED`；任务具备租约、幂等和崩溃恢复能力。
3. 视频不创建图片脱敏任务、不进入本期处理队列，也不得被标记为已脱敏；视频处理能力后续独立建模。
4. 原图默认在安全文件生成并校验成功后立即删除；测试环境可配置短期隔离留存用于验收，但不得被普通 API 访问。
5. Worker 使用不可变、带 SHA-256 的 ONNX 模型；模型版本和策略版本写入每个任务。
6. 推理并发默认 1，输入先按最长边缩放推理，再映射回原图执行局部模糊；超像素、损坏或伪造媒体明确拒绝。

## 影响模块

- Backend：`FileTransferService`、`WorkOrderAttachmentService`、附件 DTO/实体、图片脱敏任务 API 与调度恢复。
- 数据库：Liquibase 新增图片脱敏任务与附件安全状态字段。
- Worker：`media-image-worker/` 训练工具、运行时、模型清单和容器构建。
- WEB/APP：分片上传完成后立即提交；详情页按附件任务状态展示处理中、失败或可用，不轮询阻塞提交。
- 部署：`e-report-test` 增加无公网入口的单副本 Worker、只读模型和隔离/安全目录。

## 验收标准

- 含中国移动图形标识、中文或英文品牌文字的验收图片只在命中区域附近被模糊，其他区域保持可辨识。
- 不含目标的负样本不发生大面积误模糊；损坏文件、伪造扩展名、超像素图片被明确拒绝。
- 原图在 `READY` 前后均无法通过工单附件接口访问；失败时不会回退到原图。
- Worker 停止、重启和重复领取不会产生重复附件或丢失任务，租约到期后可恢复。
- 单并发压测期间 Backend 登录、查询和工单 API 无明显退化，Worker 超限时由 K8S 限制而非拖垮业务 Pod。
- 初始候选 `5.4.0` 因 Worker PostgreSQL 字典行访问缺陷作废；修复候选 Backend、WEB、APP、数据库和镜像统一为 `5.4.1`。仅部署 `e-report-test`，用户验收前不切换生产。

## 测试方式

- Backend 单元/集成测试：状态机、租约、幂等、权限、文件隔离、错误模型与 Liquibase 幂等。
- Worker：模型校验、格式/像素边界、坐标映射、局部模糊、重试和资源基准。
- WEB/APP：上传后立即提交、附件处理态/失败态、窄屏和刷新恢复。
- 测试命名空间：真实图片 smoke、HTTP/浏览器/Android、Pod 内存/CPU、数据库与文件系统不变量检查。
