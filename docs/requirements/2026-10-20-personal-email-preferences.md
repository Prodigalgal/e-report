# 个人邮件订阅

## 目标与范围

- 每个账号可独立选择新工单、阶段超时、派单/调单到本人、每日未闭环汇总四类邮件，用户已确认四类均可关闭。
- WEB、APP 的个人信息页提供同一组设置，刷新和重新登录后保留。
- 现有账号及新账号默认全部开启，保留当前通知行为。
- 组织总开关、邮件渠道、收件权限、组织层级和测试环境白名单先限定候选人，个人订阅只能减少本人收信。
- 在发送时读取当前选择；先按人过滤，再按邮箱去重，避免共享邮箱的其他订阅者被误屏蔽。
- 全部候选人取消订阅是正常跳过，不尝试 SMTP，不触发失败重试；缺少可用地址仍按原有错误处理。
- 管理员主动发起的 SMTP 测试邮件继续发送到明确填写的测试地址。

## 契约与影响

- `GET /auth/me/email-notifications` 读取本人设置，`PUT` 原子保存全部四项；身份只取认证上下文，不接受目标用户或租户参数。
- 四个布尔字段：`workOrderCreated`、`workOrderSlaBreached`、`workOrderAssigned`、`dailyOutstandingReport`，缺少字段、`null` 或无法解析的布尔值拒绝保存。
- `users` 增加四个默认 `true` 的非空布尔列；迁移 `074` 属于 `6.4.0`。不改变个人资料、权限、导入导出或会话协议。
- 影响模块：用户投影及订阅 Service/Controller、邮件收件人解析、日报、WEB/APP 个人信息、Liquibase 和相关测试。
- 暂不增加免打扰时间、按工单类型订阅或即时通知合并。

## 验证与回滚

- 验证四类独立过滤、默认开启、全部关闭、权限与租户隔离、白名单、地址去重、派单过期事件和无 SMTP 重试。
- 验证 API 认证、入参、保存与重读，WEB/APP 加载/失败/保存状态，测试环境迁移和真实跳过/发送链路。
- 应用可回滚上一镜像并保留新增列；数据库回滚会删除订阅选择，通常无须执行。
