# 全域细粒度角色与工单关系授权

## 目标

- 将工单角色统一拆为“工单类型 × 提单、处理、调度、验收、管控、审计”十八个窄岗位。
- 将用户、配置、通知、发布和租户管理中的高风险宽角色拆为可独立授权的职责角色。
- 让同一角色中的不同权限使用明确的关系或组织范围，修复提单者历史工单、历史处理人以及过期授权的可见性问题。
- 保持市公司租户硬隔离、区县组织树范围、固定权限目录和服务端最终授权不变。

## 范围

- 后端固定权限、内置角色模板、角色权限策略、鉴权快照、工单查询与对象授权。
- Liquibase 角色、权限、授权范围和历史提单归属迁移。
- Web 与 Android 角色分组、权限范围说明、用户角色授权表单和工单历史展示。
- 租户级岗位模板的查看、创建、复制、修改、停用、删除和授权表单应用。
- 全类型、全状态、全角色、缓存失效和跨租户回归。

## 非目标

- 不允许租户创建任意权限编码、任意范围表达式或显式拒绝规则。
- 岗位模板不成为运行时授权主体，不建立“用户 -> 模板”的隐式继承关系。
- 不修改六状态工单拓扑、SLA 计时规则、租户组织结构和通知收件人身份角色语义。
- 不引入新的外部鉴权服务或策略语言。

## 数据契约

`role_permissions` 继续作为唯一角色权限关联表，新增固定枚举 `scope_profile`。应用将该表映射为 `RolePermissionRule`，不再使用无范围语义的 JPA `ManyToMany`。

范围策略仅允许平台目录中的固定值：

- `GRANT_SCOPE`：使用 `MembershipRoleGrant` 的组织或租户范围。
- `MEMBERSHIP_ORG`：授权必须覆盖用户当前所属组织。
- `REPORTER`：用户是工单提单人。
- `PARTICIPANT`：用户是待接收、当前或曾经接受过派单的处理人。
- `CURRENT_HANDLER`：用户是当前已接受派单的处理人。
- `PENDING_OR_CURRENT_HANDLER`：用户是待接收或当前处理人。
- `CLAIMABLE_OR_PARTICIPANT`：授权组织内可接单工单，或用户与工单存在处理关系。

每个角色权限规则必须存在有效的 `MembershipRoleGrant`。授权缺失或过期一律拒绝，不再回退为租户全域。

## 可自定义岗位模板

- `role_bundles` 保存租户隔离的模板元数据，`role_bundle_roles` 保存模板包含的明确角色集合；两个表的主键均为 UUID。
- 内置模板由平台目录同步，只读、不可删除，但可复制成当前租户的自定义模板。
- 自定义模板允许创建、修改、停用和删除，并受 `role-bundle:manage:*` 原子权限保护。
- 在用户授权表单应用模板时，只把模板角色展开为用户的明确角色及 Grant；系统不保存用户对模板的动态引用。
- 修改、停用或删除模板不会静默改变已授权用户，避免一次模板编辑批量改变生产权限。

## 角色结构

三类工单分别提供 `REPORTER / WORKER / DISPATCHER / VERIFIER / CONTROLLER / AUDITOR` 六个角色。管理员身份角色只用于展示和通知解析，不直接携带 `management:access`；管理入口由实际管理职责角色授予。

宽管理角色按职责迁移：

- 用户管理员拆为资料维护、账号生命周期、密码重置、角色授权。
- 配置管理员拆为系统配置和通知配置。
- 发布管理员拆为安装包发布和存储维护。
- 租户管理员拆为租户创建和租户状态维护。
- 工单审计与仪表盘查看分离。

## 历史工单规则

- 提单角色有效时，可读取本人提交的所有状态工单、流转记录、回单结果和附件。
- 组织变更、派单、调单和闭环不改变提单关系。
- 曾接受派单的处理人可通过 `PARTICIPANT` 查看参与历史，但不能继续执行处理动作。
- `reported_by_user_id` 仅从可靠提交事件回填；无法确定的历史记录进入人工修复清单，不根据联系人姓名或手机号推断。

## 影响文件

- `PermissionCatalog`、内置角色模板、`Role`/`RolePermissionRule`、`UserAuthorizationSnapshot`。
- `WorkOrderAccessPolicy`、`WorkOrderSpecification`、生命周期历史与附件接口。
- Liquibase `018` 迁移及 `db.changelog-master.yaml`。
- Web/Android 角色管理、用户授权和工单详情历史组件。

## 验收标准

- 单类型岗位不能读取或执行其他类型动作；多角色授权按并集生效。
- 一线提单者在工单闭环、取消和组织调整后仍可查看本人历史。
- 处理人调离后只能查看参与历史；待接收人员只能查看目标派单。
- 无 Grant、过期 Grant、错误组织、错误租户和缺失关系均拒绝。
- 市、区县、平台管理员迁移后能力不丢失，身份角色本身不再开放管理入口。
- 内置岗位模板可复制，自定义模板可按租户维护；同名模板和跨租户角色引用被拒绝。
- Web 与 Android 仅根据服务端权限、`allowedViews` 和 `allowedActions` 展示入口。

## 测试方式

- 后端权限目录、角色服务、Liquibase 和工单全生命周期集成测试。
- Web unit/lint/build 与管理端角色、用户授权浏览器 smoke。
- Android unit/typecheck/Doctor/release 构建及模拟器多账号回归。
- 生产候选数据库迁移前后计数、角色映射、缓存失效、API 和 Pod 日志核验。
