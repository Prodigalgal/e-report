# 运行诊断降噪与角色访问边界加固需求

## 目标

- 运行诊断只保留能够帮助定位故障的错误、警告、失败操作和用户主动诊断，不再持续保存成功操作产生的 `INFO` 噪声。
- Android 诊断稳定采集设备厂商和型号；Web 在浏览器允许时尽力采集设备型号，不将浏览器厂商伪装成硬件厂商。
- 管理入口、身份文案和后端访问使用同一权限契约，杜绝普通提单者或处理人员被误显示为管理员、进入管理路由或读取管理接口。
- 将内置角色收敛为单一职责角色，并以 R、W、RW 标明权限性质；市公司和区县管理员通过窄角色组合获得能力。

## 生产事实

- 生产账号 `13000000093`（示例报单员）只有 `ROLE_FRONTLINE_REPORTER` 和 `ROLE_USER`，不存在管理角色或管理授权。
- 该账号被错误识别为管理员，是因为 Web 和 App 将任意工单查看、处理或验收权限都纳入了管理员判定。
- 当前生产诊断数据包含 49 条 `OPERATION / INFO / SUCCESS`，另有 3 条用户主动 `DIAGNOSTIC / INFO / SUCCESS`；前者属于自动采集噪声，后者需要保留。
- Android 原生模块已从 `Build.MANUFACTURER` 和 `Build.MODEL` 读取厂商、型号，服务端和管理页面也已有对应字段。

## 范围

- 后端：新增管理入口和仪表盘查看权限；重组内置角色；迁移现有市公司、区县和平台管理员授权；管理路由增加统一权限闸门；停止接收和生成成功操作事件。
- Web：管理入口只认 `management:access`；管理路由增加相同权限守卫；仪表盘使用独立权限；身份展示以服务端角色中文名为准；运行诊断隐藏历史成功操作噪声并明确显示设备信息。
- Android：与 Web 使用同一管理入口、仪表盘和身份展示契约；保留原生厂商、型号采集；角色管理显示权限访问模式。
- 数据：使用 Liquibase 新增固定权限、窄角色和授权迁移，不删除工单、用户、附件或既有诊断记录。

## 非目标

- 不采集 IMEI、MAC、设备序列号、Android ID、广告 ID 或其他系统/硬件唯一标识。
- 不部署 Prometheus、Grafana、Loki、Sentry 或其他独立观测组件。
- 不改变工单生命周期、数据范围算法、账号唯一性、租户归属或附件契约。
- 不为旧错误判定保留双轨兼容逻辑；前后端在同一生产版本切换到新权限契约。

## 权限模型

权限继续采用 `resource:action` 的最小动作形式，并由固定目录标记为读取或写入：

| 模式 | 含义 | 示例 |
| --- | --- | --- |
| R | 只包含查询、查看或下载动作 | `user:manage:view`、`observability:view` |
| W | 只包含命令动作，适合明确的自动化或组合授权 | `system:config:update` |
| RW | 同时包含读取和命令动作，可直接支撑完整人工岗位流程 | 用户管理员、配置管理员 |
| NONE | 不直接包含业务数据权限的基础或身份角色 | 普通用户 |

内置人工岗位不单独提供不可用的 W-only 大角色。写操作需要上下文读取时，由窄职责 RW 角色提供最小必需读取权限；自定义角色仍按所选原子权限计算 R/W/RW。

## 管理平面契约

- `management:access` 是进入 `/admin/**`、显示管理入口和恢复管理路由的唯一统一闸门。
- `dashboard:statistics:view` 只控制管理仪表盘；它不能替代工单查看权限和组织数据范围。
- 管理端点必须同时满足 `management:access` 和 Controller 声明的具体权限。
- 报单、本人查单、接单和回单属于业务工作台，不授予 `management:access`。
- 工单派调、验收、管控和审计岗位需要管理工作台，因此其内置角色包含 `management:access`；普通工单处理角色不包含。

## 角色组合

| 角色类别 | 访问模式 | 职责边界 |
| --- | --- | --- |
| 普通用户、管理员身份标记 | NONE / R | 登录基础或管理身份，不承载整套业务权限 |
| 一线提单者 | RW | 报单、查看和验收本人提交的工单 |
| 分类工单处理人员 | RW | 单一工单类型的查看、下载、接单、回单和挂起 |
| 工单调度员、验收员、管控员 | RW | 分别承担派调、验收、异常取消，不互相隐式继承 |
| 工单审计员 | R | 工单只读、附件下载和仪表盘，不包含任何状态变更 |
| 用户/角色/组织/配置/时限/发布查看员 | R | 对应模块只读 |
| 用户/角色/组织/配置/时限/发布管理员 | RW | 对应模块读取和维护 |
| 运行诊断查看员 | R | 组织范围内的诊断查询 |
| 租户查看员、租户管理员 | R / RW | 平台级市公司租户查看或维护 |

`ROLE_ADMIN`、`ROLE_COUNTY_ADMIN`、`ROLE_PLATFORM_ADMIN` 只保留管理身份与入口权限。现有管理员账号由迁移自动补齐对应窄角色，并复制原授权的数据范围；区县管理员继续以 `ROLE_COUNTY_ADMIN` 作为通知收件人身份。

## 诊断采集契约

- 服务端拦截器只生成失败写操作，严重度统一为 `WARN`，成功请求只保留在错误事件的客户端面包屑中。
- 批量采集接口忽略 `OPERATION + SUCCESS`，并将失败操作规范化为 `WARN`，防止旧客户端继续写入成功操作噪声。
- 查询端始终排除历史 `OPERATION + INFO + SUCCESS`；现有记录不做破坏性删除，由保留期任务自然清理。
- `DIAGNOSTIC + INFO` 是用户主动诊断，不属于噪声，管理页面显示为“主动诊断”。
- Android 必须上报 `manufacturer`、`deviceModel`；Web 只在 User-Agent Client Hints 返回 `model` 时上报型号，无法取得时留空。

## 迁移与兼容

- Liquibase 先创建固定权限和窄角色，再将管理员身份角色的直接授权及 `membership_role_grants` 数据范围复制到组合角色，最后收窄身份角色权限。
- 迁移对 `user_roles` 和角色授权使用不存在性判断，可重复执行；受影响用户递增 `authorization_version`，使旧令牌立即失效并重新获取权限快照。
- 新版本后端、Web 和 App 必须作为同一生产候选发布；旧 App 不会获得新增管理权限，后端闸门仍是最终边界。
- 回滚以迁移前数据库快照和上一组后端/前端镜像为准；Android 通过更高 `versionCode` 发布回滚版本。

## 验收标准

- 示例报单员登录 Web 和 App 后显示“一线提单者”，不显示管理入口；直达任意管理路由被送回业务首页，调用 `/admin/**` 返回 403。
- 市公司管理员、区县管理员和具有窄管理角色的用户能进入管理后台，但只能看到具体权限允许的菜单和接口。
- 身份切换不沿用上一账号的管理员显示、菜单、缓存统计或路由状态。
- 新上报中不存在成功操作 INFO；历史成功操作 INFO 不再出现在列表；主动诊断仍可查询。
- Android 诊断详情显示真实厂商和型号，且载荷与数据库中没有硬件唯一标识。
- Liquibase 在生产克隆库首跑和二次幂等执行通过；后端、Web、App 自动测试与构建通过；浏览器及 Android 模拟器完成管理员到普通提单者的切换回归。
