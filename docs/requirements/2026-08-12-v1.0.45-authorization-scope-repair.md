# 1.0.45 历史授权范围修复

## 目标

- 修复历史账号迁移将区县用户授权保留为 `TENANT_ALL`，导致区县用户可见全市数据的问题。
- 将配置生成的市公司默认管理员明确同步为租户级授权，使其可以管理和委派市公司范围内的角色。
- 恢复 Web 与 Android 用户详情中的“编辑角色权限”入口，并确保按钮状态来自真实后端授权结果。
- 防止用户导入和岗位模板在非根组织用户上自动生成 `TENANT_ALL`。
- 将漳州市公司本部组织编码从历史占位值 `ROOT` 迁移为行政区划编码 `3506`，运行时只读取 `Tenant.rootOrgUnitId` 显式关系识别根组织。

## 范围

- Liquibase 保存受影响 Grant 的迁移前快照，将现存非根组织用户的 `TENANT_ALL` 收敛为其所属组织的 `ORG_TREE`，并递增授权版本。
- Liquibase 为每个租户显式回填 `root_org_unit_id`，将默认租户根组织编码改为 `3506`，保持组织 UUID、父子关系、路径及业务归属不变。
- 默认管理员初始化使用显式 RoleGrant：`ROLE_USER` 为根组织 `ORG`，其余管理职责为 `TENANT_ALL`。
- Web、Android 和 Excel 用户导入按目标用户所属组织决定市公司/平台岗位模板的默认数据范围；只有根组织用户自动使用 `TENANT_ALL`。
- 新租户直接从固定 `PermissionCatalog + BuiltInRoleCatalog` 创建内置角色，不复制默认租户数据库中的可变角色状态。
- 后端、Web、Android 增加授权范围、模板和用户详情可编辑性的回归测试。

## 非目标

- 不把 `ORG_TREE(ROOT)` 和 `TENANT_ALL` 在运行时合并为同一种范围。
- 不通过组织编码、名称、类型或 `parent_id IS NULL` 推断根组织。
- 不禁止市公司管理员显式向非根组织用户授予 `TENANT_ALL`；显式跨区县授权仍由再授权上限校验。
- 不修改工单生命周期、业务状态、SLA 或现有角色权限集合。

## 验收标准

- 市公司 `admin` 的非基础角色全部为 `TENANT_ALL`，可查看并修改其授权上限以内的用户 RoleGrant。
- 市公司本部编码为 `3506`；修改编码后组织 UUID、层级和历史工单归属不变。
- 示例管理员乙及所有同类历史异常账号不再持有迁移遗留的 `TENANT_ALL`，工单和管理数据仅覆盖所属区县组织树。
- 区县管理员无法查看、选择或提交超过自身权限/数据范围的角色。
- Web 与 Android 用户详情对有授权能力的市公司管理员展示“编辑角色权限”按钮；只读用户仍不展示。
- 非根组织用户套用市公司管理员岗位模板或通过 Excel 导入时，默认生成所属组织 `ORG_TREE`，不静默生成全市范围。
- 迁移前快照可精确恢复原 Grant；数据库备份、构建、自动化、浏览器、模拟器和生产 smoke 全部通过。

## 测试方式

- 后端集成测试覆盖默认管理员、历史范围规整、导入模板和授权委派边界。
- Web unit/lint/build，Android unit/typecheck/Doctor/release build。
- 浏览器验证 admin 用户详情按钮、角色保存回读和区县账号数据隔离。
- Android 模拟器验证相同角色入口与账号切换后的权限刷新。
- 生产部署前备份 MySQL；部署后核对 Liquibase、Grant 分布、授权缓存、Pod、API、APK 更新和 R2 Range/SHA。
