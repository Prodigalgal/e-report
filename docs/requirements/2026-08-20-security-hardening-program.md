# 全系统安全加固专案

## 目标

在账号密码、客户端或单个工作负载失陷的前提下，将攻击者限制在最小业务与运行边界内，阻止同级账号接管、跨组织扩散、长期凭据驻留、敏感配置外泄以及由应用容器向数据库、缓存、集群和宿主机横向移动。

## 范围

- 身份认证、密码、验证码、会话、设备信任、API Token 与高危操作二次认证。
- 原子权限、岗位模板、授权委派上限、同级管理员保护、租户和组织数据面。
- WEB、APP、文件上传、用户导入导出、通知渠道、运行诊断和外部 HTTP/SMTP 调用。
- Kubernetes、MySQL、Redis、R2、Secret、备份、SSH、网络边界和测试命名空间。
- 依赖锁定、SBOM、SCA、密钥扫描、容器扫描、CI/CD、制品签名与部署溯源。

## 本轮边界

- 先完成只读审计和证据化报告，不修改生产配置或生产数据。
- 本轮实现 API Token 显式原子权限、敏感配置 write-only，以及密码变更后的统一凭据撤销。
- 不构建发布包、不部署测试或生产环境；其他整改进入后续分批交付。

## 验收标准

- 审计报告按严重度给出证据、可利用前提、影响范围、现有防线和整改顺序。
- API Token 的查看、创建和撤销均有独立权限门槛；未授权账号不展示入口，直接调用返回 403。
- API Token 管理岗位可由有委派能力的管理员授予，区县和市公司默认管理员岗位包含该能力。
- Token 可选业务权限仍不得超过创建者当前有效权限、范围、关系和有效期，API Token 不能创建其他 Token。
- 所有通用配置查询接口对敏感项只返回 `configured` 状态和固定掩码，不返回原值，也不能按原值搜索。
- 修改本人密码和管理员重置密码均撤销全部活动会话、全部未撤销 API Token，并撤销既有设备信任；同一 APP 安装必须使用新密码认证后才能恢复设备信任。
- Liquibase 迁移、后端测试、WEB 测试/构建、APP 测试/类型检查和版本契约校验通过。
