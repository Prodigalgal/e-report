# 工单查询多选与全环节 SLA 详细设计

> 日期：2026-08-08
> 等级：S3（查询契约、生命周期计时、Liquibase、Web、Android 与生产迁移）

## 目标

- 工单查询的工作队列、工单类型、处理状态均支持多选；维度内取并集，维度间取交集。
- SLA 覆盖工单从提交到闭环的每个可停留环节，管理员可按市租户、工单类型和优先级分别配置。
- 调单、拒绝派单、验收驳回和挂起恢复不会无声丢失或重置原处理时限。

## 范围与非目标

- 范围：`/work-orders/search` 重复参数、三端筛选状态、SLA 策略字段、阶段切换、超时事件、Liquibase 和策略管理页面。
- 非目标：不新增工单主状态，不用 SLA 超时自动改变工单状态，不改变角色权限、数据范围、分页排序和通知渠道。

## 查询契约

- API 参数名保持 `queue`、`reportType`、`status`，客户端通过重复参数传递多值，例如 `status=SUBMITTED&status=ON_HOLD`。
- 单值旧链接仍自然绑定为单元素集合；空集合或 `all` 表示不限制该维度。
- 同一维度使用 SQL `OR/IN`，三个维度以及关键词、组织范围之间使用 `AND`。
- Web URL 使用重复参数，Android API 使用同名重复参数；刷新、分页和分享链接保持筛选集合。

## SLA 阶段

| 阶段 | 起点 | 终点 | 策略字段 |
| --- | --- | --- | --- |
| `CLAIM` 待接单/待派单 | 工单提交、初次派单被拒绝 | 主动接单或发起派单 | `claimMinutes` |
| `ASSIGNMENT_ACCEPTANCE` 待接收派单 | 生成待接收派单 | 接受、拒绝、撤销或回单 | `assignmentAcceptanceMinutes` |
| `RESPONSE` 处理回单 | 首次接单或首次接受派单 | 提交回单 | `responseMinutes` |
| `VERIFICATION` 验收闭环 | 提交回单 | 验收通过或驳回 | `verificationMinutes` |
| `REWORK` 驳回整改 | 验收驳回 | 再次提交回单 | `reworkMinutes` |
| `COMPLETED` 已结束 | 验收通过或取消 | 无 | 不计时 |

挂起不新增平行主时钟：当前活动阶段暂停，并继续使用 `pauseOnHold`、`maxSingleHoldMinutes`、`maxTotalHoldMinutes` 约束单次和累计挂起时长。超过允许暂停量的时间继续消耗当前阶段 SLA。

## 默认策略

迁移不会改变现网已配置值；新增阶段复制语义最接近的现有时限。新建租户的默认值如下：

| 优先级 | 待接单/派单 | 派单接收 | 首次处理 | 验收 | 驳回整改 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 紧急 `URGENT` | 30 分钟 | 30 分钟 | 240 分钟 | 120 分钟 | 240 分钟 |
| 高 `HIGH` | 60 分钟 | 60 分钟 | 480 分钟 | 240 分钟 | 480 分钟 |
| 普通 `NORMAL` | 240 分钟 | 240 分钟 | 2880 分钟 | 960 分钟 | 2880 分钟 |
| 低 `LOW` | 480 分钟 | 480 分钟 | 5760 分钟 | 2880 分钟 | 5760 分钟 |

- 默认允许挂起暂停计时，单次最多 2880 分钟（48 小时），全流程累计最多 8640 分钟（144 小时）。
- 截止时间公式为“阶段进入时间 + 该阶段策略分钟数”；挂起恢复时只顺延策略允许的暂停秒数。
- 到期扫描只写入带阶段元数据的 `SLA_BREACHED` 事件、设置当前/历史超时标记并触发通知，不自动接单、调单、驳回、关闭或取消工单。
- 进入下一个阶段会开启新阶段时钟；`slaEverBreached` 始终保留此前任一阶段发生过超时的事实。

## 调单与恢复规则

- 首次派单进入 `ASSIGNMENT_ACCEPTANCE`；接受后进入 `RESPONSE`，拒绝后恢复原 `CLAIM` 截止时间，避免通过反复派单刷新接单时限。
- 待接单、处理中或整改中产生待接收派单时，暂存原 `sla_stage`、`sla_due_at` 和原阶段超时标记，派单接收阶段独立计时。
- 调单接受后恢复原处理/整改截止时间并更换责任人；调单拒绝或撤销后同样恢复原截止时间，不额外奖励处理时长。
- 管理员即时调单不重置处理/整改截止时间；仅从尚未开始处理的提交态调单时启动新的处理阶段。
- 验收驳回从驳回时间启动 `REWORK`；若同时指定新人员，则暂存整改截止时间并进入派单接收阶段。
- 每次阶段切换前先结算当前阶段是否超时；每个阶段至多写入一次 `SLA_BREACHED`，`slaEverBreached` 保留全流程事实。

## 数据迁移

- `work_order_sla_policies` 新增 `assignment_acceptance_minutes`、`rework_minutes`，分别从现有接单和处理时限复制，保证升级不收紧现网标准。
- `fault_reports` 新增 `sla_resume_stage`、`sla_resume_due_at`、`sla_resume_breached_at`，仅在待接收派单期间保存被中断阶段及其超时事实。
- 存量待接收派单按 `assigned_at + assignment_acceptance_minutes` 初始化；存量验收驳回工单把 `RESPONSE` 标记细化为 `REWORK`，截止时间保持不变。
- 迁移只通过 Liquibase 执行；上线前必须做生产克隆库首跑、二次幂等和候选启动验证。

## 验收标准

- 三个筛选条件可分别选择多个值，Web 与 Android 请求和结果一致。
- 提交、派单、接受、拒绝、接单、回单、验收驳回、再次回单、挂起、恢复、调单和闭环均得到正确阶段与截止时间。
- 处理中调单接受/拒绝不重置原处理截止时间；验收驳回使用独立整改时限。
- 存量策略与工单迁移后无空时限、未知阶段或重复超时事件。
- 后端全量测试、Web test/lint/build、App test/typecheck/Doctor/release build及模拟器流程全部通过后才能发布。
