# 5.1.x 用户操作与定位轨迹埋点

## 目标

- 在不阻塞业务交互的前提下，为 WEB、Android 和服务端关键写操作建立可关联的操作轨迹。
- 优先解决“用户反馈定位失败但后台无法还原权限、系统定位服务、供应器切换和耗时”的排障盲区。
- 将正常操作轨迹与错误/警告诊断分开展示，避免成功 `INFO` 重新污染默认“运行诊断”列表。

## 范围

- 复用现有 `client_observation_events`、Redis 缓冲、批量入库、组织数据域和 `observability:view` 权限。
- 客户端增加非阻塞操作事件与轻量操作 span；失败必采，正常操作按策略采样，高价值定位链路强制留痕。
- Android 定位记录权限结果、系统定位总开关、可用供应器、各阶段耗时、最终供应器、精度、回退原因和地址解析结果。
- WEB 定位记录浏览器能力、权限状态、结果码、耗时和精度。
- 服务端记录所有关键写接口的成功/失败、HTTP 状态、耗时、路由和请求编号，不记录请求正文。
- 管理端增加“故障诊断 / 操作轨迹”视图；操作轨迹可按时间、平台、功能、用户和关键词查询。
- 正常操作轨迹使用独立保留期，默认 14 天；错误、警告和主动诊断继续默认保留 30 天。
- 观测事件按租户上下文分组落库，PostgreSQL 对观测表启用强制 RLS，并增加行为视图复合索引。

## 非目标

- 不接入 Prometheus、Grafana、Sentry、PostHog 等重量级外部平台。
- 不采集原始经纬度、详细地址、密码、Token、手机号、邮箱、IMEI、MAC、Android ID 或设备序列号。
- 不将埋点作为业务成功条件，不因入队、SQLite、Redis、网络或入库失败阻断用户操作。
- 不在本版本构建统计画像、用户评分、广告分析或跨租户汇总。

## 关键契约

- `eventType=OPERATION`：用户行为/关键写操作；成功为 `INFO/SUCCESS`，失败为 `WARN/FAILURE`。
- `traceId`：关联客户端操作、API 请求、错误事件和定位阶段；不得承载账号或业务数据。
- 客户端队列：Android SQLite WAL 最多 500 条，WEB 本地队列最多 200 条；高严重度优先保留。
- 批量发送：默认 20 条/批、15 秒刷新；断网保留，恢复网络后重试；服务端按 `clientEventId` 幂等。
- 正常操作采样率由 `observability.client.operation-success-sample-rate-percent` 控制，默认 20%；定位等明确标记的高价值操作不采样。
- 正常操作保留期由 `observability.operation-retention-days` 控制，默认 14 天。

## 影响文件

- Backend：观测策略、入站过滤、按租户落库、操作记录器、查询模式、保留任务、管理查询 API、Liquibase 迁移与测试。
- WEB：遥测操作 span、路由行为、浏览器定位、运行诊断双视图与用户筛选。
- APP：遥测操作 span、路由行为、Android 定位阶段、运行诊断双视图与测试。
- 版本：首个测试候选为 `5.1.0 / 4001000`；闭环验收发现逆地理编码结果字段被隐私规则误脱敏后升级为 `5.1.1`，随后在模拟器关闭定位总开关的失败测试中发现前置检查失败未携带结构化设备诊断，最终修复候选升级为 `5.1.2 / 4001002 / android-5.1.2-native4001002`。各候选制品均不可覆盖。

## 验收标准

- 关闭 Redis、断网或模拟入队失败时，定位、报单、工单处理和管理操作仍按原逻辑完成或返回原业务错误。
- 定位失败事件可看到权限、定位总开关、GPS/网络供应器、逐阶段耗时、设备厂商/型号和错误码，且上下文不含坐标或地址。
- 定位成功只生成一条强制留存的完成轨迹，不为每个阶段单独写数据库。
- 默认“故障诊断”不显示正常操作；“操作轨迹”显示成功与失败操作，并能按用户筛选。
- 服务端成功写操作异步记录，不延长业务事务，不存请求正文。
- 本地测试、构建、数据库迁移、测试命名空间运行态和 Android 模拟器全部通过；生产环境保持不变，等待用户终验。
