# 1.0.40 只读用户详情与安装包发布策略

## 目标

- 用户详情页始终以只读方式展示资料、账号状态、角色范围和个人工单绩效，降低误改风险。
- 个人资料、账号状态、角色权限和密码重置分别通过独立弹窗操作，按字段权限显示入口并独立提交。
- 安装包发布中心允许授权人员修改已发布版本的强制更新策略、最低支持构建号和更新说明，不再直接操作数据库。
- Android 版本统一升级为 `1.0.40` / code40 / `android-1.0.40-native40`。

## 范围

- Backend：发布策略 DTO、业务服务、权限、API、R2 概览投影、Liquibase 021 和自动测试。
- Web：用户详情只读化及四类编辑 Dialog；发布中心展示并编辑版本策略。
- Android：用户详情只读化及四类编辑 Modal；发布中心策略编辑；版本契约与正式 APK。
- 生产：MySQL 克隆演练、Liquibase Job、镜像部署、R2 发布、浏览器和模拟器回归。

## 非目标

- 不允许修改已发布版本的 `platform`、`channel`、`versionCode`、`versionName`、`runtimeVersion`、APK 文件或 SHA-256。
- 不增加发布记录软删除、重新排序、灰度比例、设备名单或多安装包能力。
- 不改变用户详情 API 的字段级授权模型，不合并个人资料、状态和角色权限的弹窗保存。
- 不保留旧页面的内联编辑模式。

## API 与权限契约

新增 `PATCH /admin/app-updates/{releaseId}/policy`，请求字段为：

- `forceUpdate`：必填布尔值。
- `minSupportedVersionCode`：必填非负整数，且不能大于该发布版本的 `versionCode`。
- `releaseNotes`：可空，去除首尾空白后最长 2000 字符。

接口返回完整 `AppReleaseDTO`。不存在的发布记录返回 404，非法策略返回 400，无 `app-update:policy-update` 权限返回 403。策略修改只更新数据库元数据，不重复上传 APK、不刷新 R2 对象。

新增窄角色 `ROLE_RELEASE_POLICY_MANAGER`，仅包含管理入口、安装包查看和发布策略修改权限。现有 `ROLE_RELEASE_PUBLISHER` 用户在 Liquibase 021 中复制一份相同数据范围的策略管理员 Grant；区县管理员默认不获得该角色。

## 交互契约

- 用户详情主页面没有 TextField、Select 或角色勾选控件，只展示最终服务端数据。
- “编辑个人信息”弹窗只提交 `details`；“调整账号状态”只提交 `status`；“编辑角色权限”只提交 `roleGrants`；“重置密码”使用独立接口。
- 弹窗打开时从当前详情创建草稿；取消不写入、不污染主页面；成功后关闭弹窗并刷新详情；失败时保留草稿和明确错误。
- 角色弹窗继续支持按名称、编码和职责搜索；隐藏的已选角色不得因搜索或保存被移除。
- 发布策略弹窗显示不可变版本身份和策略影响说明，提交期间防重复操作，成功后重新读取服务端状态。

## 验收标准

- 只有相应权限的用户能看到对应编辑按钮，只有查看权限的用户仍可完整浏览详情和发布记录。
- 四类用户操作互不夹带字段，任一失败不会改变其他资料。
- 发布策略 API 对成功、无权限、记录不存在、最低构建号越界和文本超长均有测试。
- Web 桌面与窄屏、Android 模拟器均验证只读页面、弹窗打开/取消、角色搜索和发布策略显示。
- Backend/Web/App 自动测试、lint/typecheck、构建、版本契约、APK 签名、R2 Range/SHA 和生产只读 smoke 全部通过。

## 回滚

- 应用可回滚到 1.0.39 镜像；新增权限和角色保留不会影响旧应用。
- 若回滚 Liquibase 021，应先撤销新角色 Grant、`user_roles`、角色权限、角色和权限目录，再清理授权缓存。
- code40 一旦发布不得复用或降级；后续修复使用更高且继续对齐的 versionCode。
