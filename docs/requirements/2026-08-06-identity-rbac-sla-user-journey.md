# 账号、岗位权限、组织归属与故障 SLA 增强

> 状态：已完成并于 2026-08-07 投产  
> 级别：S3 生产数据迁移与三端联动

## 目标

- 登录只填写全系统唯一的用户名、密码和验证码，由服务端从账号反查市公司租户与组织。
- 用岗位职责而不是页面入口组织权限，拆开报单验收、处理、派调、验收、监督及各管理职能。
- 新工单固定归属报单人当前组织；历史普通用户和历史工单统一归属南靖县。
- 建立可配置、可暂停、可追踪的故障 SLA，并在管理仪表盘呈现故障历时和超时结构。
- Web 与 Android 使用相同工单详情入口和 SLA 契约；报单时用一次操作完成定位与地址解析。

## 用户与主要旅程

| 用户 | 首页和入口 | 核心旅程 | 不应看到或执行 |
| --- | --- | --- | --- |
| 一线提单者 | 我要报单、工单查询 | 定位并填写地址 -> 提交 -> 查看详情 -> 验收本人报单 | 处理自己的工单、查看其他组织工单 |
| 类型处理人员 | 工单查询 | 查看详情 -> 主动接单或接受派单 -> 回单 | 派调、验收自己的回单、用户管理 |
| 工单调度员 | 工单查询、仪表盘 | 查看详情 -> 选择合格人员派单/调单 | 验收、配置或账号管理 |
| 工单验收员 | 工单查询、仪表盘 | 查看详情和回单历史 -> 通过或驳回 | 默认派调和账号管理 |
| 区县管理员 | 管理后台 | 管理本区县工单、人员、授权和组织配置，查看全市 SLA 标准 | 兄弟区县数据、全市 SLA 修改、市租户生命周期、安装包发布 |
| 市公司管理员 | 管理后台 | 管理全市业务和租户内管理能力 | 其他市租户业务数据 |
| 平台管理员 | 市公司租户 | 创建或启停市租户 | 默认读取市租户工单明细 |

所有工单列表项只进入工单详情。回单、派单、验收、挂起等动作统一由详情页的服务端 `allowedActions` 驱动。

## 范围

- Backend：认证、全局唯一用户名、用户/工单组织归属、固定权限目录、内置角色、SLA 策略与计时、超时事件、统计接口。
- Database：仅使用 Liquibase 增量迁移，包含约束替换、南靖县归属回填、角色兼容迁移、SLA 表和工单 SLA 快照字段。
- Web：移除登录租户输入，调整管理入口与角色展示，增加 SLA 策略页、仪表盘历时指标、详情 SLA 信息，简化报单定位。
- Android：同步认证、角色与 SLA 契约；搜索和最近工单统一进入详情；报单合并定位与解析；候选 APK 在已连接真机覆盖安装并走用户旅程。

## 非目标

- 逆地址服务仍可返回行政区解析信息，但工单不再保存乡镇/街道和社区/行政村两个独立属性。
- 不跨市调单，不引入 BPMN，不修改六状态主状态机拓扑。
- 不实现省级跨租户 SLA 聚合，也不在 SLA 超时时自动改变工单主状态。

## 权限与角色决策

固定动作权限仍按 `work-order:{type}:{action}` 管理。管理权限按读取和写入职责拆分，不再使用一个 `*:manage:all` 承载所有端点。

内置岗位角色：

- 基础与业务：`ROLE_USER`、`ROLE_FRONTLINE_REPORTER`、三个类型处理角色。
- 工单职责：`ROLE_WORK_ORDER_DISPATCHER`、`ROLE_WORK_ORDER_VERIFIER`、`ROLE_WORK_ORDER_CONTROLLER`、`ROLE_WORK_ORDER_AUDITOR`。
- 管理职责：`ROLE_USER_MANAGER`、`ROLE_ROLE_MANAGER`、`ROLE_ORG_MANAGER`、`ROLE_CONFIG_MANAGER`、`ROLE_SLA_MANAGER`、`ROLE_RELEASE_MANAGER`。
- 综合岗位：`ROLE_COUNTY_ADMIN`、`ROLE_ADMIN`、`ROLE_PLATFORM_ADMIN`。

一次性迁移：

- `ROLE_WORK_ORDER_RESPONDER` 的用户和数据范围授权复制到三个类型处理角色后退休。
- `ROLE_WORK_ORDER_SUPERVISOR` 拆为调度、验收和工单控制三个岗位角色，保持原数据范围后退休。
- 旧的 `role:manage:all`、`organization:manage:all`、`app-update:manage`、`tenant:manage:all` 在 Liquibase 中映射到对应细分权限后删除，不保留运行时双权限判断。
- 旧的 `work-order:close` 映射到三类工单验收权限后删除，旧关闭端点随本版本移除。
- 内置角色由系统维护且前端只读；租户管理员通过自定义角色组合固定权限。

## SLA 契约

策略键为 `tenant_id + report_type + priority`，优先级为 `URGENT / HIGH / NORMAL / LOW`。首版默认值可在管理后台修改：

| 优先级 | 首次接单 | 处理回单 | 验收闭环 |
| --- | ---: | ---: | ---: |
| 紧急 `URGENT` | 15 分钟 | 120 分钟 | 60 分钟 |
| 高 `HIGH` | 30 分钟 | 240 分钟 | 120 分钟 |
| 普通 `NORMAL` | 120 分钟 | 1440 分钟 | 480 分钟 |
| 低 `LOW` | 240 分钟 | 2880 分钟 | 1440 分钟 |

- 默认挂起暂停 SLA；单次最多暂停 24 小时，累计最多暂停 72 小时。
- 调单不重置处理截止时间；验收驳回从驳回时启动新一轮处理 SLA。
- 当前阶段和截止时间写入工单快照；策略修改只影响新进入该阶段的计时，不追溯改写历史事件。
- 超时只写一次 `SLA_BREACHED` 事件并通过 Outbox 触发隔离后的通知通道，不自动变更主状态。
- 详情和列表返回当前 SLA 阶段、截止时间、是否超时、超时秒数和工单总历时。

仪表盘至少返回：活动工单数、24 小时内、24-48 小时、48-72 小时、超过 72 小时、当前 SLA 超时数、曾发生 SLA 超时数和最长未闭环故障历时。

## 数据迁移

- 迁移前检查全系统重复用户名；存在重复时 changeset 失败，禁止带歧义切换登录契约。
- 将 `(tenant_id, username)` 唯一约束替换为 `username` 全局唯一约束。
- 登录请求删除 `tenantCode`；服务端、Web 和 APP 只使用全局用户名，租户信息只出现在登录响应和已认证上下文。
- 漳州市默认租户中，保留市公司 `admin` 和 11 个区县默认管理员的既有组织；其他历史用户迁入南靖县组织。
- 所有迁移前既有工单的 `reporting_org_id`、`responsible_org_id` 迁入南靖县；迁移后新工单按报单人当前组织创建。
- 历史工单以 `NORMAL` 初始化 SLA；当前阶段根据状态推导，终态不再启动计时。
- 删除 `fault_reports.township` 和 `fault_reports.village_or_street`；该清理已明确允许丢弃历史字段值，数据恢复只能依赖迁移前备份。
- 生产迁移前停止写入并生成新备份，迁移后核对用户、工单、附件、回单、授权和事件总数。

## 验收标准

- 相同用户名不能在不同租户再次创建；登录请求不含租户也能返回正确 `tenantId/tenantName/orgUnitId`。
- 历史普通用户与历史工单均归属南靖县，11 个区县管理员仍归属各自区县。
- 新工单的上报和责任组织等于报单人组织；修改用户组织不追溯改写已创建工单。
- 角色列表没有通用处理人/工单主管重复项，内置角色只读，细分岗位可独立授权且页面入口与端点权限一致。
- 各 SLA 阶段正确启动、暂停、恢复、驳回重启和闭环；并发扫描不重复产生超时事件。
- Web 与 APP 的搜索、最近工单点击均进入详情；只有详情动作进入回单。
- 报单界面不再显示乡镇/街道和社区/行政村，定位并解析地址为单一按钮；解析失败时保留 GPS 并允许手填地点。
- Web 桌面/窄屏五类用户旅程无越权、死路或入口不一致；Android 真机升级安装后可登录、查询详情、进入回单、报单定位和查看 SLA。

## 测试方式

- Backend：完整 Gradle test、Liquibase MySQL/H2 migration、bootJar，覆盖认证、全局唯一、角色迁移、组织范围、SLA 生命周期和统计边界。
- Web：unit、lint、build；Playwright 桌面和移动视口按五类用户执行真实链路。
- Android：unit、typecheck、Expo Doctor、release APK；ADB 覆盖安装到当前真机，使用 UI tree、截图和 logcat 验证。
- Production：备份校验、Liquibase Job、滚动部署、Pod/日志/API/浏览器/真机 smoke、APK HEAD/Range/SHA 与更新检查。

本版本部署后将新 Android 版本设为最低支持版本，避免旧客户端继续依赖已删除的登录、聚合管理权限或关闭端点。
