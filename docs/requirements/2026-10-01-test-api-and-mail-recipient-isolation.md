# 测试/生产 API 选择与邮件通知验收

## 目标

同一不可变 Android APK 可在登录前选择测试或生产 API；测试环境的工单邮件只投递给 SuperAdmin，并以真实工单调单完成链路验收。

## 范围

- APP：提供明确的测试/生产环境选择；默认生产环境；持久化选择；切换时清除登录凭据与查询缓存，并按环境隔离本地遥测队列，避免跨环境复用身份、数据和诊断事件。
- Backend：增加可选邮件收件人用户 ID 过滤配置；测试环境只放行 SuperAdmin，未配置时保持既有权限解析行为；过滤覆盖普通工单及调单接收邮件。
- GitOps/CI：测试环境注入收件过滤；测试发布中心使用隔离对象前缀；同一 APK 先登记到测试发布中心，不自动提升生产。
- 测试：启用测试邮件通道并配置已验证发件方，创建测试工单并调单给 SuperAdmin，确认唯一收件人及 SMTP 接受结果。

## 非目标

- 不修改生产环境配置或发送生产邮件。
- 不改写管理员的系统基线授权；通过测试环境邮件收件过滤实现隔离。
- 不将 SMTP 凭据提交到源码或 GitOps 明文文件；使用测试站受控设置或既有 secret 管理。

## 影响范围

`e-report-app` 环境路由、登录界面、API/遥测地址；`e-report-backen` 邮件收件解析；测试环境 `e-report-config` Backend/发布中心配置；Android 构建及发布流水线；版本契约与发布说明。

## 验收标准

1. 6.3.0 APK 默认连接生产；用户可在登录前切换测试/生产，切换会清除本机会话，API、下载链接和遥测随环境一致切换；测试遥测不发送到生产。
2. Backend 未配置收件过滤时行为不变；测试环境配置后，普通邮件和调单邮件均只向 SuperAdmin 解析收件人。
3. GitHub Actions 构建的同一 APK hash 被测试下载中心登记，生产晋级 job 保持跳过。
4. 测试环境真实调单触发邮件；后端日志显示一位目标收件人、SMTP 返回接受；用户检查邮箱确认到达。
5. 生产运行版本与配置不变；所有相关测试、版本契约、Backend/WEB/APP 构建通过。

## 验证方式

模块单元测试、APP test/typecheck/version-contract/build、Backend notification tests 与完整构建、WEB build、GitHub Actions 构建产物核验、测试站 release/API smoke、一次真实测试工单调单及 SMTP/收件箱确认。

## 回滚

删除测试环境的收件过滤配置并关闭测试邮件通道；测试 APK 发布中心条目可撤回/停发；源码回退使用前一不可变镜像，APP 修复用更高 versionCode 发布。生产未参与本次操作。
