# 1.0.47 用户批量治理 V2 ExecPlan

## 目标

把用户批量导入导出从同步 V1 深度迁移为任务化 V2：一份多 Sheet 工作簿分别表达账号资料和逐条角色 Grant，支持可自定义岗位授权规则、预览快照、执行一致性、分页结果、逐 Grant 导出、权限与数据域上限校验。

## 范围

- Liquibase 新增岗位授权规则、用户传输任务、任务行和预览快照数据。
- 统一工作簿包含 `填写说明`、`用户资料`、`授权调整`、`岗位模板`、`岗位模板明细`、`角色目录`、`组织目录` 和隐藏 `模板元数据`。
- 支持 `CREATE`、`UPDATE`、`ORG_MOVE` 用户动作与 `ADD`、`REMOVE` 授权动作。
- 岗位模板在预览时展开为具体角色、数据范围、组织锚点和有效期。
- 预览与执行通过输入 SHA-256、目录摘要、用户 `authorizationVersion` 和短期签名令牌绑定。
- WEB 使用任务化四步流程；导出拆为用户清单和角色授权两张事实表。
- 候选环境完成权限、并发、文件安全、Excel 和浏览器验收后，才允许生产迁移。

## 非目标

- APP 不新增 Excel 导入导出入口。
- 不在本阶段直接部署生产或修改生产数据。
- 不允许模板创建租户、组织、角色或权限。
- 不通过普通资料更新修改手机号或登录账号。

## 迁移约束

1. 所有新增主键使用 UUIDv7。
2. 新表旁路现有用户事实，候选失败可通过关闭 V2 和回退镜像恢复。
3. `CUSTOM_ORGS` 先迁移为等价 `ORG`；代码和客户端随后删除该枚举。
4. `membership_role_grants` 成为最终角色事实前，必须校验并修复 `user_roles` 差异；禁止未经验证直接删除关系表。
5. 岗位规则迁移完成后删除 `RoleGrantScopeDefaults`，不保留运行时推断兼容层。
6. V2 WEB 切换后删除 V1 Controller、DTO、同步解析器和旧页面流程，不长期双写。

## 验收标准

- 创建账号不填写授权时不产生角色；资料更新不填写授权时原 Grant 完全不变。
- `ADD/REMOVE` 精确修改可见 Grant，隐藏 Grant 保留且不泄露详情。
- 每条授权的数据范围、锚点组织和有效期均不超过操作者上限。
- 目标用户只要存在一条超出操作者可委派包络的有效授权，即禁止其通过单用户或批量入口修改资料、组织、状态、密码、会话和授权；允许在数据可见范围内只读查看基础资料，但不得泄露越权 Grant 详情。
- 预览后用户、岗位、角色、组织或操作者授权变化时执行返回 `STALE`。
- 相同幂等键重复提交返回原任务，不同请求体返回冲突。
- 10、500、5,000、20,000 行场景不阻塞 HTTP 请求线程，任务进度可恢复。
- 中文文件名、Office/WPS/LibreOffice、下拉、批注、隐藏元数据、HEAD/Range/SHA-256 全部通过。
- WEB、Backend 测试和构建通过；测试命名空间 Liquibase 幂等、真实浏览器流程和日志检查通过。

- WEB：Node 测试、ESLint、Vite build、Playwright 管理员流程。
- 表格：Apache POI 结构校验、工作区表格工具逐 Sheet 渲染、Microsoft Excel COM 打开验证。
- 运行态：测试命名空间 Pod/Job/Redis/日志、API smoke、任务重启恢复与文件 Range 下载。

## 回滚

- 关闭 `app.user-transfer.v2-enabled` 并回退 Backend/Frontend 镜像。
- V2 任务表和岗位授权规则表在候选阶段属于旁路数据，可保留审计或按 Liquibase rollback 删除。
- 已执行的用户/Grant 变更必须使用批次 before/after diff 补偿，不能靠删除任务记录回滚。
- `user_roles` 删除和 Grant 单事实源切换只在最终迁移步骤执行，执行前保留完整数据库备份和一致性报告。
