# 1.0.43 用户批量导入与角色授权收敛

## 目标

- 将 11 个漳州区县默认管理员密码统一为“区县首字母小写 + `@` + 区县邮编”，账号继续使用区县全拼小写。
- Web 管理后台支持下载用户导入模板、预校验并按手机号批量新增或更新用户；Android 不提供导入入口。
- Web/Android 用户列表支持按所属组织、账号状态和角色筛选，角色最多展示三个，其余以数量汇总。
- 角色、岗位模板、权限目录和用户授权响应只暴露当前操作者实际可授予的内容，服务端拒绝越权构造请求。
- 权限动作、关系策略、组织范围和有效期共同构成再授权上限；任一维度不得超过授予者当前有效授权。
- 深度退役 `ROLE_ADMIN`、`ROLE_COUNTY_ADMIN`、`ROLE_PLATFORM_ADMIN` 三个无权限身份角色，不保留运行时兼容层。

## 导入契约

- Excel 第一张表为“用户导入”，字段为：手机号、姓名、所属组织编码、岗位模板、登录账号、初始密码、邮箱、账号状态。
- 手机号是全局唯一更新键；手机号和邮箱都全局唯一。数据库允许历史空手机号、空邮箱，但非空值不得重复，邮箱统一按小写保存和比较。
- 新用户登录账号留空时使用手机号；初始密码仅新用户必填，更新既有用户时不重置密码、不修改登录账号。
- 岗位模板按租户内唯一中文名称解析，只允许选择当前操作者可见且启用的模板；模板展开为明确角色，后续修改模板不追溯用户。
- 一行只选择一个岗位模板。需要组合职责时，管理员先在角色管理中创建自定义岗位模板，再用于导入。
- 预校验返回新增数、更新数、无变化数和逐行错误；存在任一错误时禁止执行。执行阶段重新解析和校验，同一文件全部成功或全部回滚。
- 单次最多 500 行、仅接受 `.xlsx`，文件大小上限 5 MiB；空行忽略，重复手机号、重复新增账号、未知组织或模板均报错。

## 角色与数据范围

- 不新增宽泛“用户导入管理员”角色。导入执行要求同时具备用户创建、资料修改、状态修改和角色分配四项现有权限。
- 角色可见性以“目标角色的权限名称与作用范围策略是否均被操作者有效授权覆盖”为准；权限目录、自定义角色和岗位模板采用同一规则。
- 区县管理员只能在自身授权组织树内导入、筛选和授权；市公司管理员可以使用全市范围。
- 角色 Grant 同时受目标角色每一项权限、`user:manage:assign_roles`、组织覆盖范围和到期时间约束；多个区县 Grant 不能等价为 `TENANT_ALL`。
- 修改已被使用的自定义角色时，必须以新策略重新校验现存 Grant，禁止通过修改角色定义间接扩大既有用户的数据视野。
- 权限与角色 API 返回服务端计算的可授予范围，Web/Android 不复制权限强弱矩阵。
- 内置“市公司管理员标准岗位”“区县管理员标准岗位”“平台租户管理员标准岗位”只组合真实职责角色。
- 新增“市公司通知收件人”“区县通知收件人”窄角色及对应权限，用于通知路由，替代空身份角色。

## 用户筛选与列表

- `GET /admin/users` 新增 `orgUnitId`、`status`、`roleName` 条件，并继续受租户和组织范围约束。
- Web 与 Android 使用紧凑选择控件；角色选项可搜索，所有筛选变更回到第一页。
- 用户卡片或表格只显示前三个可见角色，超出部分显示“另有 N 个”；详情页保留完整的可见角色授权。

## 非目标

- Android 不下载、选择或上传 Excel。
- 导入不修改既有用户登录账号，不重置既有用户密码，不创建组织或岗位模板。
- 不保留三个身份角色的别名、空壳实体、双读或客户端兼容判断。

## 验收标准

- Liquibase MySQL/H2 演练通过；11 个默认管理员新密码验证为小写首字母规则，三个旧身份角色及其关系归零。
- 手机号、邮箱唯一约束生效，创建、资料修改、个人资料更新和导入均给出明确重复错误。
- 导入模板四张表可读、下拉选项有效，预校验覆盖成功、重复、越权、脏数据和全量回滚。
- 低权限管理员在 API、Web、Android 均看不到也无法提交高权限角色、权限和岗位模板。
- 同权限下更强的关系策略、组织范围、全市范围或更长有效期同样不可见或不可提交；预校验和事务内校验结果一致。
- Web/Android 组织、状态、角色筛选正确，角色折叠在宽屏与窄屏均不溢出。
- Backend/Web/App 测试、构建、Android 模拟器及生产只读 smoke 通过后才发布。
