# v5.6.6 脱敏模型与全量候选发布任务规格

## 目标

将当前工作树中已经完成的后端、Web、App 和图片脱敏增强统一收敛为同一套 `5.6.6` 制品，先部署测试命名空间完成隔离验证、回归和性能检查，再将同一不可变制品晋级生产环境。

## 范围

- 图片脱敏 Worker 使用 `cmcc-brand-v2-focused`，仅处理中国移动中文品牌名、英文品牌名和对应标识；普通文字、颜色、二维码及其他品牌属于硬负样本。
- Worker 支持可配置的 OCR 二次确认、有限密集扫描、独立置信度门槛、检测框有限外扩，以及原图/安全派生图分离保存。
- 后端、Web、App、数据库迁移、镜像标签和发布记录统一使用 `5.6.6`；Android `versionCode` 按项目公式生成。
- 将工作树已有的用户、权限、密码策略、脱敏巡检和 UI 增强纳入同一候选构建，不引入新的旁路兼容层。

## 非目标

- 不在本次新增视频脱敏。
- 不改变现有工单状态机、权限数据模型或组织归属规则。
- 测试验证不创建生产工单、通知或邮件；测试命名空间使用既有隔离数据库和关闭外发配置。

## 影响文件/制品

- `media-image-worker/redaction/`、`media-image-worker/models/`、运行时依赖和 Worker Kubernetes 配置。
- 后端 `build.gradle`、Web/App 版本元数据及现有工作树改动。
- `deploy/dedicated-cloud/e-report-test.yaml` 与生产 Worker 配置。
- 远端不可变发布目录、OCI 镜像和 SHA256 清单。

## 验收标准

1. 后端、Web、App、Worker 自动化测试和构建通过，版本契约检查通过。
2. 模型验证报告通过：所有正样本目标命中；法国军旗、普通建筑、广州铁塔、3G 手机等硬负样本零误报；CPU p95 在配置预算内。
3. 测试命名空间滚动发布成功，Worker 启动日志显示模型校验通过且 OCR 配置生效；抽样原图保留、安全派生图可加载，用户提交接口不被 Worker 阻塞。
4. 测试命名空间性能压测不产生生产工单、通知或邮件，任务失败/重试/完成状态可观察。
5. 生产备份、滚动发布、健康检查、日志和受控图片回归均通过；失败时使用发布前不可变镜像回滚。

## 测试方式

- Worker：`tmp/worker-venv` 中运行 pytest、py_compile、模型验证和受控图片处理基准。
- Backend：`gradlew test`、`bootJar`。
- Web：`npm test`、`npm run lint`、`npm run build`。
- App：`npm test`、`npm run typecheck`，如签名环境可用再构建 Android release。
- 远端：测试/生产命名空间 rollout、Pod/日志/健康接口、隔离任务计数和受控图片 smoke。
