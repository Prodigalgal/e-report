# 2.3.4 南靖通知配置归属与权限刷新

## 目标

- 清空漳州市公司层级的全部通知配置，把现有有效通知配置迁移到南靖县本地作用域。
- 未配置通知的其他区县保持“未配置且关闭”，不得继续读取平台、环境变量或市公司隐式默认。
- 规整历史 `MIGRATION` 岗位，使现有通知配置编辑员可通过正式授权计划升级到当前模板并刷新权限。

## 范围

- Liquibase `047` 先保留南靖县已有本地值，再迁入市公司租户和平台的 `notification.*`、`spring.mail.*` 配置，最后删除市公司与平台来源。
- 删除已退役且无代码消费者的 `system.fault.notification.recipient.phones`。
- 通知开关和日报缺少数据库配置时返回 `UNCONFIGURED`，运行时按关闭处理；发送时间只提供无副作用的 `18:00` 表单初值。
- 应用启动后清空配置缓存和授权快照缓存；岗位升级继续通过预检、幂等应用、授权版本递增和会话失效链路完成。
- 发布时仅升级现有“通知配置编辑员”历史岗位，不批量增加工单导出岗位，也不重建通知收件权限。

## 非目标

- 不改变工单、收件人、SLA、组织归属或数据域。
- 不把南靖配置写死到运行时代码；`350627` 只作为一次性数据迁移的行政区划业务键。
- 不自动启用其他区县通知，不触发邮件、钉钉、企业微信或日报发送。

## 影响文件

- Backend：`AppConfigService`、`NotificationSettingsService`、`NotificationSwitchPolicy`、日报开关、历史岗位升级规则。
- WEB：通知配置来源状态的未配置样式。
- Data：Liquibase `047`；Backend/WEB/APP 统一版本 `2.3.4`，Android `versionCode=1003004`。

## 验收标准

- 市公司 `app_config`、`tenant_app_config` 中通知与 SMTP 配置均为 0；南靖县本地配置完整且原有本地值优先。
- 南靖县显示本地配置；其他区县与市公司显示“未配置”，全部通知开关为关闭且发件方不可用。
- 测试、生产通知投递与日报调度在迁移验收期间不产生新 Outbox 或日报发送记录。
- 现有通知配置编辑员全部升级到当前模板，来源从 `MIGRATION` 收敛为 `PROFILE`，获得 `notification:sender:update`；其他原子权限数量和通知收件权限不被批量改写。
- 每个被升级用户的 `authorization_version` 递增，Redis 授权快照清空，旧会话在下一次请求时按既有机制失效并要求重新登录。

## 测试方式

- Backend 全量测试、H2 Liquibase、真实 MySQL 首次迁移与幂等复跑。
- WEB 测试、ESLint、生产构建；APP 测试、类型检查和版本契约。
- 测试命名空间 API/数据库/Redis/日志/UI 验收后，备份生产数据库再提升同一不可变制品。
