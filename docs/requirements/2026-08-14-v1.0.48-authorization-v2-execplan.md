## 核心契约

- `AuthorizationProfile`是配置模板，不参与运行时鉴权。
- 模板应用产生`AuthorizationAssignment`审计批次和显式`PermissionGrant`；前端不按批次组织权限。
- `PermissionGrant`是唯一授权事实，包含权限、资源范围、关系条件和有效期。
- 工单查询类权限默认使用本人组织树和 `ANY_IN_SCOPE`；`REPORTER` 与 `PARTICIPANT` 分别表示本人提单和本人参与处理，不互相包含。
- `ADJUST_PERMISSION` 必须携带目标原子权限，可以保持原权限只调范围，也可以在同一来源中替换为另一原子权限。
- 多条有效授权按允许并集计算；普通管理员只能撤销自己可管理的来源。
- 委派必须满足权限相同、组织范围为子集、关系条件不更宽、有效期不超过授予者。
- 列表查询计划和详情检查必须由同一`EffectiveAuthorizationSnapshot`生成。

## 验收标准

- 业务代码不再按`ROLE_`名称授权，也不再读取`MembershipRoleGrant`。
- 标准岗位、特殊逐权限调整、临时授权和多来源并集均可在WEB/APP完成。
- 区县管理员看不到、不能授予或修改超出自身边界的权限与数据范围。
- 管理员十天有效授权最多只能下发同权限且不晚于自身到期时间的授权。
- 每类工单 19 个独立动作均由原子权限控制，自验收动作使用 `RESPONSE_SUBMITTER` 关系而非当前处理人关系。
- 任一无额外业务筛选的列表结果均可打开详情，任一有详情权限的工单均可被查询到。
- V1迁移前后全部账号的有效权限差异均有确定解释，不出现未说明增权。
- 导入预览分页、分片上传、按用户事务执行和失败回滚保持有效。
- 后端全量测试、Liquibase MySQL/H2幂等、WEB测试/构建/lint、APP测试/typecheck通过。
- `e-report-test` Pod Ready、迁移成功、Redis快照可失效、API/WEB/APP全角色流程通过。

## 授权清单式 UI 重构

### 目标

- 用户详情页只保留一组集中操作入口，消除“调整授权”等重复按钮。
- 调整授权时首先展示用户当前可见的原子权限清单，管理员在同一界面完成查看、调整、撤销和追加。
- 岗位模板仅作为批量追加原子权限的快捷入口，单条权限作为精细追加入口。

### 范围

- WEB 用户详情页和 `AuthorizationEditorDialog`。
- APP 用户详情页和 `AuthorizationEditor`。
- 授权编辑工作流 helper 与对应前端测试。

### 非目标

- 不修改授权 API、数据库结构、Liquibase 迁移和运行时权限裁决。
- 不改变岗位模板发布、授权预检、委派上限、数据范围和有效期规则。
- 不切换生产环境。

### 验收标准

- 用户详情页的个人信息、组织、授权、状态和密码操作集中展示，任一功能只出现一个入口。
- 授权弹窗打开后直接显示当前权限，系统基线保持只读，可管理权限可直接调整或撤销。
- 当前权限以扁平清单展示，岗位模板和授权来源不得成为一级分组或独立管理对象。
- `追加岗位模板` 生成 `GRANT_PROFILE`，`追加单条权限` 生成 `GRANT_PERMISSION`，二者与现有调整、撤销操作统一进入待预检清单。
- WEB 与 APP 均采用“编辑清单 -> 确认变更”两步流程，预检前不得执行真实授权变更。
- WEB 测试、lint、构建及 APP 测试、typecheck、Expo Doctor 通过，并完成浏览器与 Android 模拟器交互验证。

## 逐权限 Diff 预览

### 目标

- “预览变更”只展示实际发生变化的原子权限，不再用一条岗位模板或操作摘要包揽多项变化。
- 新增、调整、撤销分别使用明确的 Diff 语义；调整项只展示发生变化的字段及变更前后值。

### 范围

- 后端授权预检响应新增逐权限结构化 `before/after`，由服务端作为最终执行事实来源。
- WEB 与 APP 使用同一字段语义渲染权限、数据范围、资源关系、开始时间和有效期差异。
- 岗位模板仍作为批量追加快捷方式，但预览时展开为模板内的每一条原子权限。

### 非目标

- 不改变授权计划的执行、幂等、有效期、委派边界和审计规则。
- 不修改数据库结构或 Liquibase，不切换生产环境。

### 验收标准

- 岗位模板包含 N 条权限时，预览展示 N 条“新增”记录。
- 单条新增展示完整新值；撤销展示完整旧值；调整仅展示真正变化的字段。
- 无实际变化的调整在服务端预检阶段被拒绝。
- WEB、APP、后端专项测试与构建通过，并部署到测试命名空间等待用户终测。

## 用户导入导出 Diff 升级

### 目标

- 批量导入预览按用户展示真实字段和原子权限 Diff，不再把一行命令拼成一段文案。
- 批量导出在创建异步任务前确认筛选范围、预计用户数、工作表和字段集。
- 保留既有分片上传、多段 Range 下载、异步校验、分页读取、快照防漂移和按用户事务执行能力。

### 范围

- 导入预览行新增脱敏用户标识、结构化字段 `before/after` 和逐权限 `ADD/UPDATE/REMOVE`。
- 导入任务摘要新增受影响用户、阻断用户、无变化命令及权限变更数量。
- 导出新增只读预检 API；实际文件继续由后台任务生成并分段下载。
- WEB 重构批量治理预览和导出确认对话框；APP 不增加表格导入导出入口。

### 非目标

- 不改变工作簿命令语义、授权执行规则、权限委派上限和用户事务边界。
- 不在预检阶段生成文件或加载完整授权事实，不把大数据集一次性返回浏览器。
- 不部署生产环境，不修改生产用户、工单、通知或授权数据。

### 验收标准

- 用户资料变更只显示实际变化字段；每项均明确旧值和新值，无变化命令单独计数。
- 岗位模板在导入预览中展开为每条原子权限；调整只显示变化字段，撤销显示原值。
- 错误命令按脱敏用户聚合并显示阻断原因；预览仍支持服务端分页和只看错误。
- 导出确认显示当前筛选条件、服务端可导出用户数、上限及四个工作表字段，不确认不得创建任务。
- Liquibase MySQL/H2、后端全量测试、WEB 测试/lint/build 和测试命名空间浏览器 smoke 全部通过。
