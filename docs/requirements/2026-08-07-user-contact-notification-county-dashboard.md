# 用户联系方式、区县通知路由与仪表盘域分增强

> 状态：已完成并投产
> 日期：2026-08-07
> 等级：S3（用户契约、通知路由、统计查询、Liquibase、Web、Android 与生产迁移）

## 目标

- 用户新增必填手机号和可选邮箱；账号继续保持全系统唯一，登录时无需选择租户。
- 区县工单通知默认发送给工单提单组织所属区县的启用状态区县管理员。
- 通知收件地址优先使用用户显式邮箱；未配置邮箱时使用 `手机号@139.com`。
- 通知中心继续位于系统配置菜单中，但使用独立 Tab，并保持市、区县作用域隔离及分渠道启停。
- 企业微信和钉钉保留渠道能力，但默认关闭且本期不写入 webhook、密钥等凭据。
- 市公司管理员可以查看全市汇总、下钻任一区县，并在全市视角横向比较各区县数据；区县管理员只查看本区县。
- Android 最新版下载 URL 统一为 `https://e-report.fantong.eu.org:60443/download/android`；348 账号的 R2 上传和对象分发保持不变，但客户端与页面不直接使用 R2 域名。

## 范围

- 数据库：`users.phone`、`users.email`；历史手机号用户名回填；退役静态邮件收件人配置；关闭并清理企业微信、钉钉渠道敏感配置。
- 后端：用户联系方式校验、租户初始管理员联系方式、按角色和组织解析邮件收件人、统计作用域和区县聚合查询。
- Web：用户与租户表单、个人信息、系统配置/通知中心双 Tab、仪表盘区县选择与对比。
- Android：用户管理、个人信息、系统配置/通知中心双视图、仪表盘区县选择与对比。
- 运维：MySQL 迁移演练、生产备份、滚动发布、API/浏览器/Android 模拟器验证。

## 非目标

- 不强制一次性补齐全部历史用户手机号，也不为历史无手机号用户生成虚假号码。
- 不改变账号全局唯一和登录自动识别租户的现有契约。
- 不改变六状态工单主状态机、派调单规则、验收规则和 SLA 阈值。
- 不接入新的邮件供应商，不启用企业微信或钉钉，不在源码或数据库写入其密钥。
- 不新增独立报表服务，不引入 OLAP、消息总线或平行的组织权限体系。

## 数据与兼容策略

- `users.phone` 物理列暂允许 `NULL`，仅用于容纳未处理的历史账号；所有新增用户、租户初始管理员和后续用户/个人资料编辑均要求合法手机号。
- `users.email` 允许 `NULL`，非空时必须符合邮箱格式；客户端和服务端使用同一语义校验。
- Liquibase 仅将符合中国大陆手机号格式的历史 `username` 回填到 `phone`，其他历史账号保持 `NULL`。
- `notification.email.recipient.phones` 从平台、租户和组织配置中删除，应用不再读取该键。
- 企业微信、钉钉启用状态迁移为关闭，并删除现存 webhook/secret 配置值；后续只能由管理员显式重新配置和启用。
- 数据迁移不可逆部分以生产迁移前 MySQL 快照为回滚点；应用镜像和前端镜像保留上一生产 tag。

## 通知收件人与隔离规则

1. 工单通知快照保留 `reportingOrgUnitId`，以提单时组织作为通知归属；后续派单或调单不改变通知归属。
2. 提单组织向上解析到最近的 `COUNTY` 组织，查询该区县范围内处于启用状态且拥有 `ROLE_COUNTY_ADMIN` 的用户。
3. 市公司直属工单没有区县祖先时，查询市公司范围内处于启用状态且拥有 `ROLE_ADMIN` 的用户。
4. 每名用户优先使用合法的显式 `email`；未配置时使用合法 `phone` 生成 `phone@139.com`。
5. 非中国移动手机号仍按规则尝试投递到 `@139.com`；失败只影响该收件人的投递记录，必须记录脱敏地址、用户 ID 和失败原因，并进入现有 Outbox 重试。
6. 没有任何可用收件人的已启用邮件渠道视为配置错误，不静默成功；租户与工单组织边界必须同时参与查询。

## 仪表盘统计契约

- `GET /work-orders/statistics/scopes` 返回当前用户可选的区县作用域。只有具备全租户统计范围的市公司管理员返回区县列表；区县管理员返回空列表。
- `GET /work-orders/statistics?countyOrgUnitId={uuid}` 在既有权限范围之上增加提单组织归属过滤，不扩大数据可见范围。
- 全市汇总响应增加 `countyComparison`，每个区县包含：总量、在途量、已闭环量、闭环率、当前 SLA 超时量和超过 72 小时量。
- 选中单一区县后，现有总览卡片、状态/类型分布、SLA 和历时指标全部按该区县重算；此时不重复返回全市对比。
- 区县比较使用一次分组查询读取必要列，再按组织祖先归并；即使某区县无工单，也必须返回零值行，保证前端稳定比较。
- 统计归属始终使用工单 `reportingOrgId`，避免派调单改变区县业绩归属。

## 验收标准

- 新建/编辑用户缺少手机号或手机号格式非法时返回中文校验错误；邮箱为空合法，非空非法时被拒绝。
- 历史手机号用户名被正确回填；非手机号用户名不被伪造联系方式，既有登录不受影响。
- 区县新工单只解析到本区县管理员；显式邮箱优先，未配置邮箱回退到 `手机号@139.com`；跨区县和跨租户收件人均不可出现。
- 静态收件人配置键不存在且代码无引用；企业微信和钉钉默认关闭、无 webhook/secret 值。
- Web 与 Android 的系统配置菜单均有“系统配置”和“通知中心”两个独立视图，作用域切换一致。
- 市公司账号能切换 11 个区县，所有统计随选择变化，并可在全市视角比较区县；区县账号无跨区县入口和数据。
- 后端测试、Web test/lint/build、Android test/typecheck/doctor/release 构建、浏览器桌面/窄屏和 Android 模拟器 smoke 全部通过。
- 生产部署前完成数据库备份和 Liquibase 演练；部署后 Pod、日志、API、Web、通知设置和 APP 更新链路正常。
- 版本检查、Web 下载按钮和发布脚本只输出统一下载 URL；固定入口仍能重定向到当期 R2 不可变对象并完成 Range/SHA 校验。
