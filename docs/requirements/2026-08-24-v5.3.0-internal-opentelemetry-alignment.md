# 5.3.0 内部观测全量对齐 OpenTelemetry

## 目标

将 WEB、APP、Backend 已有埋点统一为可验证的 OpenTelemetry 语义模型，贯通 W3C Trace Context，并由 Spring Micrometer Observation 承担服务端 Trace 生命周期；不增加外部或自建观测服务。

## 范围

- `ereport-otel/1` 批量上报协议及服务端兼容转换。
- Resource、InstrumentationScope、Log、Span、Span Event 和标准 Severity Number。
- WEB/APP 请求发送 `traceparent`，同时保留独立 `X-Request-Id`。
- Backend 接收或创建 W3C Trace Context，并在响应暴露 `traceparent`、`X-Trace-Id`、`X-Request-Id`。
- Redis 缓冲消息升级到 schema 2。
- PostgreSQL 使用 Liquibase 加法迁移保存 canonical OTel 字段。
- 管理端详情显示信号类型、Trace/Span、Scope、Resource、Attributes、Span Events 和旧协议标识。
- Backend 使用 Spring Boot OpenTelemetry/Micrometer Observation，关闭所有远端 exporter。
- 功能版本最初占用 5.3.0，Android `versionCode=4003000`；真实浏览器验收发现 MUI 9 输入插槽兼容问题后升级为 5.3.1；APP 实机链路验收又发现 User-Agent 遗留固定版本，最终修复候选升级为 5.3.2 / `versionCode=4003002`。5.3.0、5.3.1 制品均不复用。

## 非目标

- 不部署或连接 OTel Collector、Jaeger、Tempo、Prometheus、Grafana、Sentry、PostHog。
- 不开放公网 Actuator 管理端点。
- 不采集新的硬件唯一标识或敏感业务数据。
- 不修改生产环境；仅部署 `e-report-test`，待用户终验。
- 不因为对齐规范而采集所有 INFO 日志或每个只读请求。

## 数据契约

批次新增 `schemaVersion=2`、`resource`、`instrumentationScope`。事件新增：

- 公共：`signalType`、`traceId`、`spanId`、`parentSpanId`、`traceFlags`、`requestId`、`attributes`。
- Log：`severityNumber`、`severityText`、`body`。
- Span：`spanName`、`spanKind`、`spanStatusCode`、`spanStatusMessage`、`durationNanos`、`spanEvents`。

旧 `environment`、`severity`、`message`、`breadcrumbs` 在入站层保留兼容；内部缓冲和新数据库列只认 canonical 结果。

## 属性约束

- 标准 HTTP 属性：`http.request.method`、`http.response.status_code`、`url.path`。
- 标准异常属性：`exception.type`、`exception.message`、`exception.stacktrace`。
- 项目属性：`ereport.request.id`、`ereport.event.type`、`ereport.event.category`、`ereport.event.name`、`ereport.operation.name`、`ereport.operation.outcome`。
- 单事件最多 64 个属性，Span Event 最多 30 个，每个 Span Event 最多 32 个属性；字符串单值最长 2,000 字符，结构化 JSON 总长继续受现有 Sanitizer 限制。

## 兼容与迁移

- PostgreSQL 迁移只新增列、索引和校验约束，不删除旧列。
- 旧客户端上报转为 `schemaVersion=1`，Log/Span 类型按 `eventType` 推导，无法确认的 Trace ID 不写入 canonical `otel_trace_id`。
- 新记录同时写必要旧投影，现有筛选、留存和 UI 不退化。
- Redis 中 schema 1 消息由 Writer 兼容读取；新生产消息一律 schema 2。

## 验收标准

1. WEB 与 APP 请求携带合法 W3C `traceparent`，Backend 响应携带同一 Trace ID 的新 server Span。
2. 客户端 API 失败事件与 Backend 写操作可按 32 位 Trace ID 关联，`X-Request-Id` 保持独立。
3. 新客户端批次包含规范 Resource/Scope，数据库 canonical 字段完整。
4. 旧 schema 1 批次仍返回 2xx，非法 canonical Trace/Span 被拒绝或降级，不污染标准字段。
5. Spring OTLP traces、metrics、logs exporter 均关闭，运行日志不存在向 Collector 连接失败。
6. 租户、组织、用户数据面和脱敏规则不退化；测试期间不产生工单与通知数据。
7. Backend 测试、WEB 测试/build、APP 测试/typecheck、Liquibase 首次与幂等执行、浏览器和模拟器 smoke 全部通过。

## 回滚

- 应用回滚到 5.2.0 时保留新增 nullable 列和索引，不影响旧实体读写。
- 测试环境回滚使用上一不可变镜像；不逆向删除观测数据。
- 只有迁移约束造成写入异常时才删除对应约束/索引，新增列保留以便审计。
