# 5.0.9 权限体系 V4 执行计划

## 目标

以原子权限、单一有效 Grant、组织/部门/工单资源关系替换旧 V3 管理域、账号保护、管理主体、独立委托和审批模型，并把 PostgreSQL 作为最终运行数据库。

## 范围

- 固定权限目录增加主体敏感度和 API Token 可分配性，完成 every-action 权限拆分。
- `PermissionGrant` 改为用户直接授权事实，支持父子链、转授权、有效期、覆盖、暂停和重新挂接。
- 岗位模板退化为无运行时绑定的权限批量选择器。
- 用户唯一所属组织、可选部门；组织树决定自然数据面。
- 部门树及停用、移动、合并、删除预检。
- 工单组织归属、部门责任、保留查看关系和两阶段完整移交。
- WEB/APP 用户详情直接编辑权限清单，模板仅用于批量追加，所有变更提供结构化 Diff。
- MySQL 到 PostgreSQL 转换、Liquibase baseline、测试数据隔离和测试环境闭环。

## 非目标

- 不实现工单多标签/多任务抽象。
- 不建设铁通、驻地网之间的独立租户。
- 不保留旧角色、管理域、保护等级或岗位绑定兼容接口。
- 用户终验前不切换生产环境。

## 既有未提交工作并入基线

本次升级以当前工作树为唯一开发基线，不回退或静默删除下列已完成/进行中的增强：

- PostgreSQL 迁移工具、租户感知数据源、RLS、测试命名空间和专用云部署脚本。
- API Token 权限化、敏感配置脱敏、改密后撤销 Token/受信设备及供应链扫描。
- 用户姓名全拼/首字母模糊检索、用户组织调整预览和批量导入导出的任务化、分片与 Diff。
- 登录、未认证路由、会话恢复、客户端版本信息与品牌文案修复。
- 工单处理/审计时间轴、报单材料与回单材料区分、已领取工单详情可见性和 SLA 相关修复。
- WEB/APP 已完成的用户详情、系统配置、工单详情及管理入口 UI/UX 优化。

若既有实现引用 V2/V3 角色、Assignment、DataScope、账号保护或管理域模型，保留其业务目标和验收用例，改写到 V4 原子 Grant、自然组织数据面与资源参与关系上；不保留旧运行时兼容层。

## 迁移顺序

1. 冻结 V4 权限目录和旧码映射。
2. 建立 V4 Grant、部门、工单组织参与和移交结构。
3. 转换既有有效授权，校验唯一性、有效期和转授权上限。
4. 切换授权快照、用户管理、工单查询和动作判定。
5. 切换 WEB/APP 权限编辑、部门和移交交互。
6. 删除旧 V3 Controller、Service、Entity、Repository 和前端入口。
7. 完成 PostgreSQL、Backend、WEB、APP、模拟器及测试命名空间验收。

## 验收标准

- 业务代码和 API 不再读取角色、管理域、保护等级、管理主体、独立委托或岗位绑定。
- 每个独立业务动作有权限码且服务端默认拒绝未授权请求。
- 同一用户同一权限只有一个 ACTIVE Grant；覆盖和级联状态可审计。
- 下游授权权限、有效期和 `grantOption` 均不超过上游。
- 同组织横向保护、严格上级治理、同级组织隔离和 `superAdmin` 信任根通过正反向测试。
- 领取后的工单仍可由其他满足查看权限和资源关系的用户查看。
- 跨组织移交接受前后归属正确，原组织保留查看权。
- 模板应用不建立运行时关联，逐项执行授权上限检查。
- API Token 权限不超过用户当前有效 Grant，禁止系统/授权治理权限进入 Token。
- PostgreSQL 迁移行数、UUID、外键、唯一性和摘要校验通过；测试环境不发送生产通知。

## 测试方式

- Backend：领域单测、Repository/Service 集成测试、Controller BOLA/BFLA、Liquibase/PostgreSQL Testcontainers 或独立测试实例。
- WEB：权限清单、模板追加、Diff、组织/部门与工单移交交互测试、lint/build。
- APP：相同权限态与工单链路测试、typecheck、Expo Doctor、Android 模拟器安装与登录 smoke。
- 运行态：测试命名空间迁移、真实账号矩阵、数据库只读核对、日志与健康检查。

## 回滚边界

测试环境保留 4.2.0 不可变镜像、被拒绝的 5.0.0 至 5.0.8 候选和迁移前 PostgreSQL 快照。5.0.9 开放写入前可直接回滚镜像和数据库快照；开放写入后必须停写并恢复对应快照，禁止新旧权限模型双写。
