# 1.0.41 工单领域标识与语义颜色深度迁移

## 目标

- 将误导性的“普通故障”领域类型完整迁移为“网络故障”，将“未关箱”迁移为“箱门未关”，并统一破损箱体更换的角色标识。
- 将优先级 `NORMAL` 完整迁移为语义明确的 `ROUTINE`，中文展示为“常规”。
- 建立类型、优先级、SLA 风险、流程状态和历时区间相互独立的颜色语义，红色只表达紧急，紫色只表达 SLA 超时。
- 由后端统一计算 SLA 风险等级，Web 和 Android 只消费契约，不各自复制时限算法。
- Android 统一发布为 `1.0.41` / code41 / `android-1.0.41-native41`，并作为强制更新版本。

## 范围

- Backend：工单类型、优先级、权限常量、内置角色、SLA 风险等级、DTO、通知与报表，以及相关自动测试。
- Data：Liquibase 022 原位迁移工单、SLA 策略、角色、权限和授权缓存版本；MySQL 枚举最终只保留新值。
- Shared：新增 `work-order-presentation.json`，作为 Web 与 Android 的颜色、标签和显示优先级唯一来源。
- Web：工单列表、详情、创建、回单、仪表盘、角色管理和 SLA 展示统一使用新契约。
- Android：工单列表、详情、查询、创建、回单、仪表盘、角色和版本契约同步迁移。
- Release：数据库快照与克隆演练、生产停写迁移、镜像部署、R2 APK、浏览器和模拟器验收。

## 非目标

- 不改变既有工单主状态机、角色职责边界、组织数据范围或租户隔离规则。
- 不新增旧枚举、旧权限名、旧角色名、旧路由或旧请求值的兼容别名和双读双写。
- 不修改历史 Liquibase changeSet；历史文件保留作为已执行迁移证据。
- 不用颜色替代文字、图标或可访问性标签，不以单一颜色表达多个业务维度。

## 领域契约

### 工单类型

| 旧标识 | 新标识 | 中文名称 | 权限 slug | 角色前缀 |
| --- | --- | --- | --- | --- |
| `NORMAL_FAULT` | `NETWORK_FAULT` | 网络故障 | `network-fault` | `ROLE_NETWORK_FAULT_` |
| `UNCLOSED_BOX` | `BOX_DOOR_OPEN` | 箱门未关 | `box-door-open` | `ROLE_BOX_DOOR_OPEN_` |
| `DAMAGED_BOX_REPLACEMENT` | `DAMAGED_BOX_REPLACEMENT` | 破损箱体更换 | `damaged-box-replacement` | `ROLE_DAMAGED_BOX_REPLACEMENT_` |

### 工单优先级

| 旧标识 | 新标识 | 中文名称 |
| --- | --- | --- |
| `URGENT` | `URGENT` | 紧急 |
| `HIGH` | `HIGH` | 高优先 |
| `NORMAL` | `ROUTINE` | 常规 |
| `LOW` | `LOW` | 低优先 |

### SLA 风险

后端新增 `SlaRiskLevel`：

- `NORMAL`：未进入临期、未超时。
- `DUE_SOON`：剩余时间大于 0，且不超过当前环节预算的 20%。
- `BREACHED`：当前环节已超时。
- `PAUSED`：SLA 处于暂停状态。
- `COMPLETED`：SLA 已完成，不再计时。

列表和详情 DTO 同时返回 `slaRiskLevel` 与中文 `slaRiskName`。风险计算以服务端时间、当前环节截止时间和租户 SLA 策略为准，客户端不得自行推导风险等级。

## 数据迁移

- Liquibase 022 先扩展 MySQL `report_type` 枚举，再原位更新工单和 SLA 策略，最后收紧为只包含新枚举值。
- `fault_reports.priority` 和 `work_order_sla_policies.priority` 原位将 `NORMAL` 更新为 `ROUTINE`。
- `roles` 与 `permissions` 保留 UUID 主键，原位更新编码、名称和说明；`role_permissions`、`role_bundle_items`、`user_role_grants` 等关联无需重建。
- 全量递增用户 `authorization_version` 并在发布切换时清理 Redis 权限缓存，防止旧 token 权限投影继续生效。
- 迁移前必须停写并生成数据库备份；在生产克隆库验证首次迁移、数据计数、孤儿引用、旧标识归零和应用启动后，才能执行正式迁移。
- 该迁移不支持应用与数据库单独降级。回滚必须同时恢复数据库快照、1.0.40 后端和 1.0.40 前端；code41 不复用。

## 验收标准

- 当前运行时代码、API、角色、权限、现行数据库值、Web 和 Android 不再出现旧领域标识；历史 migration 和历史发布文档除外。
- 原有用户角色 Grant、权限数量关系、工单数量、附件引用和 SLA 策略数量保持完整，新角色编码立即生效。
- SLA 风险五种状态均有后端测试；20% 边界、超时、暂停、完成和无截止时间行为明确。
- 三端的工单类型、优先级、SLA 和状态颜色与共享契约一致，页面内没有重复颜色分支。
- Web 桌面及窄屏、Android 模拟器验证工单创建、查询、详情、回单、派调单、验收和看板，不出现旧文案或颜色冲突。
- Backend/Web/App 测试、lint/typecheck、生产构建、Liquibase MySQL/H2 演练、APK 签名、R2 HEAD/Range/SHA、更新检查和生产只读 smoke 全部通过。
