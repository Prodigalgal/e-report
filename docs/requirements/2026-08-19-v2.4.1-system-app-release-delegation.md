# 2.4.1 系统级安装包发布权限委派

## 目标

- 安装包发布中心保持系统级资源，不受租户或组织数据域裁剪。
- 超级管理员作为系统权限根，可在用户授权界面显式委派发布权限，不依赖数据库人工改数。
- 被委派管理员若同时拥有用户授权能力，可沿用统一授权流程继续委派，但权限集合、目标用户可见范围和有效期均不得超过自身。

## 权限模型

- `system:super-administrator`：系统根身份，天然覆盖全部系统级发布权限。
- `app-update:view`：查看系统发布记录。
- `app-update:publish`：上传并发布安卓安装包。
- `app-update:policy-update`：修改强制更新、最低支持版本和发布说明。
- `app-update:delete`：撤销发布记录。
- `app-update:storage:view`：查看对象存储同步状态。
- `app-update:storage:sync`：发起对象存储同步。
- `app-update:storage:delete`：删除非当前发布对象。

系统级发布权限只能作为单条原子权限显式委派，作用范围固定显示为“全系统”。它们不进入租户岗位模板、用户批量导入模板或普通 API Token，避免通过批处理和自动化凭据无意扩散。

## 委派边界

- 授予者必须实际拥有目标 `app-update:*` 权限；超级管理员由系统根身份提供无限期根覆盖。
- 授予者还必须拥有对应的用户授权授予、调整或撤销权限。
- 被授权用户必须位于授予者用户管理数据域内。
- 下级授权的到期时间不得晚于上级；上级是限时权限时不得向下授予长期权限。
- 系统级权限拒绝指定组织、组织树或租户范围，避免把系统动作错误表达为业务数据域。
- 所有变更继续经过预检、逐权限 Diff、原因、幂等应用、授权版本刷新和审计来源记录。

## 迁移与回滚

- Liquibase `048` 退役历史租户发布岗位和旧授权，默认不向普通管理员自动下放。
- Liquibase `049` 修正迁移审计说明，明确后续通过统一授权界面显式委派。
- 生产迁移前备份数据库；回滚应用使用上一不可变镜像，授权数据恢复以迁移前备份为准。

## 验收标准

- 超级管理员可在 WEB/APP 用户授权弹窗搜索并授予系统发布原子权限，UI 固定显示“全系统”。
- 被授权管理员获得相应菜单和 API 能力；未授权动作保持隐藏且接口返回 403。
- 同时具有用户授权能力的被授权管理员可继续委派，超过自身权限或有效期的预检必须失败。
- 系统发布权限不出现在岗位模板、批量导入模板和 API Token 权限候选中。
- WEB 支持上传最新版与下载指定版本；APP 支持查看和下载指定版本，不新增安装包上传入口。
