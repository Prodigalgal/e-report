# 5.2.0 委派基线修复与装维关箱岗位收敛

## 目标

- 修复 PostgreSQL V5 数据迁移后系统基线 Grant 全部丢失 `grantOption`，导致岗位模板和用户可选权限为空的问题。
- 保证 `superAdmin`、市公司默认管理员和区县默认管理员在无角色运行时模型下持续拥有与其组织层级匹配的标准权限和向下委派能力。
- 将箱门未关处理职责明确收敛到装维岗位模板，普通人员继续通过提单岗位提交并跟踪工单。

## 范围

- 新增启动期系统授权基线校准：同步固定岗位模板、校准超级管理员系统根 Grant、校准既有系统基线管理员的市公司/区县标准权限，并刷新授权版本。
- 新增 PostgreSQL Liquibase 幂等数据迁移，修复迁移存量 Grant、记录迁移审计并使旧会话重新认证。
- 岗位模板页面和用户授权弹窗在委派集合为空时显示明确原因，不再呈现无说明空白。
- “箱门未关处理员”更名为“装维关箱处理员”；“通用故障处理员”不再隐式包含关箱处理权限。

## 非目标

- 不按姓名、账号或组织硬编码装维人员，不自动猜测既有人员是否属于装维。
- 不撤销既有用户已经持有的箱门未关处理 Grant；存量人员清理必须依据明确的装维名单另行执行。
- 不改变 `grantOption` 双重约束：授权动作权限决定能否操作，单项 Grant 的 `grantOption=true` 决定该权限能否继续向下委派。
- 不切换生产环境；仅更新测试候选，等待用户终验。

## 影响文件

- Backend：系统授权基线初始化器、Grant/用户查询、固定岗位模板、岗位与授权查询空态、集成测试。
- Database：PostgreSQL `003` Liquibase 幂等修复与审计记录。
- WEB/APP：岗位模板和授权编辑器空态说明。
- Version/Deploy：Backend、WEB、APP、Android 与测试镜像统一升级到 `5.2.0`。

## 验收标准

- `superAdmin` 拥有固定目录全部原子权限，所有可委派权限均存在长期有效的 `SYSTEM_ROOT` Grant 且 `grantOption=true`。
- 市公司和区县系统基线管理员分别与当前标准岗位一致；只能在自身组织树内操作。
- `admin`、`nanjing` 重新登录后，岗位模板列表和用户授权可选权限均非空。
- 没有任何 `grantOption=true` 权限的账号仍看不到可委派项，但页面明确说明原因。
- “装维关箱处理员”包含领取、接受派单、拒绝派单、回单、挂起和恢复权限；普通关箱提单员不包含处理权限。
- 全量 Backend/WEB/APP 测试、版本契约、Liquibase 首次与幂等执行、测试环境 API/浏览器/模拟器 smoke 通过；生产保持不变。
