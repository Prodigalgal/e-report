# 3.1.0 用户姓名拼音检索

## 目标

- 用户管理、组织负责人候选人和工单派单候选人支持按中文姓名、姓名全拼和姓名首字母检索。
- `林智博` 可由 `林智博`、`linzhibo`、`lzb` 定位；拼音检索忽略大小写、空格和常用连接符。
- `吕春珉` 使用键盘拼音 `lvchunmin`，并兼容用户输入 `lüchunmin` 或带声调拼音。
- 检索不得扩大调用人的租户、组织数据域或业务权限。

## 范围

- `users` 增加 `name_pinyin`、`name_pinyin_initials` 两个持久化检索键及租户联合索引。
- 所有 JPA 新建、修改和批量导入用户的写入路径统一维护检索键。
- 历史空检索键由幂等、分批、可重试的后台任务回填；部署验收前必须确认待回填数量为零。
- 管理端 WEB 和 APP 的用户搜索提示补充“姓名拼音/首字母”。
- 修正 3.0.0 V3 权限迁移在 MySQL 中使用保留字别名的问题，并使失败后重跑不产生重复控制事实。

## 非目标

- 不提供多音字人工词典、模糊纠错或同音字搜索。
- 不把拼音字段返回给客户端，也不允许客户端提交拼音字段。
- 不改变用户名、手机号和邮箱的唯一约束。

## 影响文件

- Backend：`User`、`UserRepository`、`UserService`、姓名检索键生成器与回填任务。
- 数据库：Liquibase `055` 迁移和 V3 `053` 可重入修复。
- WEB/APP：用户管理搜索输入提示。
- 版本契约：Backend、WEB、APP、Android 与部署制品统一为 `3.1.0`。

## 契约与取舍

- 拼音字段属于服务端派生数据，业务真相仍是 `users.name`。
- 拼音匹配采用前缀查询，以利用 `(tenant_id, name_pinyin)` 与 `(tenant_id, name_pinyin_initials)` 索引；中文、账号、手机号和邮箱保持包含查询。
- 转换采用 Maven Central 发布、Apache-2.0 许可的 `com.github.houbb:pinyin`，不在客户端重复实现。
- 拼音列使用 utf8mb4；中文拼音统一生成键盘输入形式，避免 `ü` 与 `v` 造成写入和检索不一致。
- 实体生命周期回调保证所有 JPA 写入路径一致；回填任务只处理空值或与当前姓名不一致的历史行，每批独立事务。

## 验收标准

- `林智博` 使用 `lzb`、`linzhibo`、`LIN ZHI BO` 均可检索到。
- 县级管理员只能检索到其授权组织数据域内的匹配用户；市级和系统级管理员按各自数据域返回。
- 派单候选人拼音检索仍执行工单类型处理资格过滤。
- 新建、编辑个人资料和批量导入修改姓名后，检索键立即更新。
- 迁移可在 3.0.0 已部分执行的测试数据库上重跑，且管理域、保护事实、管理身份和委托上限无重复。
- 历史回填任务可重复执行，最终待回填数量为零。
- 后端测试、WEB/APP 测试与构建、版本契约、依赖扫描、测试环境 API/浏览器/模拟器验收全部通过。

## 测试方式

- 单元测试：拼音生成、规范化、空值、混合字符、实体回调。
- 集成测试：Liquibase 全新库与失败恢复路径、用户查询数据域、创建/更新/导入后的检索。
- 运行态：测试库回填计数、真实管理 API、浏览器用户管理页、Android 模拟器用户管理页。
