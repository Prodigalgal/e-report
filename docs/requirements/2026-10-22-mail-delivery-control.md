# 邮件发送节奏与收件人重试

## 目标与范围

- 为每个实际 SMTP 账号增加可配置的单封冷却，默认 10 秒；同账号跨组织、继承池和应用实例共享并发限制及失败退避。
- 工单、派单、超时通知、日报和配置测试统一经过发送控制。保留现有权限、订阅、组织继承、正文、附件和邮件台账三种状态。
- 按业务通知及收件地址持久化投递进度，SMTP 已接受的收件人不因其他收件人失败而重发。实际尝试继续分别记入邮件台账。
- 非目标：不更换 SMTP 提供商、不将冷却作为 Gmail 网络故障修复、不启用 Argo 邮件、不提升生产。

## 实现边界

- 复用现有 Outbox 与日报调度，通过可用时间重新调度；冷却不消耗发送尝试次数，不使用线程休眠，不新增独立消息组件。
- Redis 原子租约按服务器及认证账号的摘要（同主机的465/587端口共用；无认证时使用发件地址）协调，同账号同时仅一个发送操作；凭据和明文邮箱不进入 Redis key。协调服务故障时暂缓发送。发送期间定期续租，同时延长数据库检查点期限，结束时取消续租。
- 连接失败、认证失败及 SMTP 临时拒绝使账号退避；后续单次试发成功后恢复。内容或收件人永久拒绝不无差别熔断账号。
- 新增数据库投递检查点，按租户、通知身份及收件地址摘要去重。发送网络操作在事务外执行；检查点和每次尝试台账分别保留。
- SMTP 已明确拒绝或连接建立前失败可重试；提交阶段超时、执行中崩溃等不能确定是否已接受的场景记为失败并停止自动重发，避免重复通知。
- 配置测试在冷却期间直接返回剩余等待时间，不排入业务队列。
- 默认发送间隔10秒，暂态失败依次退避1/5/15/30分钟，认证失败退避30分钟；每个收件人最多10次实际发送尝试。成功后清除账号失败计数。已有账号未提交新字段时保留已保存的间隔，新账号或未配置字段的账号默认10秒。

## 影响模块

- Backend：发件池 DTO/存储、发送协调、邮件投递检查点、工单通知、日报、配置测试、Outbox 延迟重试、Liquibase。
- WEB：现有发件账号配置中的发送间隔及校验，Lite 使用相同页面；RN 发送的业务通知自动使用相同服务端控制，不新增原生 SMTP 配置页面。
- 版本：新增向后兼容能力，测试候选占用 `6.10.0`，由既有版本工具同步各端。

## 验收与验证

- 同账号串行、不同账号独立、跨组织共享、冷却边界、Redis 故障、租约过期及旧租约释放均有验证。
- 失败退避、成功恢复、临时/永久错误、提交后超时分别验证；日志包含安全的账号标识与错误分类。
- 部分收件人成功后重试、并发领取、服务重启、日报延迟继续发送均不重发已经确认接受的邮件。
- 后端相关测试及全量回归、WEB test/lint/build、APP test/typecheck、版本与迁移契约通过；外部 SMTP 的网络可达性与收件箱送达单独记录。
- 使用已有自动 CI/CD 进入测试环境；生产保持现状，待验收后另行提升。

## 兼容与回滚

- 发件池新增可选间隔字段，允许0至3600整数秒，0秒关闭间隔，并发限制仍保留。默认值及部分更新规则见实现边界。
- 数据库只新增检查点及可空关联字段；保留现有发送历史，不改写已经发布的迁移。
- 回滚使用上一不可变 Backend/WEB 制品，新增表与字段可保留。旧版本不具备冷却与收件人去重，回滚时须先暂停邮件渠道，防止重放未完成通知。
