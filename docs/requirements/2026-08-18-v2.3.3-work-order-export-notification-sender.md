# 2.3.3 故障导出与区县邮件配置

## 目标

- WEB 工单查询按当前筛选条件导出 XLSX，导出结果严格受独立原子权限、资源关系和数据域约束。
- 将每日未处理工单邮件的启停、发送时间和发件方配置完整暴露到通知中心，并按原子权限控制查看与修改。
- SMTP 发件方取消平台和环境默认值；区县使用本地完整配置，未配置时只允许继承市公司显式默认配置。

## 范围

- 新增每种工单类型的 `work-order:{type}:export` 原子权限，允许 `ANY_IN_SCOPE`、`REPORTER`、`PARTICIPANT` 资源关系。
- 新增 `notification:sender:update` 原子权限；保留 `notification:config:view`、`notification:channel:update`、`notification:schedule:update` 的既有职责。
- WEB 工单查询页增加“导出当前结果”，后端按 500 条分页查询、最多导出 50,000 条，并通过临时文件返回 UTF-8 中文文件名。
- XLSX 只包含工单业务字段和组织名称，不包含附件文件、密码、内部授权信息或诊断数据。
- 通知中心增加 SMTP 发件方表单，区分“市公司默认”“区县本地配置”“未配置”，支持保存完整覆盖和删除区县覆盖后恢复继承。
- Liquibase `045` 将已有平台 SMTP 值迁移为各现有租户的显式市公司默认，再删除平台 SMTP 默认项；新租户不自动生成发件方。

## 非目标

- APP 不提供工单导出入口。
- 不增加手动立即发送日报，不改变每日调度幂等账本、收件人解析和 18:00 默认计划。
- 不把附件二进制嵌入 XLSX，不新增跨租户汇总导出。
- 不按“管理员”名称重建通知收件授权；收件资格继续由独立 `notification:recipient:*` 原子权限决定，允许保留管理岗位并逐条撤销收件权限。

## API 与权限契约

- `GET /work-orders/export`：查询参数与 `/work-orders/search` 一致；需要至少一个当前有效的工单导出权限，后端仅导出该权限覆盖的类型、组织和资源关系。
- `GET /admin/notifications/settings/scopes`：按 `notification:config:view` 返回可配置作用域。
- `PUT /admin/notifications/settings/sender`：按 `notification:sender:update` 保存当前作用域完整 SMTP 配置。
- `DELETE /admin/notifications/settings/sender`：按 `notification:sender:update` 删除区县或市公司本地 SMTP 配置组；删除后重新解析继承来源。
- 通知中心页面允许仅持有通知权限的管理员进入；系统配置列表仍只对 `system:config:*` 权限开放。

## 发件方解析规则

1. 请求/调度位于区县作用域且该区县存在完整 SMTP 配置时，使用区县配置。
2. 区县没有任何本地 SMTP 配置时，允许继承当前租户的完整 SMTP 配置。
3. 区县只存在部分本地配置时视为配置错误，不与市公司字段混合拼接。
4. 市公司没有完整 SMTP 配置时，邮件通道明确失败并记录“发件方未配置”，不得回退到 `application.properties`、环境变量或平台 `app_config`。

## 影响文件

- Backend：`PermissionCatalog`、`WorkOrderAccessPolicy`、`WorkOrderController`、工单查询/导出服务、通知设置 DTO/Service/Controller、`ConfiguredMailSenderFactory`、`AppConfigService`。
- WEB：工单查询页、权限常量、通知中心、系统配置路由和菜单。
- Data：Liquibase `045` 迁移发件配置，`046` 补齐既有配置的显式传输标志；Backend/WEB/APP 统一版本 `2.3.3`，Android `versionCode=1003003`。

## 验收标准

- 无导出权限返回 403；只有单类或本人关系授权时，XLSX 不出现越权类型或记录。
- 导出继承搜索页的关键字、状态、类型、队列、日期等全部筛选；超 50,000 条给出可操作错误。
- XLSX 可由 Excel/Apache POI 正常打开，中文文件名、日期类型、冻结表头、自动筛选、列宽和公式型文本均正确。
- 通知查看员可进入通知中心但不能修改；渠道、计划、发件方修改按钮分别按对应权限显示。
- 区县完整覆盖、市公司继承、无默认、部分覆盖四种 SMTP 场景均有自动化测试。
- 生产提升前只读确认示例管理员甲的有效 `notification:recipient:county` 为 0；本版本迁移不得批量刷新用户岗位或收件权限。

## 测试方式

- Backend：权限目录、数据域裁剪、Controller 403、分页导出、XLSX 结构、SMTP 解析和 Liquibase 幂等测试。
- WEB：筛选参数复用、导出状态、通知权限与发件方表单单元测试；执行 lint、test、build。
- 运行态：仅部署 `e-report-test`，验证测试命名空间通知发送仍关闭，使用测试数据完成浏览器下载和工作簿打开检查；未经用户明确验收不提升生产。
