# 1.0.44 深度安全审计与加固需求

## 目标

在 1.0.43 本地候选基础上完成一次不依赖重量级安全平台的认证、客户端和软件供应链安全重构，降低撞库、凭据窃取、Token 重放、请求篡改、会话长期失控、APK 静态分析，以及上游依赖或下游制品被替换的风险。1.0.44 完成前不部署或发布 1.0.43。

## 范围

- 设备信任：Android 安装实例 UUID、Android Keystore P-256 不可导出密钥、公钥指纹；尽量完整采集厂商、品牌、型号、产品/硬件代号、CPU ABI、系统与安全补丁、屏幕和内存/存储档位、语言/时区、安装来源、应用签名，以及 root、模拟器、调试、Hook/篡改等风险信号。
- 智能挑战：低风险无感知 PoW，中风险数学验证码加 PoW，高风险冷却或拒绝；挑战必须绑定账号、网络和设备上下文且一次性消费。
- 密码治理：新密码至少 15 字符，最多 100 字符；允许粘贴和密码管理器；拒绝常见、泄露式、账号相关密码；不要求固定字符组合，不做无理由周期轮换。
- 登录防护：按账号、网络前缀和设备三维累计风险；失败后执行有上限的指数级冷却，成功后只清理账号设备维度，不清空网络攻击信号。
- API 防篡改与重放：Android 对已认证请求签署 method、规范化 URI、body digest、时间窗、nonce、session id；服务端校验设备公钥、时间窗和 Redis 一次性 nonce。
- 会话治理：WEB 使用 HttpOnly/Secure/SameSite Cookie 与 CSRF；APP 使用短期 Access Token、旋转 Refresh Token 和设备绑定；支持会话列表、单会话撤销和全部撤销；密码修改后撤销本人全部会话并要求重新登录。
- 客户端加固：Release 强制 R8/资源压缩、禁止备份和明文流量、收敛 ProGuard keep、保留签名证书校验和可回滚构建证据。
- 供应链治理：npm/Gradle 锁文件和校验元数据、官方 registry、GitHub Action commit SHA、容器 digest、工具下载 checksum、OSV/npm/Trivy/Gitleaks 扫描、CycloneDX SBOM、制品 SHA256SUMS 和受控例外到期门禁。
- 审计扩展：检查认证授权、越权、敏感数据、文件处理、CORS/CSRF、安全响应头、依赖和生产配置默认值。

## 明确非目标

- 不采集 IMEI、MAC、设备序列号、Android ID 或其他硬件唯一标识。
- 设备指纹是风险与会话绑定信号，不是独立认证因子，不替代账号密码。
- 不在客户端内置共享验签 secret；WEB 不伪造无法安全保管的长期签名密钥。
- 不引入 Prometheus、Grafana、商业 WAF 或重量级 IAM。
- 本阶段不部署生产、不登记发布中心、不上传 R2。

## 核心流程

### 登录

1. 客户端以用户名、平台、安装实例和公开设备摘要请求挑战。
2. 服务端按账号、网络、设备和近期失败计算风险，返回 `SILENT`、`INTERACTIVE` 或 `COOLDOWN`。
3. Android 同时提交 Keystore 公钥及对登录挑战的签名；WEB 依赖同源 Cookie、Origin 校验和挑战一次性消费。
4. 认证成功后创建服务端 `AuthSession`。WEB 只获得 HttpOnly 会话 Cookie；Android 获得 15 分钟 Access Token 与一次性旋转 Refresh Token。
5. 已知弱默认密码登录后只能访问本人信息、会话、改密、退出和公开升级接口，完成改密后恢复业务访问。

### Android 请求

1. 客户端计算 body SHA-256，并构造包含 method、规范化 path/query、digest、created、expires、nonce、session id 的规范串。
2. 使用 Android Keystore P-256 私钥签名，发送公钥指纹和签名头；私钥不出 Keystore。
3. 服务端先验证 Access Token 和会话状态，再验证 key id、签名、时间窗和 nonce；同一 nonce 二次使用必须拒绝。
4. Refresh Token 轮换受同一设备签名保护；发现旧 Refresh Token 重用时撤销整条会话。

### WEB 请求

1. 登录成功只设置 HttpOnly/Secure/SameSite Cookie，前端不再把 Token 写入 `localStorage`。
2. 非安全方法必须携带可读 CSRF Cookie 对应的 `X-XSRF-TOKEN`，并通过 Origin/Referer 校验。
3. XSS 防护依赖 CSP、安全响应头、React 默认转义和不持有长期凭据；WEB 不采用可被脚本窃取的伪签名 secret。

## 密码与迁移规则

- 新增、重置、导入和本人修改密码统一走 `PasswordPolicy`。
- 新哈希采用带算法标识的 Argon2id；既有无前缀 BCrypt 在成功认证时原位升级，不保留两套业务认证流程。
- 既有未知明文密码不批量判弱；已知区县默认密码通过 Liquibase 标记 `password_change_required=true`，首次登录强制修改，不在迁移中再次写入明文或新默认密码。
- 空数据库首次创建默认管理员时必须显式提供 `DEFAULT_ADMIN_PHONE`；既有库不补写、不覆盖历史管理员资料。
- 改密增加 `authorization_version`，撤销本人全部会话，WEB/APP 清理本地凭据并返回登录页。

## 会话状态与时限

- 状态：`ACTIVE`、`REVOKED`、`EXPIRED`、`COMPROMISED`。
- APP Access Token：15 分钟；Refresh/绝对有效期：30 天；空闲有效期：7 天。
- Refresh Token 每次成功使用后轮换；并发网络重试可在 30 秒恢复窗口内使用上一枚 Token，超过窗口再次使用则将会话标记为 `COMPROMISED`。
- WEB 绝对有效期：7 天；空闲有效期：12 小时；Cookie 每次登录轮换。
- 权限或角色变化继续通过 `authorization_version` 即时使旧 Access Token 与会话失效。
- 会话只保存 Token/Secret 的 SHA-256 摘要，不保存可直接使用的原始凭据。

## 数据与隐私

- `trusted_devices` 保存公钥、key id、安装实例加盐摘要、经白名单和限长处理的完整环境/硬件能力信息、风险信号、信任和最后使用时间。
- `auth_sessions` 保存会话状态、客户端类型、Token 摘要、设备引用、生命周期和脱敏网络/UA 摘要。
- Redis 仅保存短期挑战、风险计数、冷却截止时间和 nonce；Key 中不出现用户名、手机号、邮箱、Token 或设备原值。
- 观测日志不得记录密码、验证码答案、Refresh Token、Cookie、签名正文或完整公钥。

## 验收标准

- 低风险登录不展示验证码；连续失败升级为可见挑战并产生指数冷却，返回明确 `retryAfterSeconds`。
- WEB 存储中不存在认证 Token；跨站非安全请求因 CSRF/Origin 校验失败。
- Android 请求被改 body、改 path、超时或复用 nonce 时均被拒绝；合法签名可通过。
- Access Token 过期可通过一次性 Refresh Token 刷新；重用旧 Refresh Token 后会话转为 `COMPROMISED`。
- 用户可查看设备、最近活动和会话，并撤销指定会话或其他全部会话。
- 弱默认管理员完成强制改密前不能访问工单或管理接口。
- Release APK 确认 `minifyEnabled=true`、`shrinkResources=true`、`allowBackup=false`、`usesCleartextTraffic=false`，并能在模拟器覆盖安装和完成全链路登录。
- release 依赖图不存在未审查漏洞；构建工具链、npm 和容器例外必须精确匹配且未过期，任何依赖来源、版本、父级、CVE 或补偿控制漂移都使门禁失败。
- Git 历史和工作树密钥扫描为零；生成 CycloneDX SBOM，release OCI/APK 具备可复核 SHA-256。
- Liquibase 在 MySQL 与 H2 均可前向迁移；回滚方案不删除既有用户和工单数据。

## 测试方式

- 后端：密码策略、哈希升级、风险阶梯、挑战绑定、Token 轮换/reuse、签名规范向量、nonce 重放、CSRF、会话撤销和权限变化集成测试。
- WEB：认证存储、CSRF、无感挑战、强制改密、会话列表单元测试；lint/build 和浏览器跨域 smoke。
- APP：Keystore 模块单测/仪器验证、签名请求、Refresh 并发互斥、强制改密和会话管理测试；typecheck、Doctor、R8 Release 构建、APK 静态检查与 Android 模拟器全链路。
- 依赖与配置：`npm audit`、OSV-Scanner、Trivy、Gitleaks、Gradle dependency verification、来源/锁定契约校验、CycloneDX SBOM、生产 manifest 静态审查；构建工具链残余采用带到期日的精确指纹基线，不能宽泛忽略。

## 发布门禁与回滚

- 1.0.44 未完成全部自动化和模拟器验收前不部署；1.0.43 APK 不发布。
- 正式部署采用数据库备份、Liquibase 前向迁移、后端/WEB 同批切换、Android 1.0.44 强制升级的单窗口方案。
- 回滚优先回退应用镜像并保留新增安全表；不得通过恢复旧长期 Token 或重新启用弱默认密码完成回滚。
