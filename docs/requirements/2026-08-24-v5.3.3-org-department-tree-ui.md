# 5.3.4 组织与部门树形工作台

最初占用 5.3.3；归档复核发现 WEB `dist` 未包含最后一次只读权限态修正，5.3.3 候选拒绝提升且不得覆盖，最终实现版本升级为 5.3.4。

## 目标

将组织和部门从彼此割裂的平铺列表重构为统一层级工作台，使用户能够先在组织树定位数据边界，再在同一上下文查看和维护该组织内部的部门树。

## 范围

- 左侧组织树按 `parentId` 展示真实父子关系，支持展开、收起、名称/编码搜索和当前节点选中态。
- 组织节点显示类型、启停状态、下级数量和直属部门数量。
- 右侧显示当前组织详情、组织级操作和该组织的部门层级。
- 部门树按 `parentId` 展示直属部门和下级班组，支持展开、收起、搜索、状态识别和当前节点详情。
- 保留组织新增、编辑、移动、启停，以及部门新增、改名、移动、启停、合并、删除和破坏性操作预览。
- 桌面端采用左右工作台，窄屏按组织树、组织详情、部门树的业务顺序纵向排列。
- 只有 `department:view` 的账号从已授权部门结果构造只读组织入口；不得额外请求组织目录或显示无权操作入口。

## 非目标

- 不改变组织、部门、用户或工单的数据模型。
- 不新增、合并或重命名原子权限。
- 不改变组织/部门接口、生命周期规则和数据域判定。
- 不修改 APP 的组织与部门管理界面。
- 不切换生产环境。

## 验收标准

1. 组织与部门均按真实父子关系显示连接线、缩进和展开状态，不再以平铺表格表达层级。
2. 搜索子节点时保留完整祖先路径；孤立脏数据不会导致整个树无法显示。
3. 当前组织和当前部门具有明确但不过度的选中态；启用、停用和已合并状态可区分。
4. 组织操作只作用于当前选中组织，部门操作只作用于当前选中部门；原有权限和服务端校验保持不变。
5. 只有部门查看权限时页面仍可用，且不出现组织管理或部门变更按钮。
6. 390px 视口无横向溢出；桌面端主要信息无需跨页或切换 Tab。
7. WEB 单元测试、lint、build、浏览器 console、测试环境 API 和运行日志全部通过。

## 测试方式

- `npm test`
- `npm run lint`
- `npm run build`
- 本地 Mock API 覆盖全权限和仅部门查看两种身份。
- 测试命名空间真实管理员登录，验证市公司/区县切换、南靖县三个部门、搜索、展开收起和权限隐藏。
- 部署前后核对工单、通知 Outbox 和部门人数不发生非预期变化，生产镜像保持不变。
