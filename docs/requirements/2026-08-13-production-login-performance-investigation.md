# 1.0.47 集中更新登录性能调查与生产只读压测

## 目标

- 还原集中下载新版本并登录时，用户等待至少 5 秒的真实耗时分布和根因。
- 分离客户端环境采集、PoW、Keystore、网络、后端认证、Redis、MySQL、会话写入和授权加载的成本。
- 在不产生工单、附件、通知、Outbox 或日报数据的前提下，验证生产公开接口、登录链路和已授权只读接口的容量。

## 范围

- 生产运行态、日志、认证会话、诊断事件、Redis、MySQL、K8S 与主机资源只读取证。
- Android 模拟器执行聚焦登录性能采样；没有可用模拟器时，明确记录未验证范围。
- 生产公开接口和只读 GET 接口按阶梯并发压测。
- 完整认证链路优先在 `e-report-test` 隔离环境压测；生产只使用专用测试身份或可精确识别的测试会话，并在结束后清理认证副作用。

## 非目标

- 不创建、修改或删除生产工单、附件、用户资料、角色、配置和发布记录。
- 不调用通知、日报、邮件、钉钉、企业微信或 Outbox 写入链路。
- 不通过错误密码制造登录风险计数，不绕过验证码、PoW、设备证明、限流或会话安全规则。
- 调查阶段不直接修改生产代码、资源配额、数据库参数或安全策略。

## 停止条件

- 任一生产接口出现持续 5xx、Backend/Frontend Pod 非 Ready、Pod 重启或节点负载异常。
- 只读接口 P95 连续两个阶段超过 2 秒，或登录 P95 超过 5 秒。
- 工单、附件、Outbox、通知/日报数据计数发生非业务可解释变化。

## 验收标准

- 给出用户感知登录各阶段耗时、服务端耗时和集中并发下的 P50/P95/P99。
- 给出公开接口、只读业务接口和登录链路的安全容量区间及首个退化点。
- 压测前后工单、附件、Outbox、日报和通知相关计数保持一致；测试认证副作用清理完成。
- 明确根因、次要风险、修复优先级、建议配置和回归测试方案。
