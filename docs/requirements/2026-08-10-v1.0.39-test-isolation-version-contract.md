# 1.0.39 测试隔离与版本契约

> 生产硬约束：官方生产域名只允许执行只读 smoke。任何创建账号、上传附件或改变工单状态的 E2E 必须在声明为隔离环境的生产克隆库执行，且真实通知和 Outbox 入队均关闭。

## 目标

- 阻止写入型 E2E 误连生产环境，避免测试账号、工单、附件和通知事件再次进入生产数据。
- 清理已确认的历史测试数据及其上传文件，同时保留完整备份和可复验清单。
- 从 1.0.39 起统一 Android `versionName` 末段、`versionCode` 和 `runtimeVersion` 原生版本号，并在构建、发布两处强制校验。

## 范围

- 后端隔离环境能力声明、通知抑制和 Outbox 入队开关。
- 写入型工单生命周期 E2E 的目标环境防护，以及生产只读 smoke。
- Liquibase 019 历史测试数据清理、生产备份和上传文件回收工具。
- Android 1.0.39/code39/native39 版本配置、源码契约、APK manifest 和发布参数校验。
- 用户资料、账号状态和角色数据范围在独立用户详情页通过单一事务保存，列表仅承担查询、新建、删除和恢复。
- 用户详情展示提单、在办、回单、验收和平均处理历时；Web 与 Android 均支持按名称、编码和职责搜索角色。
- Liquibase 020 将历史同用户同角色的多条 Grant 收敛为单条最宽有效范围，并用数据库唯一约束阻止再次产生重复。
- MySQL 克隆演练、自动测试、Android 模拟器升级、生产部署与 R2 发布。

## 非目标

- 不通过客户端请求头、用户名参数或普通业务字段临时跳过生产通知。
- 不在生产租户内新增“测试组织”或“测试数据标记”继续执行写入型 E2E。
- 不删除仅凭单一模糊文案疑似测试的数据；只处理保留前缀和关系链均可证明的测试数据。
- 不修改工单状态机、角色权限内容、SLA 和通知收件人规则。

## 环境契约

写入型 E2E 必须同时满足以下条件，否则在第一次业务写入前终止：

1. `E_REPORT_E2E_BASE_URL` 显式提供，且主机不是官方生产主域、relay 或生产 IP。
2. 管理员登录后，`GET /admin/e2e-isolation` 返回 `ready=true`。
3. 服务端确认通知中心、邮件、企业微信、钉钉、日报和 Outbox 入队均已关闭。

生产 smoke 只允许登录以及 `GET`/`HEAD` 查询，覆盖组织、角色、岗位模板、工单列表/详情、更新检查和统一 APK 下载入口，不创建任何业务记录。

## 测试数据清理契约

测试账号仅按保留用户名空间识别：`e2e-*`、`appqa-*`、`video-smoke-*`。删除前必须满足：

- 账号全部为 `DELETED`。
- 由这些账号提交的工单全部为 `CLOSED` 或 `CANCELLED`。
- 测试账号没有参与任何非测试提单人的业务工单。
- 数据库完整备份、上传目录归档和待删除文件清单均已生成并校验 SHA-256。

2026-08-10 已确认的保留测试集合为：70 个测试账号、52 张测试工单、84 个附件、88 个上传会话。发布前只锁定这组待清理集合及安全关系；用户、工单、附件和上传会话总量必须在备份时实时快照，允许正常业务增长，迁移后按“实时总量减去测试集合”复核。

数据库删除由 Liquibase 019 完成；运维工具仅负责备份、生成受限文件清单、迁移后删除 `/data/e-report/uploads` 内对应文件、清理 Redis 和复核计数。

## Android 版本契约

1.0.39 的唯一合法组合为：

| 字段 | 值 |
| --- | --- |
| `package.json` / lockfile / Expo `version` | `1.0.39` |
| Gradle / Expo `versionCode` | `39` |
| Gradle `versionName` | `1.0.39` |
| Expo `runtimeVersion` | `android-1.0.39-native39` |

校验器必须验证源码配置；release 构建后还要验证 APK manifest 和签名；发布脚本必须验证命令参数与源码/APK 完全一致，任一不匹配即在上传 R2 前失败。

## 影响文件

- `application.properties`、隔离环境配置、`OutboxService`、隔离状态 Controller。
- `scripts/isolated-work-order-lifecycle-e2e.mjs`、`scripts/production-read-only-smoke.mjs` 及其测试。
- Liquibase 019/020、`deploy/dedicated-cloud/manage-e2e-test-data.py`。
- `AdminUserController`、`UserService`、用户绩效只读投影，以及 Web/Android 用户详情和角色编辑组件。
- App 版本配置、版本校验器、Android 构建和发布脚本。

## 验收标准

- 写入型 E2E 对生产主域、relay、生产 IP和未声明隔离能力的服务均拒绝运行。
- 隔离环境运行全生命周期 E2E 时不产生 Outbox，也不调用真实通知渠道。
- 生产只读 smoke 执行前后用户、工单、附件和 Outbox 计数不变。
- Liquibase 清理在生产克隆库首跑成功、二次执行为 0 个新变更集；业务数据计数和文件不受影响。
- 生产清理后保留数必须等于备份 manifest 中的实时总量减去测试集合；测试账号、测试工单、关联行与对应上传文件均为 0。
- App 自动测试、typecheck、Expo Doctor、release 构建、签名、模拟器升级及 R2 Range/SHA 校验全部通过。
- 用户详情一次保存成功后，服务端回传的角色与范围必须和提交值一致；任一字段失败时资料、状态和 Grant 全部回滚。
- 用户列表点击“查看详情”统一进入详情页；角色搜索不再一次平铺全部角色；无对应写权限时字段只读或不展示操作。

## 回滚

- 数据清理回滚必须同时恢复清理前 MySQL 备份和上传目录归档，再清空 Redis。
- 应用回滚使用上一版 backend 镜像；Android code39 已发布后不降 `versionCode`，修复版本必须使用更高且继续对齐的版本号。
