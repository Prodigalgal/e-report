# 邮件发件池的后台管理与组织策略

## 目标与范围

- WEB 后台通知中心支持录入、编辑、移除、保存和测试本级发件账号；部署 Secret 提供默认池，不再锁定后台写入。
- 每级组织可选择 `INHERIT`（仅继承）、`REPLACE`（仅本级）、`MERGE`（本级与上级共同使用）。沿同租户组织树逐级计算，上级有效池包含其已选择的继承策略；根组织继承市公司默认，市公司默认再继承部署默认。
- 没有本级配置时默认继承；未启用部署默认的现有本级池继续独立使用。部署默认当前覆盖的数据库配置在升级后仍保持继承，避免无声切换正在使用的账号；管理员保存策略后以显式选择为准。保存后重新读取配置即可生效，无须重新部署。
- 共同使用时按发件账号合并并轮询；相同 ID 或相同 SMTP 登录账号由本级覆盖，避免重复计权。上级无可用池时，本级有效账号继续工作，后台展示上级配置问题。
- 本级账号与继承账号分开展示，继承账号只读；修改只落本级，撤销本级覆盖恢复继承。切换为继承可保留已保存的本级账号。

## 契约与权限

- 沿用 `GET /admin/notifications/settings`、`PUT/DELETE /admin/notifications/settings/sender` 和测试邮件端点；更新请求增加可选 `strategy`，省略时按独立池处理。
- 返回有效池、策略、本级池和继承池及账号来源；密码、OAuth Client Secret 与 Refresh Token 均不回显。留空仅保留本级既有凭据，不从上级复制凭据到本级。
- 本级/合并模式至少需要一个完整本级账号；继承模式允许空本级池。保留原 SMTP/OAuth2、高级连接项、组织权限、测试收件白名单和不限 10 个账号的规则。
- OAuth 刷新凭据按每个账号的实际来源回写，不能写入当前使用方的组织。
- 非目标：新增邮件渠道、变更收件权限、自动探测 SMTP 或在浏览器回显凭据。

## 影响与验收

- 影响发件配置解析/持久化、组织层级读取、发件工厂、DTO、WEB 表单及相关测试；策略使用现有作用域配置表，无新增数据库结构。
- 验证三种策略、多级继承、账号去重、本级凭据保留、继承凭据隔离、撤销回退、Secret 可用/不可用、权限拒绝和 OAuth 来源回写。
- 本次与 C 版 LOGO 合并为 `6.5.0` 测试候选；GitHub Actions 后台执行，生产升级等待测试验收。回滚应用前需将新增策略恢复为原有独立/继承模式，防止旧版本忽略合并策略。
- 继承池的测试请求使用 `inheritedSenderId`，由服务端选择既有配置；本级草稿测试仍使用 `sender`，两者必须二选一，避免客户端改写继承账号的 SMTP 目标。

## 本地验证与发布边界

- Backend：`test bootJar` 通过，474 项测试零失败、零跳过，包含三种策略、多级继承、去重、来源回写、凭据隔离与部署默认不可用场景。
- WEB：74 项测试、lint、生产构建通过。APP：69 项测试、TypeScript、资源安全检查、原生依赖锁、版本契约与 Android JS bundle 导出通过。
- C 版矢量源同步生成 SVG/PNG/WebP；PWA 入口、图标及离线缓存使用同一资源摘要，Windows/Linux 换行差异不改变摘要。Android/PWA 前景轮廓位于圆形安全区内。
- 本次未改生产配置，未执行真实 SMTP 投递或定时触发验收；浏览器逐页检查与 Android 真机验证尚未完成。按用户要求，推送后由 GitHub 后台构建，构建结果和部署运行态另行验收。
- 回滚到不支持组织策略的版本前，先确认各组织退回部署默认；保留数据库中的账号与策略。Android 发布后使用更高版本修复。
