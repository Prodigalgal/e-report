# 可配置密码长度与复杂度策略（5.6.5）

## 目标

密码校验不再把复杂度规则写死在客户端或服务类中。平台默认密码最小长度为 8 位，并要求包含大写字母、小写字母、数字和特殊字符；管理员可以在已有配置作用域内调整最小长度及四项组成要求。

## 范围

- 后端 `PasswordPolicy` 从 `AppConfigService` 读取平台、租户和组织级有效配置。
- 新增 `/auth/password-policy`，登录后返回当前用户所属组织解析出的有效策略；密码变更页使用该策略即时提示。
- 新增 `/admin/password-policy` 读、写、删除组织覆盖接口，沿用 `system:config:view/update/delete` 和现有组织范围校验。
- WEB 与 APP 的密码提示、创建用户、重置密码和修改密码校验使用同一策略模型。
- 删除组织覆盖后恢复上级或平台默认；不改变已有密码，策略只约束新建、重置和变更密码。

## 非目标

- 不降低既有 Argon2id/BCrypt 密码存储强度。
- 不强制批量重置历史用户密码。
- 不新增角色或新的权限类型；密码策略管理属于系统配置权限。

## 验收标准

1. 默认策略为 8 位且四项组成均开启。
2. 管理员在系统配置页面可选择作用域、编辑最小长度和四个开关，保存后立即影响该作用域的新密码校验。
3. 删除组织覆盖后显示继承来源，子组织按既有层级规则继续解析。
4. WEB、APP 和后端对相同密码给出一致的长度及组成要求；后端始终是最终校验方。
5. 未认证用户不能读取策略；处于首次改密状态的用户可读取策略并完成改密。
