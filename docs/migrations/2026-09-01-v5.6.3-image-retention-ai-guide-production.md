## 变更

### 图片脱敏

- Worker 不再删除 `_quarantine` 原始上传文件；无论成功或终态失败，原图均保留用于审计和人工取证。
- `_sanitized/{jobId}.jpg` 是唯一对前端展示/下载的派生文件，原图不回退到客户端。
- `ImageRedactionProcessor` 继续使用安全相对路径校验和原子写入；数据库任务记录同时保存原始路径与派生路径，运维可在 VPS 上传根目录按任务追溯。

### AI Guide

- `GET /api/ai/guide` schema 升级为 `2`，补充服务版本、必需/禁止认证位置、权限 `validUntil`、能力的请求字段/响应提示/错误状态和幂等要求。
- 权限只从当前有效 Grant 与固定 `PermissionCatalog` 交集生成；退役权限行被忽略，不再阻断整份 Guide。
- 工单查询、详情、历史、附件、派单/调单/接单/回单/验收、仪表盘、用户/组织/配置/通知/SLA/观测等能力均按 Token 实际权限裁剪。

### 观测链路

- 修复 W3C trace ID 中包含手机号样式数字串时被错误脱敏、触发数据库约束失败的问题；保留合法 32 位 trace ID。

## 遗留风险

- Worker 吞吐为单 Pod、单并发、处理器级基准，不等同于包含 PostgreSQL 领取/回写的端到端队列吞吐；扩容前需重新评估 CPU、内存和宿主机磁盘 I/O。
- 旧生产环境仍保留历史 MySQL 资源对象但业务已使用 PostgreSQL；清理旧资源需另行执行并保留独立回滚窗口。
