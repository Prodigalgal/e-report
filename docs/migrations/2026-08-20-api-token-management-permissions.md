# API Token 管理权限迁移

候选版本：`2.5.4`  
Liquibase：`2026-08-20-051-api-token-management-permissions.sql`  
状态：代码与迁移已完成，未部署测试或生产环境。

## 变更

- 新增 `api-token:view`、`api-token:create`、`api-token:revoke` 三个原子权限。
- 新增内置岗位 `PROFILE_API_TOKEN_MANAGER`，仅组合上述三项权限，不额外授予管理工作台访问权限或业务 API 权限。
- 区县管理员和市公司管理员标准岗位包含该岗位片段；系统启动时由现有内置岗位同步与默认管理员校准机制升级到当前发布版本。
- `/api-tokens` 的查询、创建、权限选项和撤销接口分别按原子权限校验。没有权限时返回 `403`。
- API Token 可选权限目录显式排除上述三项管理权限，Token 仍不能访问 `/api-tokens/**`，不能形成 Token 管理链。

## 数据兼容性

- 迁移只幂等补齐权限目录，不修改、撤销或删除历史 API Token。
- 历史普通用户在升级后若没有 API Token 管理权限，将不能查看、创建或撤销 Token；既有 Token 的运行权限仍与账号当前有效权限动态求交。
- 代码回滚时保留三条权限目录数据。旧代码的固定目录查询不会展示这些数据库附加行，避免因回滚删除已被岗位或授权引用的权限造成数据损坏。

## 上线前检查

1. 备份 `permissions`、`authorization_profiles`、岗位版本/规则、授权事实与 `api_tokens`、`api_token_permissions`。
2. 在隔离环境执行完整 Liquibase，并确认三条权限均存在、权限目录漂移计数为零。
3. 使用普通用户验证四个 Token 管理接口均返回 `403`。
4. 使用“API Token 管理员”验证查看、创建和撤销成功，并验证创建选项不包含 `api-token:*` 和 `app-update:*`。
5. 验证区县管理员、市公司管理员及 superAdmin 的标准岗位升级，确认原组织范围、自定义授权和授权有效期未被覆盖。

## 回滚

- 应用层回滚到上一不可变制品；数据库保留新增权限目录行。
- 不自动删除已产生引用的权限、岗位版本、授权事实或 Token。
- 若迁移本身在应用启动前失败，Liquibase 事务回滚；依据迁移前备份核对权限目录，不执行宽泛清理。
