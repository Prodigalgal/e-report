# 5.6.4 脱敏附件下载修复生产发布记录

## 变更范围

- 修复脱敏结果存储键包含 `_sanitized/` 目录时，WEB/APP 将内部存储键拼入 URL 的问题。
- 新增按 `workOrderId + attachmentId` 定位附件的下载入口：
  `/api/work-orders/attachments/{workOrderId}/file/{attachmentId}`。
- 保留单段存储键的历史入口；旧入口不再允许跨越 `/`，避免与 UUID 入口竞争。
- WEB、APP、AI Guide、压测脚本和生命周期脚本统一使用附件 UUID，不再把存储目录暴露为 URL 标识。
- 本版本无数据库结构或 Liquibase 变更；原图和脱敏结果文件均保留在原有共享存储中。

## 根因

脱敏文件的数据库存储键形如 `_sanitized/{jobId}.jpg`。旧客户端将该键编码后放入路径，Envoy 对 escaped slash 执行规范化重定向，后端最终收到的路径与原路由不一致，导致 `404`。旧 Spring 路由的 `{storedFileName:.+}` 还会吞掉多段路径，与新增路由形成匹配竞争。
