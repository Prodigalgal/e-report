## 高德 Web 端凭据配置

地图渲染需要**另一对**凭据，与后端已有的 `AMAP_API_KEY`（服务端 Web 服务接口）不可混用。

在测试环境系统配置中设置：

| 配置项 | 值 |
| --- | --- |
| `map.amap.web.js-api-key` | 用户提供的 JS API key |
| `map.amap.web.js-security-code` | 用户提供的安全密钥 |

对应环境变量：`MAP_AMAP_WEB_JS_API_KEY`、`MAP_AMAP_WEB_JS_SECURITY_CODE`（部署清单需新增这两个 env，当前清单未包含）。

**另需在[高德控制台]确认域名白名单已包含测试域名**，否则浏览器请求会被拒绝并提示地图加载失败。此项为外部控制台操作，代码层无法验证。

## 已知限制与风险

- **地图无坐标时不做兜底**：后端对非法坐标、工单缺少坐标均返回 `null` 而非推算值，前端标注为"缺少坐标"。这是有意设计——地图上的假点位比缺失点位更有害。
- **WEB 地图配置随接口下发**：JS key 会出现在浏览器中，本质无法保密，真正的访问控制是高德控制台域名白名单；该配置只对持有地点查看权限的账号下发。
- **地址搜索为全国范围**：搜索不限定城市，避免其他地市用户搜不到结果且界面无法解释；已在地图取点时优先返回 50 公里内的结果，无结果再退回全国。
- **浏览器定位可能返回粗糙结果**：WEB 端已显式关闭高德 IP 定位兜底（`noIpLocate`），但 `navigator.geolocation` 在无 GPS 的桌面环境仍可能精度较差，界面上会显示精度值供判断。
- **APP 前台服务在部分定制系统上可能被限制**：厂商省电策略可能限制后台定位，需在目标机型上实测；若被限制，位置更新会停滞在最后一次成功采集。
