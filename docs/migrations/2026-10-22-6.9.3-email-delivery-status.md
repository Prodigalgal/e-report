# 6.9.3 邮件发送状态修正

## 行为与契约

- 用户可见状态只有发送中、已发送、发送失败。`SMTP_ACCEPTED` 保持原接口值，中文改为“已发送”，仅表示发件服务器已接受邮件，不代表收件箱送达或已读。
- SMTP 超时记录为 `FAILED / TIMEOUT`，保留原异常对发送流程的影响，不增加重发。详情提示本次发送未正常完成，收件人仍可能收到邮件。
- 超过 15 分钟未收尾的 `SENDING` 在列表、详情和失败筛选中统一为 `FAILED / INCOMPLETE`；查询不改写发送记录，稍后真实收尾仍可写入成功或失败结果。没有已记录的结束时间就显示“未记录”。
- 删除 `UNKNOWN` 状态及筛选选项；接口只接受三个状态。打开的旧页面应刷新，原生 APP 通过签名 OTA 取得新页面，无需更换原生基础包。
- 独立权限、组织隔离、订阅、发件池轮询和重试机制保持原行为。SMTP 成功后的台账收尾故障仍不得导致重复发信。

## 数据迁移与滚动发布

- Liquibase 078 在 H2 和 PostgreSQL 两份 master 中注册，业务 tag 为 `e-report-6.9.3`；不改动已执行的 077。
- `UNKNOWN` 修复为 `FAILED`，保留已有失败分类、地址、主题、时间和耗时；缺失分类时补 `INCOMPLETE`，不伪造 SMTP 接受或收件结果。
- 增加 `chk_email_delivery_status` 约束，滚动发布期间也禁止写回被移除的值，避免新进程读取枚举失败。尚未更新的进程若收尾写入被拒绝，沿用现有异常日志与不重发规则，其未收尾记录超期后按失败展示。
- 使用现有 GitHub Actions → 私有配置仓库 → Argo 自动迁移与部署测试；本次不提升生产。

## 验证

- Backend 全量 537 项通过，无跳过或失败；bootJar 成功。真实本地 SMTP 接受、拒收、等待响应超时均覆盖，未向外部邮箱重复发信。
- 迁移在 H2 的 MySQL / PostgreSQL 兼容模式验证历史修复、重复执行、状态约束和约束回滚；这不代替真实 PostgreSQL 部署验证。
- 查询验证租户/组织/独立权限隔离、失败筛选与详情一致、UTC+8 日期边界、延迟真实收尾，以及组织缓存预热后分页仅列表和计数两条 SQL。
- WEB 95、APP 79、发布工具 28 项通过；WEB lint/build、APP typecheck/Android 导出、资产/原生模块/版本/供应链契约及两种原生指纹通过。Gitleaks 工作区扫描无发现。
- 本地正式 WEB 构建连接现有测试 API，真实管理员登录、三状态菜单和列表展示通过。截图保存在本地 `output/ui-email-status-6.9.3/status-options.png`，不提交验收截图或凭据。
- 新候选的测试集群迁移、三端线上复验和实际 SMTP 网络恢复尚未确认；已有 Gmail 超时不因本次状态修正而视为发送成功。

## 回滚点

- Backend/WEB 使用前一不可变 `6.9.2` 制品，APP 使用已验证的兼容签名 OTA；保留台账数据。
- 若恢复允许写入 `UNKNOWN` 的发送器，须先通过受控迁移删除 `chk_email_delivery_status`；078 自带对应约束 rollback。已归为 `FAILED` 的历史记录仍可被前版读取，不反向猜测并重分类。
- 原生与 Lite 基础包分别继续引用 `6.8.2 / 5008002` 和 `6.8.1 / 5008001`，禁止覆盖 APK 或复用不同原生内容的身份。
