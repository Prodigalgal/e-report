# 1.0.45 授权范围与组织根迁移手册

## 发布范围

- Backend/Frontend 镜像：`localhost/e-report-*:20260812-v1.0.45-auth-scope-6`。
- Android：`1.0.45` / code45 / `android-1.0.45-native45`。
- Liquibase：执行 024、025、026、027、028；027 修改组织根契约并规整历史授权，028 将默认租户和默认管理员身份固化到数据库并一次性修复管理员授权。

## 迁移前门禁

1. 保存生产 Deployment、Secret 名称、Pod、镜像和 `DATABASECHANGELOG` 快照。
2. 使用 `mysqldump --single-transaction --routines --triggers --hex-blob` 备份完整数据库并记录 SHA-256。
3. 确认每个租户恰有一个 `parent_id IS NULL` 的历史根候选；该查询只用于 027 一次性回填，不进入运行时代码。
4. 记录全部 `TENANT_ALL` Grant 及用户所属组织，核对默认租户非根异常账号清单。
5. 在生产数据库克隆上执行全套 Liquibase 两次：首轮迁移成功，第二轮 `Run=0`。

## 027 数据行为

- 新增 `tenants.root_org_unit_id`，以同租户复合外键绑定根组织。
- 默认租户根组织保持原 UUID、路径、父子关系和历史业务引用，仅把编码改为 `3506`。
- `authorization_scope_repair_20260812` 保存每条被修复 Grant 的原范围和目标范围。
- 默认租户中所属组织不是根组织的历史 `TENANT_ALL` 改为该用户所属组织的 `ORG_TREE`，并递增 `authorization_version` 使旧授权缓存和会话失效。
- 028 一次性将默认管理员修复为 38 个细职责角色：`ROLE_USER` 为根组织 `ORG`，其余角色为 `TENANT_ALL`。应用启动后不再覆盖数据库中的密码、资料、角色或数据范围；ENV 仅用于首次创建缺失的系统身份。

## 迁移后断言

- 所有租户的 `root_org_unit_id` 非空且指向本租户组织；默认租户根编码为 `3506`。
- 默认租户非根组织用户不存在迁移遗留的 `TENANT_ALL`。
- 默认管理员全部非基础管理角色为 `TENANT_ALL`，用户详情不再返回隐藏授权。
- 区县管理员只能读取本组织树用户、工单、配置和诊断；不能查看或提交市公司级角色。
- Backend/Frontend/Redis/MySQL Ready，Liquibase 无 checksum/lock 异常。

## 回滚

- 优先应用回滚，不回退 APK 构建号；修复版必须使用更高 code。
- 需要恢复 Grant 时，从 `authorization_scope_repair_20260812` 按 `grant_id` 恢复 `previous_data_scope/previous_scope_org_id`，递增受影响用户 `authorization_version` 并清理 Redis 授权缓存。
- 需要恢复数据库结构时，先停止 Backend，再从本次发布前完整备份恢复；不要在运行中的新版本上直接删除 `root_org_unit_id`。
- 027 的 SQL rollback 仅用于克隆库演练；生产优先整库恢复，避免 024-026 安全会话结构与应用版本错配。
